## 2. 原生界面

把 harness 自带的交互式 CLI 交给用户直接操作，用于原生安装引导、原生设置、填写模型凭据等。

- **入口**：安装流程中"用原生方式继续"；实例页"原生界面"（高级）。具体命令来自 profile 的 `native_cli`（PROFILES.md 第 2 节），例如 `[openclaw, onboard]`；也可以打开一个普通的登录 shell。
- **连接**：需要管理登录（已解锁的管理钥匙，或用服务器密码临时登录）；每次新开一条 SSH 连接 `ssh -tt -o ControlPath=none -o IdentitiesOnly=yes …`，绝不复用日常通道或已有连接（ARCHITECTURE.md 第 2.1 节）。
- **TUI**：暂停界面，把本机终端直接交给 `ssh` 子进程（标准输入输出继承），Valise 进程不经手任何字节；退出后恢复界面并重新检测实例状态。
- **GUI（M7b）**：需要内嵌终端，字节经 Valise 中转。要求：不解析、不保存、不写入日志、诊断材料或崩溃报告；不做终端录制；关闭窗口即结束连接。具体的 PTY、断线处理与回显策略在 M7b 设计并测试。
- **凭据边界**：用户在原生界面中输入的 API Key 等，Valise 不读取也不提供输入框；文案不得声称"凭据完全不经过 Valise"，只说"Valise 不读取、不保存、不记录"。
- **结束后**：按实际结果（实例是否被发现、服务是否健康、管理页是否可达）判断，不以命令退出码代替。
- **断线后残留的程序**（2026-11-03，检测报告 F05）：porter 不再用自己替换成那个程序，而是把它作为子进程运行并记录（`~/.local/state/valise/sessions/<pid>.json`，含内核记下的启动时间），程序退出时删除记录；连接断开时 porter 留下等它退出。下次打开原生界面或安装时，若还有 Valise 启动、仍在运行的程序，先列出（命令、开始时间、当时的连接是否已断开），让用户选择结束它们（开发者模式，`terminal_session_end`）、不管它们继续、或取消。porter 只结束自己有记录且 pid 与启动时间都对得上的进程，不碰其他进程。
- **原生引导提示**（2026-11-01，M11）：profile 可以用 `native_hints` 写几句提示，在打开原生界面之前原样显示，例如"引导最后会等待控制台登录：另开终端运行 valise open <服务器> <实例>，浏览器会带着一次性令牌自动登录"。只是文字，不执行任何东西。
- **结束方式**（2026-11-01 用户反馈）：原生界面和 harness 终端里程序自己的退出码（包括用 Ctrl+C 结束、引导停在等待界面时的常见做法）属于用户的操作，不是 Valise 的失败：只说明"已离开原生界面"或"已结束（退出码 N）"，不显示"未预期的错误"。只有连接断开（ssh 退出码 255）才报错。
- **harness 终端**（2026-11-01 用户决定，M11）：`valise shell <服务器> --profile <id>` 新开一条管理连接，打开用户自己的交互 shell，并把该 harness 的 `detect.bin_dirs` 放进 PATH（经 `valise-porter exec --shell`，环境取自登录环境；不改服务器上的任何配置文件），这样 harness 自己的命令（如取令牌、诊断）在这个终端里直接可用。用于原生引导中途需要另开终端的场合。TUI 提供"打开这台服务器的终端"（暂停界面或在新的系统终端窗口中打开）；GUI 用内嵌终端（第 2 节 GUI 条目）。

## 3. 官方方案

官方方案写在签名资料包的 profile 中（`install` 段，PROFILES.md 第 2 节），只覆盖已核实的版本与安装方式。

- **步骤种类**（第一版）：
  - `npm_global`：`{package, version, integrity}`，以用户级前缀安装精确版本，安装后核对 integrity。
  - `script`：`{url, sha256, interpreter: [bash], args: [...], runtime_downloads: "…"}`。客户端下载脚本（不经服务器），核对 SHA-256，**把脚本全文展示给用户**（可滚动、可另存），确认后经管理钥匙上传到服务器的 `~/.local/state/valise/install/<op>/`，再以 `interpreter + 文件路径 + args` 执行。哈希不符时停止，说明"官方脚本已变化，此版本方案不再适用"，提供原生方式。
  - `argv`：harness 安装后执行的固定命令（例如初始化），逐字展示。
  - `path_add`：`{dir}`，把 harness 的命令目录加入用户登录 shell 的 PATH（2026-11-01 用户决定，M11）。由 porter 的 `path-add` 执行，不经过 shell：只接受 `${HOME}` 下的目录；按服务器上的登录 shell 选择文件（bash：有 `~/.bash_profile` 时用它，否则 `~/.profile`；zsh：`~/.zprofile`；其他：`~/.profile`），追加一段带"由 Valise 添加"标记的 PATH 设置，已存在时不重复添加；执行后显示写入了哪个文件、哪几行，以及删除这几行即可撤销。
- **可选步骤**（2026-11-01 用户决定）：任何步骤都可以标 `optional: true`，同时必须写 `id` 与 `skip_effect`（不执行会怎样）。可选步骤**默认不执行**：界面逐项展示说明与 `skip_effect`，用户勾选（CLI 回答 y，或 `--with <id>`）后才执行；`--yes` 不会勾选可选步骤。
  - 所有步骤都在原生界面式的交互终端中运行（安装程序常需要回答问题），用户可以随时中止。
- **禁止**：把网络内容直接交给解释器（`curl | bash`、`bash <(curl …)`、`eval "$(…)"`）；运行时拼接下载地址；profile 中出现 shell 字符串（profilelint 拒绝）。
- **动态下载**：脚本运行时还会下载的内容（如运行时、二进制）无法预先检查。profile 必须在 `runtime_downloads` 中如实写明，界面原样展示："这一步还会从 X 下载 Y，Valise 无法预先检查其内容"。
- **展示层级**：默认展示通俗说明（"安装 OpenClaw 2026.10.9，约 300 MB，不需要管理员权限"）；展开后可查看实际命令、来源、权限与依赖。
- **结果判定**：安装完成后重新检测（profile 的 `detect`），找到实例并读出版本才算成功；版本或流程与方案不符时如实提示，提供原生方式继续。
- **审计**：记录方案 id、profile 版本、步骤、退出码与检测结果；不记录终端内容。

## 4. 依赖与权限

- 官方方案的 `requires` 声明所需的程序与版本（如 `node >= 22`），由 porter 按登录 PATH 检测并展示结果。
- 用户级就能完成的依赖（如官方二进制包解压到 `~/.local`），可以作为官方方案中的 `script` 步骤，遵守第 3 节。
- 需要 sudo、系统包管理器或修改系统配置的，**默认**不执行：界面展示需要执行的命令与原因，用户可以在原生界面（登录 shell）里自己执行、交给服务器管理员，或开启高级模式（4.1 节）由 Valise 代为执行。
- 较大的依赖（数百 MB 以上）与磁盘不足在执行前说明。

### 4.1 高级模式（原"完全访问模式"，2026-11-01 用户决定，2026-11-02 改名）

> 改名原因：界面上"完全访问""无需批准（Bypass）"只用来描述 agent 自己的审批状态（PROFILES.md 的 `approval_check`），Valise 自己的这个模式改叫"高级模式"，属于开发者模式之下（代码、界面与 CLI 参数已于 M12 改名）。

让不会用终端的用户也能装好运行时与依赖：开启后，Valise 可以在这台服务器上代为执行安装运行时、系统包与依赖的命令（包括需要 sudo 的命令）。

- **开启条件**：
  - 只能由用户在客户端界面里亲自开启，按服务器分别开启；CLI 需要显式参数并在终端里输入口令。管理方技能、MCP、网页与 LLM 都不能开启。
  - 前提是已设置 Valise 口令并已为这台服务器创建管理钥匙（没有时先引导创建）。
  - 必须通过两个口令的挑战：Valise 口令解开加密钥匙（`keystore.age`），管理口令解开这台服务器的管理钥匙，两个都对才算通过。
  - 开启前展示风险与免责说明，用户必须输入确认句"我知道高级模式可能损坏服务器，后果由我自行承担"：
    - Valise 将以你的身份、包括管理员权限修改服务器；
    - 系统包与运行时的改动不在 agent 的逃生舱里，Valise 无法撤销；
    - 疑点检查只能发现明显的问题，不能保证安全；
    - Valise 不为任何第三方软件背书。
- **开启后（接管）**：
  - 执行范围：
    - profile `requires` 中声明的依赖安装步骤（`requires[].install`，按发行版区分）；
    - 用户在 Valise 里输入的安装命令（来源标注为"你提供的"）；
    - agent 生成的草稿（来源标注为"agent 生成"），仍需用户确认。
  - 执行方式：
    - 每一批命令先过第 7 节的疑点检查，再展示一次完整计划，用户确认一次后连续执行，不再逐条确认；
    - 某一步失败或检查命中，立即停止；
    - 执行完按实际结果（程序是否存在、版本是否符合）判定成败。
  - 运行方式：
    - 命令都在管理钥匙新开的独立交互终端里运行；
    - sudo 的密码由用户在这个终端里直接输入，Valise 不读取、不保存。
- **超时与结束**：
  - 管理钥匙的时间窗口到期后，高级模式进入暂停：继续执行之前必须重新输入管理口令，正在执行的那一步跑完后才暂停。
  - 用户手动关闭、退出 Valise、切换到另一台服务器时，高级模式结束；下次需要重新开启（重新挑战口令、重新确认免责）。
- **不可放宽的底线**：
  - 第 7 节"一律不执行"的命令，在高级模式下同样不执行：编码、混淆、隐藏来源、管道直接执行网络内容，以及规则能识别的明显有害命令（大范围删除、格式化磁盘、覆盖系统关键文件、关闭安全机制等）。
  - 用户坚持要执行时，Valise 不接管、不提供绕过开关；界面说明原因，告诉用户只能自己登录服务器执行，Valise 不会为此打开终端或代输命令。
- **界面**：
  - 开启期间，顶栏持续显示红色的"高级模式 · <服务器> · 管理权限剩余 N 分钟"，并提供"立即关闭"。
  - 审计记录开启与关闭的时间、执行的每条命令及其来源、检查结果与退出码；不记录终端内容。
- **适用的服务器**（2026-11-01 用户决定）：只为 Valise 自己接入的服务器（有日常钥匙并已创建管理钥匙）提供。从 `~/.ssh/config` 导入的服务器、经网关"无认证"接入的机器（如 InstaBox 一类）不提供高级模式，也不为它们做特例；界面说明原因，建议用 Valise 接入一台正常的服务器。
- **M11 实现范围**：
  - 只执行 profile `requires[].install` 中、与服务器发行版匹配的依赖安装命令；用户输入的命令与 agent 草稿等第 7 节整体落地（M15 之后）。
  - CLI：`valise install <服务器> --profile <id> --advanced`。高级模式只存在于这一次运行的进程里，进程结束即结束；开启时在终端里依次输入 Valise 口令、管理口令与确认句。终端 UI 的红色顶栏与"立即关闭"随 M12 实现。
  - 确认：整批命令过第 7 节检查后展示一次，用户确认一次；检查命中"一律不执行"的规则时整批不执行；命中提权以外的疑点时，还要输入第 7 节的确认句。
  - 时间窗口：每一步开始前检查管理钥匙是否仍在窗口内，到期则暂停并要求重新输入管理口令；正在执行的那一步不打断。
  - 执行完后重新检测依赖，按实际结果判定成败；全部满足后才继续安装方案本身（方案仍按第 3 节单独确认）。

### 4.2 高级功能的前提：有一份放在别处、能独立恢复的备份（2026-11-02 用户决定）

- **受限的功能**：聊天转接、服务器终端与原生界面、高级模式、`config` / `danger` 风险的管理动作、harness 与工具安装、专家级 Kit。
- **放行条件**：存在一个逃生舱，**同时**在本机仓库或空间站上（只在服务器上不算），并且能独立恢复：本机仓库由客户端校验并试解；空间站要求服务器同步记录中有它、空间站列表也列出了它。档位最低允许"记忆与人格"，界面推荐"记忆与人格 + 凭据"（恢复后开箱即用）。
- **范围**：聊天转接与管理动作只看那个 agent；终端、原生界面、安装与高级模式看这台服务器上**全部已接入的 agent**，因为这些操作的破坏不限于一个 agent，而是整台服务器。每个 agent 各有一份就算满足（2026-11-03 用户确认）；界面同时建议所有 agent 都有一份，或在云厂商、虚拟化平台那里给服务器做一份快照（由用户自己做；Valise 不做整机备份）。还没有 agent 的服务器不受限。
- **太旧时**：别处那一份过旧时提醒，并写明会丢失多长时间的内容；可以忽略后继续。
- 不满足时写明原因，提供一键"建立逃生舱 → 放进仓库"。
- **自担风险继续**（2026-11-03 用户决定，取代"没有绕过开关"）：用户可以不满足前提而继续这一次操作，但必须自己承担数据丢失风险。确认页写明缺哪些备份，并醒目提醒"如果没有充足的备份，数据丢失将是永久性的"，建议先备份或先做服务器快照；只对这一次操作有效，不是常开的开关；CLI 用 `--accept-risk` 并在终端里再确认一次。本机仓库不需要任何工具，因此不会出现"装工具要先有云端备份"的循环。
- **实现约定**（M12，2026-11-02）：
  - 检查在服务层执行（`AdvancedGate` / `RequireGate`），CLI 与终端界面共用，入口包括服务器终端、原生界面、harness 安装、开启高级模式、`config` / `danger` 管理动作；管理动作只看它所属的那个 agent。登录中继不在受限列表中。
  - 本机仓库的副本：先做不需要钥匙的校验，再用 Valise 口令试解那一个逃生舱并核对每个文件的哈希；每个逃生舱只试解一次，结果记在 `repo-trial.json`。
  - 空间站的副本：服务器同步记录（`last_synced_snapshots`）里有它，且空间站列表里也有它（Valise 管理的空间站由客户端直接列出）。
  - "太旧"：别处最新的那一份超过 7 天。提醒写明多少天前、会丢失这段时间的内容；CLI 用 `--yes` 或回答确认，终端界面用确认框。
  - 终端界面被拦下时，列出缺备份的 agent 与原因，提供"备份并复制到仓库 <名称>"（推荐"记忆与人格 + 凭据"，也可只要"记忆与人格"）、"先去添加仓库或空间站"与"取消"；备份完成后重新检查并回到原来那一步。CLI 只给出说明。

## 5. 管理动作（M12 定稿 schema，2026-11-01 用户确认）

profile 可以登记若干管理动作，管理页根据它动态生成按钮。约束：

- 每项至少包含：`id`、名称、对用户的解释、`argv`（argv 数组，不是 shell 字符串）、风险等级、结果展示方式。
- 风险等级：`read`（只读查询）、`manage`（常规管理，如重启服务）、`config`（修改配置）、`danger`（高风险）。`read` 走日常钥匙；其余需要管理登录，执行前展示实际命令并确认；`danger` 需要再次确认。
- 结果分别展示命令退出状态与服务或功能的实际健康状态。
- 默认折叠实际命令，但始终提供"查看实际命令"；折叠只是视觉上的，不得用于隐瞒。
- **机密输出**（2026-11-01 用户决定）：结果是令牌一类的机密时，不显示在屏幕上，复制到本机剪贴板；20 秒后如果剪贴板里仍是它就清除（2026-11-01 用户决定，窗口尽量短，避免被粘贴到别处）。界面同时显示倒计时。提示用户剪贴板管理工具可能保留历史。不写入日志、审计与诊断材料，Valise 不另存。需要终端的命令（例如只在终端里显示令牌的命令）在新的伪终端里运行。
- 只执行签名资料包或用户本地 profile 中登记过的动作；登记或生成不等于执行。不提供条件、循环、变量求值等解释器能力（CLAUDE.md"禁止实现"）。
- **schema**（PROFILES.md 第 2 节 `actions`）：`id`、`name`、`explain`、可选 `undo`（能否撤销、怎样撤销）、`risk`、`argv`（只能引用 `${HOME}`）、`output`（`text` 显示输出 / `none` 不显示 / `secret` 机密）、`secret`（`output: secret` 时必填：`json_field` 点分字段与可选 `url_param`，从输出里取出机密本身；都不写时取输出的第一行）、可选 `terminal: true`。
- **在哪里查动作**：porter 只按服务器上保存的 profile 副本（登记时写入）里的动作 id 执行，客户端只传实例 id 与动作 id，不能经日常钥匙传任何命令。资料包新增或修改了动作，需要重新登记一次才能用；客户端发现本机 profile 与服务器副本不一致时提示"重新登记后可用"。
- **访问级别**：`read` 且不是 `secret` 的动作走日常钥匙；`secret` 一律需要管理登录（等同代取管理页令牌），即使风险等级是 `read`；其余等级需要管理登录。
- **需要交互终端的动作**（`terminal: true`）：在独立的管理连接与交互终端里运行（同原生界面），输出不经过 Valise；不能是 `secret`。
- **执行前**：`config` 与 `danger` 默认先建逃生舱，可以取消勾选，取消时说明后果；`danger` 需要输入动作名称才能执行。确认框写明会发生什么、不会发生什么、能否撤销（`undo`），并可查看实际命令。
- **结果**：命令退出码与动作后的实际状态分开展示（服务是否运行、管理页是否可达，`manage` 及以上等级）；`text` 输出最多保留最后 200 行；`none` 只显示退出码；`secret` 按上面的机密输出规则。
- **审计**：记录动作 id、风险等级、退出码与是否先建了逃生舱；不记录输出。

## 7. 用户或 AI 提供的安装命令（规则已定，M15 之后实现）

- **来源标注**：官方方案、用户提供的命令、agent 生成的草稿在界面上分别标明；agent 不得绕过用户确认。
- **展示**：执行前展示全部命令；涉及脚本时，先下载、展示全文与哈希，再执行文件（同第 3 节，禁止管道直接执行）。
- **基础疑点检查**：编码或混淆（如 Base64 解码后执行）、隐藏下载来源、网络内容直接交给解释器、提权、修改敏感配置（`authorized_keys`、sudoers、shell 启动文件、systemd 系统单元）、大范围删除或覆盖、来源与说明不一致。每个命中项说明原因；结果写"未发现基础疑点"，绝不写"安全"。
- **一律不执行**（包括高级模式，4.1 节）：编码、混淆或隐藏来源、无法向用户清楚展示实际内容的命令，以及规则能识别的明显有害命令。Valise 不提供任何绕过开关；用户坚持时只能自己登录服务器执行，之后可以再登记管理。
- **高风险确认**：命中疑点或需要提权时，要求用户输入确认句"我知道自己可能会面临安全风险，确认"，并再次确认一次。
- **局限**：检测不能识别所有隐藏行为；运行时动态下载的内容范围要明确写成"未知"。
- **M11 先行实现的检查**（用于高级模式的整批命令，`core/install` 的 `CheckCommand`）：命令按 argv 检查，不经过 shell。
  - 一律不执行：参数里出现命令替换（`$(`、反引号）或编码解码后执行（`base64 -d`、`xxd -r` 等）；网络内容经管道交给解释器（`curl … | sh` 一类）；解释器执行的内联代码里含下载、解码或 `eval`；删除或改写根目录、家目录或系统目录（`rm -r /`、`--no-preserve-root`、对 `/etc` `/usr` `/boot` 等递归删除、递归 chmod/chown 根目录）；格式化或直接写磁盘（`mkfs*`、`dd of=/dev/…`、`wipefs`、`fdisk`、`parted`、`sgdisk`）；关闭安全机制（`setenforce 0`、`ufw disable`、停用或屏蔽 ssh、防火墙、AppArmor、auditd）；删除用户密码；fork 炸弹。
  - 疑点（说明原因）：提权（`sudo`、`doas`、`su`、`pkexec`）；修改敏感配置（`authorized_keys`、sudoers、shell 启动文件、`/etc/systemd/system`）；下载（列出地址）；解释器执行内联代码；递归删除。
  - 没有命中时写"未发现基础疑点"。
