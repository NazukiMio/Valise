## 2. 原生界面

把 harness 自带的交互式 CLI 交给用户直接操作，用于原生安装引导、原生设置、填写模型凭据等。

- **入口**：安装流程中"用原生方式继续"；实例页"原生界面"（高级）。具体命令来自 profile 的 `native_cli`（PROFILES.md 第 2 节），例如 `[openclaw, onboard]`；也可以打开一个普通的登录 shell。
- **连接**：要求管理钥匙已解锁；每次新开一条 SSH 连接 `ssh -tt -o ControlPath=none -o IdentitiesOnly=yes -i <管理钥匙> …`，绝不复用日常通道或已有连接（ARCHITECTURE.md 第 2.1 节）。
- **TUI**：暂停界面，把本机终端直接交给 `ssh` 子进程（标准输入输出继承），Valise 进程不经手任何字节；退出后恢复界面并重新检测实例状态。
- **GUI（M7b）**：需要内嵌终端，字节经 Valise 中转。要求：不解析、不保存、不写入日志、诊断材料或崩溃报告；不做终端录制；关闭窗口即结束连接。具体的 PTY、断线处理与回显策略在 M7b 设计并测试。
- **凭据边界**：用户在原生界面中输入的 API Key 等，Valise 不读取也不提供输入框；文案不得声称"凭据完全不经过 Valise"，只说"Valise 不读取、不保存、不记录"。
- **结束后**：按实际结果（实例是否被发现、服务是否健康、管理页是否可达）判断，不以命令退出码代替。

## 3. 官方方案

官方方案写在签名资料包的 profile 中（`install` 段，PROFILES.md 第 2 节），只覆盖已核实的版本与安装方式。

- **步骤种类**（第一版）：
  - `npm_global`：`{package, version, integrity}`，以用户级前缀安装精确版本，安装后核对 integrity。
  - `script`：`{url, sha256, interpreter: [bash], args: [...], runtime_downloads: "…"}`。客户端下载脚本（不经服务器），核对 SHA-256，**把脚本全文展示给用户**（可滚动、可另存），确认后经管理钥匙上传到服务器的 `~/.local/state/valise/install/<op>/`，再以 `interpreter + 文件路径 + args` 执行。哈希不符时停止，说明"官方脚本已变化，此版本方案不再适用"，提供原生方式。
  - `argv`：harness 安装后执行的固定命令（例如初始化），逐字展示。
  - 所有步骤都在原生界面式的交互终端中运行（安装程序常需要回答问题），用户可以随时中止。
- **禁止**：把网络内容直接交给解释器（`curl | bash`、`bash <(curl …)`、`eval "$(…)"`）；运行时拼接下载地址；profile 中出现 shell 字符串（profilelint 拒绝）。
- **动态下载**：脚本运行时还会下载的内容（如运行时、二进制）无法预先检查。profile 必须在 `runtime_downloads` 中如实写明，界面原样展示："这一步还会从 X 下载 Y，Valise 无法预先检查其内容"。
- **展示层级**：默认展示通俗说明（"安装 OpenClaw 2026.10.9，约 300 MB，不需要管理员权限"）；展开后可查看实际命令、来源、权限与依赖。
- **结果判定**：安装完成后重新检测（profile 的 `detect`），找到实例并读出版本才算成功；版本或流程与方案不符时如实提示，提供原生方式继续。
- **审计**：记录方案 id、profile 版本、步骤、退出码与检测结果；不记录终端内容。

## 4. 依赖与权限

- 官方方案的 `requires` 声明所需的程序与版本（如 `node >= 22`），由 porter 按登录 PATH 检测并展示结果。
- 用户级就能完成的依赖（如官方二进制包解压到 `~/.local`），可以作为官方方案中的 `script` 步骤，遵守第 3 节。
- 需要 sudo、系统包管理器或修改系统配置的，**默认**不执行：界面展示需要执行的命令与原因，用户可以在原生界面（登录 shell）里自己执行、交给服务器管理员，或开启完全访问模式（4.1 节）由 Valise 代为执行。
- 较大的依赖（数百 MB 以上）与磁盘不足在执行前说明。

### 4.1 完全访问模式（2026-11-01 用户决定）

让不会用终端的用户也能装好运行时与依赖：开启后，Valise 可以在这台服务器上代为执行安装运行时、系统包与依赖的命令（包括需要 sudo 的命令）。

- **开启条件**：
  - 只能由用户在客户端界面里亲自开启，按服务器分别开启；CLI 需要显式参数并在终端里输入口令。管理方技能、MCP、网页与 LLM 都不能开启。
  - 必须通过两把钥匙的口令挑战：输入 Valise 口令，Valise 分别用它解开加密钥匙（`keystore.age`）和这台服务器的管理钥匙，两者都成功才算通过。
  - 开启前展示风险与免责说明，用户必须输入确认句"我知道完全访问模式可能损坏服务器，后果由我自行承担"：
    - Valise 将以你的身份、包括管理员权限修改服务器；
    - 系统包与运行时的改动不在 agent 的逃生舱里，Valise 无法撤销；
    - 疑点检查只能发现明显的问题，不能保证安全；
    - Valise 不为任何第三方软件背书。
- **开启后（接管）**：
  - 执行范围：
    - profile `requires` 中声明的依赖安装步骤（`requires[].install`，按发行版区分）；
    - 用户在 Valise 里输入的安装命令（来源标注为"你提供的"）；
    - agent 生成的草稿（来源标注为"agent 生成"），仍需用户确认。
  - 执行方式：
    - 每一批命令先过第 7 节的疑点检查，再展示一次完整计划，用户确认一次后连续执行，不再逐条确认；
    - 某一步失败或检查命中，立即停止；
    - 执行完按实际结果（程序是否存在、版本是否符合）判定成败。
  - 运行方式：
    - 命令都在管理钥匙新开的独立交互终端里运行；
    - sudo 的密码由用户在这个终端里直接输入，Valise 不读取、不保存。
- **超时与结束**：
  - 管理钥匙的时间窗口到期后，完全访问模式进入暂停：继续执行之前必须重新输入管理钥匙的口令，正在执行的那一步跑完后才暂停。
  - 用户手动关闭、退出 Valise、切换到另一台服务器时，完全访问模式结束；下次需要重新开启（重新挑战口令、重新确认免责）。
- **不可放宽的底线**：
  - 第 7 节"一律不执行"的命令，在完全访问模式下同样不执行：编码、混淆、隐藏来源、管道直接执行网络内容，以及规则能识别的明显有害命令（大范围删除、格式化磁盘、覆盖系统关键文件、关闭安全机制等）。
  - 用户坚持要执行时，Valise 不接管、不提供绕过开关；界面说明原因，告诉用户只能自己登录服务器执行，Valise 不会为此打开终端或代输命令。
- **界面**：
  - 开启期间，顶栏持续显示红色的"完全访问模式 · <服务器> · 管理权限剩余 N 分钟"，并提供"立即关闭"。
  - 审计记录开启与关闭的时间、执行的每条命令及其来源、检查结果与退出码；不记录终端内容。

## 5. 管理动作（M12 定稿 schema）

profile 可以登记若干管理动作，管理页根据它动态生成按钮。约束：

- 每项至少包含：`id`、名称、对用户的解释、`argv`（argv 数组，不是 shell 字符串）、风险等级、结果展示方式。
- 风险等级：`read`（只读查询）、`manage`（常规管理，如重启服务）、`config`（修改配置）、`danger`（高风险）。`read` 走日常钥匙；其余走管理钥匙，执行前展示实际命令并确认；`danger` 需要再次确认。
- 结果分别展示命令退出状态与服务或功能的实际健康状态。
- 默认折叠实际命令，但始终提供"查看实际命令"；折叠只是视觉上的，不得用于隐瞒。
- 只执行签名资料包或用户本地 profile 中登记过的动作；登记或生成不等于执行。不提供条件、循环、变量求值等解释器能力（CLAUDE.md"禁止实现"）。

## 6. 第三方工具（M15）

- 第一阶段只登记用户已安装的工具：用户创建 tool-profile（服务、状态、端口、管理页、动作），格式与 harness profile 共用相关部分，具体 schema 在 M15 设计。
- 逐项测试（程序存在、服务状态、端口、管理页连接），只陈述已验证的内容；Valise 不为工具的安全性背书。
- 工具安装（M15 之后）：走第 7 节；每次要求管理钥匙已解锁并新开独立 SSH 连接（ARCHITECTURE.md 第 2.1 节）。安装前建议先建立逃生舱，允许跳过，并说明：agent 的逃生舱不等于服务器整机备份，不能撤销工具对系统、其他服务或外部资源的修改。
- 用户提到的 Magpie 是将来的测试案例，不视为已支持。

## 7. 用户或 AI 提供的安装命令（规则已定，M15 之后实现）

- **来源标注**：官方方案、用户提供的命令、agent 生成的草稿在界面上分别标明；agent 不得绕过用户确认。
- **展示**：执行前展示全部命令；涉及脚本时，先下载、展示全文与哈希，再执行文件（同第 3 节，禁止管道直接执行）。
- **基础疑点检查**：编码或混淆（如 Base64 解码后执行）、隐藏下载来源、网络内容直接交给解释器、提权、修改敏感配置（`authorized_keys`、sudoers、shell 启动文件、systemd 系统单元）、大范围删除或覆盖、来源与说明不一致。每个命中项说明原因；结果写"未发现基础疑点"，绝不写"安全"。
- **一律不执行**（包括完全访问模式，4.1 节）：编码、混淆或隐藏来源、无法向用户清楚展示实际内容的命令，以及规则能识别的明显有害命令。Valise 不提供任何绕过开关；用户坚持时只能自己登录服务器执行，之后可以再登记管理。
- **高风险确认**：命中疑点或需要提权时，要求用户输入确认句"我知道自己可能会面临安全风险，确认"，并再次确认一次。
- **局限**：检测不能识别所有隐藏行为；运行时动态下载的内容范围要明确写成"未知"。

## 8. 用户自建 profile（M14 之后）

- 两条路径共享格式与测试流程：表单（参考官方文档填写路径、服务、端口、动作）与官方技能（用户提供文档链接，由 agent 协助生成草稿，用户审阅）。
- AI 生成的结果是草稿，命令与路径可查看，不擅自执行；逐项测试只陈述已验证的内容（PROFILES.md 1.2）。
