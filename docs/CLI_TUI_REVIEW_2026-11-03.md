# Valise CLI / TUI 实机检测与改进报告

- 日期：2026-11-03
- 检测版本：`760ff8fda6a783824eb923b2d78b2c0e66427397`
- 性质：产品体验检测、有限代码核对与改进提案；不是完整安全审计或里程碑验收。

> 本报告记录本轮观察与后续建议，不替代 PRODUCT、ARCHITECTURE、PROFILES、INSTALL、UI 等现行规范，也不授权跨里程碑实现功能。涉及规则调整时，先由用户决定，再修改对应规范。已纳入用户对“忽略状态”与“窗口下限”的反馈。

## 1. 结论

备份恢复内核已经具备实用价值。本轮实际完成了从零安装 harness、封存、本机仓库同步、NAS 直传、恢复测试、真实原地回滚、独立恢复、OpenAI OAuth 登录、真实对话和 MCP 调用。

当前主要问题是流程衔接、状态解释和入口一致性：官方安装与来源登记没有闭环；CLI 与 TUI 的空间站浏览路径不同；部分长操作缺少进度；若干界面仍沿用旧定位与旧文案。应优先修复这些断点，再扩展工具种类和外围能力。

TUI 更适合运维与恢复；GUI 面向新人的价值，需要单独验证。不能因为 TUI 用户通常能找到原生对话入口，就否定 GUI 中快捷对话、投递技能提示词和首次使用引导的价值。项目当前免费开源，本报告不以商业化、付费转化或打开次数为优化目标。

## 4. 发现与改进建议

### F01 — 官方安装与来源登记断开（已复现，P1）

**观察**：安装成功后，接入报告显示“可执行文件不属于 npm 包，无法记录来源”，版本为未知。当前安装器生成了启动包装脚本；来源探测向上寻找 package.json，失败后查询当前 npm 的全局根目录，在本轮保留了既有 npm 前缀配置的环境中没有找到实际安装包。

**影响**：用户按照产品提供的方案安装，却不能完成异机重建。克隆计划又将缺失来源报告成“来源已变化”，提示与事实不符。原地回滚计划还显示“同一来源、同一版本”，而来源版本实际未知；这条相等判断的依据也需复核，不能把回滚成功当成来源已被正确识别。

**建议与验收**：把来源完整性列入安装收尾检查；通过通用 profile 能力或安装结果记录解决，不在 Go 中加入具体 harness 特例。分别报告来源缺失、来源不符、版本不可取得和校验失败。覆盖已有 npm 用户前缀、私有安装前缀及包装脚本环境；安装结束后应能生成可执行的异机恢复计划。

代码线索：`porter/internal/enroll/provenance.go`。

### F02 — CLI 空间站列表走错权限路径（已复现，P1）

**观察**：NAS 直传成功后，CLI `target list` 返回 `rrsync: reading from write-only server is not allowed`；TUI 能浏览同一位置。代码核对显示，CLI 使用的 `TargetList` 直接请求服务器，而 `StationList` 已按服务器证书只写的设计由客户端读取。

**建议与验收**：统一空间站识别与路由，覆盖 CLI、TUI、健康检查和副本检查入口。保留服务器只写、不删、不覆盖的权限边界。相同空间站应返回一致结果；权限拒绝不能一律建议用户检查普通 SSH 登录。

代码线索：`client/ui/cmd/valise/cloud.go`、`client/ui/service/cloud.go`、`client/ui/service/station.go`。

### F03 — 指定小快照仍拉取大周期，CLI 缺进度（已复现，P1）

**观察**：恢复新建的约 2.9 MiB 快照前，客户端先下载包含旧 raw 备份的约 247 MiB 周期数据。等待达到数分钟，CLI 没有持续说明当前传输内容和进度。

**建议与验收**：先补阶段、下载范围、字节数和等待原因，再评估按快照依赖拉取必要 pack 的能力。使用“大历史周期中的小快照”验证，避免只测空金库。若暂时必须下载整个周期，开始前明确说明。

### F04 — 小窗口确认内容不可完整阅读（已复现；P1，方案待决策）

**观察**：80×24 下，本地资料包确认页截断长命令，PgDn 没有使完整内容可见。多个页面的标题、图标和重复说明也明显挤占操作区域。

**用户反馈**：80×24 可能过小；应考虑各种窗口体验，也可以设置最小启动尺寸。

**结论**：不能仅凭小窗口不舒适就判定整个布局失败，但不应允许用户确认未能查看完整的关键内容。现行 `UI.md` 仍要求 80×24 可完整使用；采用新的下限前需先修改规范，不能把建议当作已经决定的标准。

**可选方案**：自适应紧凑布局、滚动与换行；或低于明确下限时显示尺寸提示并阻止进入不完整的操作页。也可组合两者。TUI 以列×行为单位，GUI 另行规定窗口尺寸；不要擅自调整用户的终端窗口。

**验收**：确定最小值、推荐值以及阈值附近行为；覆盖长名称、长路径、长命令、窗口缩小再放大。关键内容必须可查看；进入交换阶段后，即使窗口缩小也不能中断操作。未选定方案前，不新增具体尺寸承诺。

### F05 — 中断原生向导后，远端操作残留（已复现，P1）

**观察**：测试端结束本地连接后，服务器上的 onboarding 进程未退出。用户随后启动向导，收到“Another onboarding/config operation is running”及 PID 提示。核对并关闭遗留进程后，改用 OAuth 登录中继完成授权。

**边界**：这次涉及测试连接异常结束，不能据此断言所有正常取消路径都有问题。不能在缺少归属证据时自动结束其他用户或其他操作的进程。

**建议与验收**：识别本次操作、远端进程及存活状态，提供重连、等待和明确确认后的结束入口。分别验证正常退出、Ctrl+C、连接断开和客户端异常结束；对已经结束的操作清理状态，不能让用户自己猜 PID。

### F06 — 安装后返回 TUI 的状态衔接滞后（已观察，P2）

**观察**：安装和接入已完成，返回 TUI 时仍一度显示没有 agent，并残留“正在确认仓库或空间站……”的提示；手动刷新后显示新实例。

**建议与验收**：任务收尾清除旧提示、刷新相关状态并进入明确的完成页或实例页。成功、失败、取消分别验证；不要让用户依靠刷新判断是否需要重复安装。

### F07 — 概览与健康页显示不同（待复核，不定为已确认缺陷）

**观察**：概览显示“需要处理：无”，健康页仍列出审批提醒。

**用户纠正**：健康页可能已经选择“忽略”；客户端也可能抓到了以前的数据。此前将其直接判定为摘要口径错误，证据不足，撤回该确定性结论。

**复核要求**：先用全新配置且无忽略记录复测；再分别测试黄色永久忽略、红色限期忽略、到期恢复、刷新及重启。记录实际使用的配置目录、实例标识、缓存时间和忽略状态。已忽略问题留在健康详情中，不一定意味着它仍需计入摘要。

**建议**：详情可显示“已忽略”和有效期，区分发现仍存在与当前需要处理；保留手动重新检查入口。仅在排除忽略及旧数据影响后，再决定是否需要修复摘要计算。

### F08 — 首次启动与现行定位不一致（已复现，P2）

**观察**：欢迎页主要介绍备份，口令步骤没有“稍后设置”；添加服务器入口依赖已有 SSH 别名，与现行安装管理定位及规范中的手动填写路径不一致。

**建议与验收**：首次任务优先连接服务器、安装或接入 agent；按需要补齐加密保障。验证没有 SSH 配置的新用户路径。GUI 可把首次成功结果延伸到“向 agent 发出第一句话并收到回应”，不把配置模型凭据变成所有用户必须立即完成的步骤。

代码线索：`client/ui/tui/wizard.go`、`client/ui/tui/addserver.go`。

### F09 — 开发版本发布入口和旧文案（已复现，P2）

**观察**：在线资料包入口返回 HTTP 404，建议却是确认用户没有填写的版本号；本地包安装又提示客户端缺少 Release 公钥。服务器起名页仍说“起好后不能改”，当前已有改名功能；部分动作仍笼统写“需要管理登录”，未清楚对应新的操作分级。

**建议与验收**：开发构建准确说明其可用来源和发布能力，不能由本轮 404 推断正式发布链的全部状态。清理已过期说明，动作文案来自实际访问级别。核对默认路径，而不仅检查错误对象是否有 suggestion 字段。

### F10 — MCP 的事实被 agent 解释错（已复现，P2）

**观察**：agent 确实调用了 `valise_status`，随后称“同步目标列表为空”。直接核对结构化返回，它实际只有空的 `last_seal_synced_to`，并没有配置目标列表；CLI 同时确认 NAS 目标存在，之前的备份已经同步，只是最新 MCP 自动备份尚未同步。

**建议与验收**：明确区分已配置目标、最新备份的副本、最近异地备份和正在等待同步。决定性说明尽可能由代码生成，LLM 只解释。测试“已有异地历史副本，但最新备份只有服务器副本”的场景，不能把空数组推断成未配置目标。

### F11 — “两处都有才算真正安全”承诺过强（已复现，P2）

**观察**：仓库与空间站页使用上述说明。两处存在副本并不证明副本已解密验证、存储故障域独立或运行恢复成功。

**建议与验收**：分别展示副本位置、校验状态、最近试解时间和运行恢复证据，不将其合成绝对安全判断。

代码线索：`client/ui/tui/cloud.go`。

## 5. 安全措施取舍

### 应保留

- SSH 权限分级、独立管理连接、签名与哈希核对、标准 age 加密、交换日志和独立恢复路径。
- 只绑定回环地址、明确报告端口冲突、不静默修改端口。
- 恢复计划与交换前确认：本轮两次确认分别说明“准备什么”和“何时开始影响运行状态”，有实际作用。
- 服务器访问 NAS 的只写边界。F02 应修复调用路径，而不是扩大服务器证书权限。

这些措施并未在本轮全部独立做安全验收；保留建议不等于宣称没有漏洞。

### 应减轻或重新讨论的负担

- 提前强制设口令：延后至首次需要加密保障的步骤，符合渐进引导方向。
- 不能读全却要求确认的内容：以简短摘要辅助判断，完整命令可查看；不要用更多免责文字替代信息呈现。
- 笼统、重复的未审核警告：说明当前动作受什么影响，避免长期占据主视图。
- 终端、原生界面等功能检查服务器全部 agent 异地备份的门槛：规范有此要求，但本轮未完整复现其最坏阻断场景。应研究是否会妨碍修复故障实例，再决定是否调整范围；本报告不自行放宽规则。

本轮自带 SSH 路径的安装没有遇到双口令门槛。不能把架构中的全部安全分级都算作已经观察到的日常使用负担。

## 6. 可删减、延后和新增的能力

| 建议 | 理由与边界 |
| --- | --- |
| TUI 未实现对话页可收敛为快捷入口，待决定 | 对 TUI 优先提供打开原生对话、复制技能提示词；不据此否定 GUI 聊天入口 |
| 默认卡片、图标和重复标题更紧凑 | 先保证状态与操作可见；装饰可保留为可选展示，不仅凭伪终端输出评价具体视觉效果 |
| 必需教程与可选介绍分开 | 管理钥匙、Kit 等介绍不应让已完成核心任务的用户一直感到未完成 |
| 第三方工具管理、伴生记忆插件继续后置 | 当前完整使用链路的断点更值得优先投入 |
| 安装后连续引导 | 串联接入、模型登录、首次回应、技能安装和 MCP 验证，支持暂停与继续 |
| 中断操作恢复入口 | 显示真实状态，帮助处理残留向导和连接；不盲目结束未知进程 |
| 来源完整性与迁移准备检查 | 安装结束即说明是否满足重建条件，避免出事时才发现缺记录 |
| 按快照取回和持续进度 | 控制传输成本，让等待原因可见 |
