## 一、需要确认的设计点

### A. 管理动作（INSTALL.md 第 5 节）的 schema 与执行

示例（OpenClaw，命令都要在靶机上核实后才写进 profile）：

```yaml
actions:
  - id: status
    name: 查看网关状态
    explain: "显示网关是否在运行、监听在哪个端口"
    risk: read                      # read | manage | config | danger
    argv: [openclaw, gateway, status]
    output: text                    # text | none | secret
  - id: copy-token
    name: 复制控制台令牌
    explain: "把控制台登录用的令牌复制到剪贴板（不显示）"
    risk: read
    argv: [openclaw, dashboard, --no-open, --json]
    output: secret
    secret: { json_field: url, url_param: token }   # 从输出里取出令牌本身
  - id: restart
    name: 重启网关
    explain: "重启 OpenClaw 网关服务；正在进行的对话会中断几秒"
    risk: manage
    argv: [systemctl, --user, restart, openclaw-gateway.service]
    output: none
  - id: new-token
    name: 生成新的控制台令牌
    explain: "生成新的网关令牌；旧令牌立即失效"
    undo: "无法撤销；已登录的浏览器需要用新令牌重新登录"
    risk: config
    argv: [openclaw, doctor, --generate-gateway-token]
    output: none
```

需要你定的几点（括号里是我的建议）：

1. **在哪里查动作**：porter 只按服务器上保存的 profile 副本（登记时写入）里的动作 id 执行，客户端不能经日常钥匙传任意命令。资料包新增了动作，要重新登记一次才能用，界面会提示。（建议这样，日常钥匙被盗也只能跑已登记的只读动作。）
2. **机密输出一律需要管理登录**，即使风险等级是 `read`（取令牌等于代取管理页令牌，原来就是管理操作）。机密按 20 秒剪贴板规则处理。
3. **需要交互终端的动作**（`terminal: true`）：在独立的交互终端里运行，和原生界面一样，输出不经过 Valise；这类动作不能是 `secret`。
4. **`config` 与 `danger` 执行前默认先建逃生舱**，可以取消勾选，并说明不建的后果（同两边改端口）。
5. **`danger` 的再次确认**：输入动作名称才能执行。
6. **结果展示**：命令退出码与动作后的实际状态分开显示（服务是否运行、管理页是否可达）；`read` 只显示输出（最多最后 200 行，可滚动）。
7. **审计**：记录动作 id、风险等级、退出码；不记录输出。

### B. 首页服务器卡片的样式

UI.md 9.2 没有规定卡片尺寸。我的建议是：**首页用整宽的服务器卡片纵向排列**（每台服务器 4～5 行：名称、在线、各 agent 一行状态、需要处理的事、一行备份状态）。服务器卡片没有图标，信息是列表性质，纵向更好读。横向翻页的标准卡片只用在服务器页的实例卡片上（UI.md 8.1）。

### C. 图标

- lint 改为新标准：标准图标最多 12 行 × 24 列，紧凑图标最多 6 行 × 12 列（现在是 16 × 32）。
- OpenClaw 现有图标是 10 行 × 22 列，已经符合新标准，草图里直接用的就是它。你之前说会重绘：如果要换，给我新图案即可。没有 `icon_compact` 时按 UI.md 8.1 的点缩放兜底。
- 没有图标的 harness 用你画的机器人（标准 / 紧凑两个尺寸）。

