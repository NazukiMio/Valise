### 真实 CLI / TUI

客户端使用新建配置目录、测试专用 SSH 包装器和真实系统 SSH；包装器仅将远端 HOME 指向本轮隔离目录，未修改用户 SSH 配置。它不验证新一轮 sshd 日常钥匙/管理钥匙隔离，不能将本轮结果写成该认证链路的实机验收。

CLI 通过：动作清单与计划；用户确认后取消且审批仍 Bypass；执行后分项结果；status；重复 resume；明确 cleanup。另用一次性口令在进程内生成临时客户端密钥，登记其公钥，确认默认备份的 snapshot id 写入操作记录；口令没有打印、记录或另存。本项验证备份调用与关联，不将最小资料的备份称为完整真实 agent 的恢复验收。

TUI 通过：实际 PTY 80×24 启动并导航；查看异步事务计划后取消；默认备份因未登记收件人而失败时不执行配置；单次明确选择不备份后的配置执行、分项结果及操作详情页。测试也发现并修复了 TUI 风险接受未传给服务层的问题。CLI/TUI 使用 run 技能启动实际应用；不是仅运行内部函数或测试截图。实际启动需要专用 SSH/PTY 驱动，建议后续用 `/run-skill-generator` 固化为项目运行技能。

## 4. 实际写入与审批读取的限制

隔离运行 `exec-policy preset cautious` 后，除了主配置，还观察到备份、`config-journal-fingerprint.key`、SQLite 主库/WAL/SHM、`tmp/`。因此仅列两个 JSON 文件不足以声明写入范围。

紧接 preset 的第一次 `exec-policy show --json` 改变了 `state/openclaw.sqlite-shm`；后续连续两次读取没有发现文件内容变化。完整事务第一次实测因“审批读法意外改变暂存配置”被拒绝，没有发布，并恢复原服务。

临时验收资料随后将首次 show 列为明确的第二个暂存步骤，再单独做严格审批复核，以上合成服务事务通过。事务环境同时重定向 STATE_DIR、CONFIG_PATH 和 harness HOME。该证据只覆盖所测试的隔离状态，不能据此断言任意已使用配置或运行中的网关都可安全暂存。
