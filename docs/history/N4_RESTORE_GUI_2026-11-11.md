## 1. 本段范围

从旅程的一个时间点、或备份位置中的该时间点进入。共用：选择用法与去处 → 读取及核对来源、准备计划 → 第一次确认 → 暂存与校验 → 第二次确认 → 目录交换与复核 → 分项结果。

- 恢复当前实例：目标是当前实例，保留其世代。按快照当时的范围恢复；范围外内容按既有回滚规则携带。
- 迁移：目标是另一台已接入服务器。第二次确认后核实停用源实例；只有真实成功结果才接续旅程。源的备份和旧目录不自动删除。
- 创建副本：目标为另一台服务器，独立标识与旅程；原实例继续使用。排除 profile 声明的独占凭据，列出文件及影响，不猜测或扫描秘密。
- 同服务器创建副本不在现有 PlanRevive 支持范围，本段不画成可用选项。
- 本段不顺带交付导出、失联恢复、原生终端或旧目录清理。这些按 DEV_PLAN.md 后续分段推进；草图中的源失联仅为边界说明，不给假执行按钮。

## 2. 页面与信息取舍

1. 时间点详情保留一个节点、多个位置。主操作“使用这个时间点…”。发现记录、材料齐全、解密校验、暂存校验与运行结果分别展示。
2. 用法页有三个互斥选项。来源位置与原服务器分开，显示读取状态；不因同名合并，不在来源失败时静默换另一份。命名实例在必要时明确填写目标目录，不推测默认实例的位置。
3. 计划页先回答谁会变、哪些内容会变、会停哪些服务。路径、具体命令、文件清单和技术 ID 折叠。资料未测试和快照内资料各有独立确认，不能用一个风险勾选跳过硬阻断。
4. 来源身份不明时，展示快照自带信息；用户明确选择“我清楚，继续”，或目标有可备份实例时“先备份当前状态再恢复”。后者失败就不开始暂存。
5. 含凭据的时间点写清将恢复凭据；副本列出排除项。当前执行器没有通用的逐项凭据删改开关，不画出不能落实的任意排除 UI。
6. 准备页只报告真实阶段与可用字节进度。停止准备需核实停止结果，已产生的缓存或暂存单独说明，不称作完全撤销。
7. 第二次确认绑定这次暂存、目标与原冻结计划；明确从这里起可能停服、交换不可取消。确认过期或现场变化，重新核实，不能复用旧勾选。
8. 交换中允许切页，但退出要协调到安全边界。断线和强退后先核实原操作，不自动重发，不把失联写成取消。
9. 结果分开写文件、目录交换、服务状态、健康、身份关系；失败回退、没有服务和结果未知各有示例，不汇成绿色成功徽标。

## 3. 现有实现映射与接入缺口

| 草图部分 | 既有服务/规则 | 实施时要补的适配 |
| --- | --- | --- |
| 时间点与位置 | JourneyReader / SnapshotRef、全位置只读元数据 | 绑定完整 SnapshotRef 和准确来源，冲突硬阻断；不能把元数据副本当完整材料 |
| 读取备份和目标预检 | PlanRevive、ReviveOptions、SnapshotPull | 窗口口令、后台进度、计划生命周期、profile 允许项；失败保留具体下一步 |
| 来源适配 | 服务器、repo、dir、这台电脑登录的 cloud 已有 Source 实现 | 目前不是任意备份位置都能直接交给 PlanRevive。NAS/服务器登录的云盘等需限定配置目标的恢复读取适配，或用明确可用的本机材料入口；未做完前不渲染对应执行入口 |
| 第一次确认 | RevivePlan / Blockers / Required access | GUI 持有计划，不 JSON 往返授权，不把口令解锁当计划确认 |
| 来源身份不明 | ReviveConfirm.UnverifiedSource | 主线程展示选择；确实有目标实例才出现先备份选项 |
| 暂存与第二次确认 | ExecuteReviveConfirmed / StageVerifyResult / Swap callback | 将回调适配为等待用户的窗口状态；先核对有效期和现场再推进 |
| 交换、回退与重连 | 既有 revive journal、ReviveResume | 只提供现场核实后允许的固定继续/退回分支，不作通用重试按钮 |
| 完成与旅程 | SwapResult、身份关系记录 | 文件、服务、健康、关系逐项映射；失败或仅暂存不生成成功迁移边 |

恢复范围、旧快照、凭据、目录交换和保护计划均按现行规范执行。现有 PlanRevive 的准备步骤会读取并缓存材料、解密头并查询目标，不应在用户刚打开详情时自动调用；草图以明确的“查看计划”作为触发。

## 4. 评审后实施与验收

先把用户确认的布局/措辞写入 UI.md，再接服务和恢复来源适配。按场景补 fake-ssh 与视图回归，完整自检后再在真实 Linux 上验收恢复、迁移、副本、共享服务影响、取消/到期、断线核实与失败回退。已有 CLI 实测不能替代 GUI 全链路；不改 profile 的核实状态来代替实际演练。

草图是浏览器中的本机交互示意，所有数据均为明确标示的示例，不连接服务器、不收集口令、不读写备份。正式产品仍用 mygo v0.7.3 原生 UI。
