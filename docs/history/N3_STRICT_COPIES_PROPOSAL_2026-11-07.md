## 1. 现状与问题

`service.LeafCopies` 判“完整”的依据是：这一处的快照数等于各处中最多的快照数。删除周期（CLI `vault delete`、TUI 空间清理）凭它决定要不要加一次“没有其他完整副本”的确认。它不核对 pack、index、epoch、key，不核对内容，读取失败的位置直接略过；服务器上的快照只按 ID 计数。

## 2. 基准：材料清单

- **材料清单**（material list）：一个叶子里除 `DELETING`、临时文件（`tmp-*`、`.part-*`）与 `.partial.json` 外每个文件的相对路径、大小和 SHA-256，按路径排序后取摘要。pack 的 SHA-256 就是它的名字。
- **基准**：服务器在线时，由 porter 对服务器叶子现算（新只读方法 `leaf_materials`，日常钥匙）。已结束的周期，这份清单就是最终的；当前周期的清单只代表“截至这一刻”，副本只能证明“齐至这一刻”（契约 5.2）。
- **服务器不可达**：没有基准。只能对某一处证明“这里现有的材料自成一体、能恢复它列出的快照”，不能证明灾难前没有更多快照；这种结论不放宽删除（契约 5.2）。

## 3. 每一处要核对的两件事（契约 5.2 的 check）

| check | 怎么核对 | 结果 |
| --- | --- | --- |
| `period_material` | 这一处的文件集合与基准逐项对比：路径齐全、大小相同；非 pack 的小文件（VAULT、PERIOD、epochs、keys、index、快照 `.age` 与 `.meta.json`）比 SHA-256 | 缺哪些、多哪些、哪些不同，列出路径 |
| `integrity` | 第 7 节免钥匙校验：pack 的 SHA-256 等于名字；index 的范围落在 pack 内；每个 meta 有 `.age`；每个 epoch 有 `epochs/<n>.json` 与 `keys/dedupe.<n>.age` | 逐项问题 |

“完整副本” = 当场重新列出后 `period_material` 通过，且 `integrity` 通过（可复用缓存，见第 5 节）。读取失败为“未知”，不算完整。`DELETING` 或 `.partial.json` 存在一律不算完整。

## 4. 各种位置在哪里核对

| 位置 | period_material | integrity |
| --- | --- | --- |
| 服务器金库 | porter 本地 | porter 本地（现有 `VerifyNoKey`） |
| 本机仓库 | 客户端直接读 | 客户端直接读 |
| 服务器自己配置的位置（rsync） | porter 用 `rsync -n -c` 对比服务器叶子与目标（由目标那一端计算校验和，不下载） | 同一次对比：内容与服务器上已校验的文件一致即通过 |
| 服务器自己配置的位置（sftp）、Valise 管理的远程备份位置 | 列出后下载小文件比哈希 | 需要逐个下载 pack 计算哈希（见问卷） |
| 云盘（rclone，后做） | `rclone lsf` + 下载小文件 | `rclone check` 用云盘自己的哈希，不支持时下载 |
| 单快照取回缓存 | 不适用：永远不算完整周期副本 | — |

## 5. 证据存储与复用

- 客户端 `verification-state.json`（0600），按契约 5.2 字段记录 `CopyEvidence`：位置、叶子、check、结果、核对时间、基准摘要、核对规则版本、问题摘要（只有路径与问题类型，没有文件内容）。
- 已校验的 pack 按“位置 + 路径 + 大小 + 修改时间”记下；下次大小或修改时间没变就不重新下载计算（契约 5.3：pack 不可变，大小与修改时间只用于发现变化）。其他文件每次都重新比对。
- 旧 `repo-trial.json`、`restore-tests.json` 不迁移成新证据，各自继续原用途。

## 6. 用在哪里

- **删除周期**：删除前对所有其他位置当场重新核对（第 3 节），逐处显示“完整 / 不完整（缺什么）/ 未知（为什么）”与核对时间；只有至少一处“完整”才不加二次确认。删除权限分级不变：客户端的核对结果不变成 porter 的放行凭据。
- **备份位置页**：每处显示最近一次核对的两项结果与时间，提供“核对副本”。
- **复制后**：见问卷第 2 题。

## 7. 兼容

- 新 RPC `leaf_materials`、`target_verify` 由能力 `copy-verify/1` 声明；旧 porter 没有时，服务器与它配置的位置显示“这个 porter 版本不能核对，更新 porter 后再试”，删除时按“未知”处理（必须二次确认）。
- 金库格式不变，不写任何新文件到金库。

## 8. 验收

- fake-ssh：快照数相同但缺 pack、缺 index、缺 epoch/key、小文件内容不同、pack 损坏、存在 `DELETING`/`.partial.json`、位置读取失败、当前周期在核对后又追加、缓存复用后 pack 被替换（大小或修改时间变化）。
- 实机：`ubuntu-vm` 服务器金库、本机仓库、`nas`（rsync）与一个 Valise 管理的远程备份位置；人为删掉/改坏一个 pack 后核对与删除确认的显示。
