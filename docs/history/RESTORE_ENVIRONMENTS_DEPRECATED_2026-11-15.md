# 并行模式、直通模式与完整重建测试

状态：2026-11-12，产品决定已由三轮问卷确认；环境底座、私有候选材料构建及隔离 HTTP 试运行已实现，生产来源适配与正式服务执行仍待完成。默认开启保留旧环境的并行模式，未来 Wizard 默认勾选并建议开启；模式只在设置中决定。原 Agent 在隔离测试期间继续运行，受测环境隔离对外连接。正式切换后须由用户实际对话成功并点“确认可用”，小占用模式才开放清理旧环境的独立入口。槽位交替复用，禁止为恢复腾空间提前释放当前激活环境。非全量的全量底座只自动选择同一 Agent 且不晚于目标时间点的最近全量，否则按目标记录版本重建。本稿不代表已实现，也不据此执行安装、启动、停服或删除。

## 1. 本轮反馈与现状

- 桌面健康页只测试服务器上最新的备份；服务层虽接受 snapshot 参数，界面尚无时间点选择。
- 现有测试只有解密、文件核对、服务器暂存校验和清理，没有重建程序、启动隔离实例或验证网关。其结果只能说明文件与暂存通过。
- 当前恢复已经通过交换日志保留旧目录，并在失败时退回；它没有为所有程序建立可独立启动的私有旧版本。有些来源仍在共享安装位置更新，回退可能需要重装原版本，不能承诺立即切回完整旧环境。
- 当前“先备份当前状态”新增普通备份时间点，不能替代完整旧环境保护。用户提出的旅程分支冲突尚未按具体记录复现，不把问题仅归因于新增快照。

## 2. 已明确的产品目标

1. 用户可选择具体备份时间点，再选择文件校验或隔离重建测试；隔离重建检查到网关可打开。
2. 完整重建测试验证到隔离实例的网关可打开；结果清楚区分文件、程序重建、启动、网关与外部登录/连接。
3. 提供可选本地双环境保护，默认开启保留旧环境的并行模式。准备候选时当前环境继续运行；切换到新环境后，仍保留原环境供失败退回，网关就绪不等于用户已确认可用。
4. 本地保留不是普通备份时间点，不创建新 Agent 身份、分身或旅程分支。恢复保护记录挂在本次操作下。
5. 设置提供并行、小占用并行、直通三种模式，恢复沿用设置；不在恢复期间追加释放旧环境或选择云端保护的流程。
6. 小占用并行接受较高峰值空间；正式切换后必须由用户实际对话成功、点“确认可用”，随后才开放清理旧环境的独立入口。关闭并行只在设置里操作，可另行选择清理非活动槽位，转换为直通；恢复准备阶段不得先释放当前激活环境。
7. 在另一槽位恢复非全量备份时，先按官方来源重建底座，或以同一 Agent 的适用全量备份为数据底座，再恢复所选非全量范围。

## 3. 选择要测试的备份

- 健康页“测试备份…”先选择时间点，默认选最新，但允许选择更早记录。
- 旅程时间点详情提供测试该时间点的入口；绑定完整 SnapshotRef、位置与加密头摘要。
- 列表限于当前 Agent 的已确认旅程与副本位置，不为测试扫描无关服务器，不凭同名合并历史。
- 展示保存时间、内容范围、实际来源与已知缺口。冲突或缺失材料不能冒充可用备份。
- 材料不够完整或位置不支持读取时说明缺口，不静默换成另一时间点或另一来源。

## 4. 两种测试深度

### 文件校验

保留现有快速路径：解密、文件与暂存校验、清理。结果不代表运行环境已重建。

### 完整重建测试

在隔离环境中准备所选时间点，按登记来源重建对应程序和运行配置，启动隔离实例，再按 profile 的已核实规则检查网关。

隔离必须覆盖文件写入、进程、端口、管理入口和对外连接。仅换一个目录不算完整隔离；不能影响原 Agent、共享服务或其他实例，也不能同时使用未隔离的独占登录身份。

- 隔离方式和启动/网关检查须扩展通用 profile 能力，并逐 harness 核实，不能在 Go 中硬编码。
- 所需运行时与隔离工具先检测；安装仍遵守来源、管理登录与人类确认规则，不自动装依赖。
- 网关只通过本机回环转发给用户。端口监听、网关能响应、页面可打开、外部账号能用分别记录。
- 已确认：原 Agent 继续运行，受测环境在运行时隔离对外连接，只验证到网关可打开，不进行真实外部账号/消息连通测试。准备安装材料可按既有受信来源获取；不能借下载材料让已经加载 Agent 状态或登录信息的测试进程对外连接。
- 测试成功不自动把候选环境作为日常环境启用；是否用于随后正式恢复需另行复核与确认。
- 清理测试产生的隔离环境，不清理原 Agent、共享安装或备份库。中断后查询原操作，不重新启动测试。

完整重建支持尚未核实的 profile 不画可执行入口；现有文件校验仍可独立使用。不提供有头容器桌面或 VNC，也不将 porter 改成常驻服务。

## 5. 本地双环境保护

### 保护对象

需要覆盖该 Agent 的状态目录、可独立使用的程序版本、启动配置及必要的私有运行环境。共同依赖必须列明：不能将共享安装目录或一份会被升级的全局程序称为两套受保护环境。

独占身份仍属于同一个 Agent，两个环境不能同时完整对外运行。共享网关/其他实例的影响必须由 profile 和登记事实计算；无法隔离时明确不支持该切换能力，不以空间足够替代隔离验证。

### 切换目标流程（产品决定已确认）

以 A 激活、B 待准备为例：

1. 读取所选备份，计算所需空间与影响，将恢复内容准备到 B。A 继续日常运行，不在准备阶段封存 A。
2. 在隔离对外连接的 B 中完成重建、启动与网关检查；准备或检查失败直接停止 B，A 继续使用。
3. 准备通过并进入已确认的正式切换后，停止并核实 A，将 A 封存为非活动环境，再激活 B。封存不建立普通备份点，不生成分身或旅程分支。
4. 核实 B 在正式运行状态下的网关与健康。网关可打开后进入“等待确认可用”，B 保持激活，A 保留；网关就绪只说明可以试用，不将恢复或清理记为全部成功。切换入口、原/新活动状态和每步证据持久记录。
5. B 启动或网关检查失败时，先停止并核实 B，再激活 A、检查原网关，封存 B 并报告恢复失败及回退结果。对话可用性由用户亲自验证；用户报告无法对话时，可从原操作切回 A。若不能核实 B 已停止，不同时激活两套独占身份；无法完成回退时准确报告待处理状态。
6. 用户在原生界面实际对话成功后，点“确认可用”。Valise 不读取聊天内容，不代发测试消息，也不以网关响应或使用时长替代此确认。确认只完成验收，不授权删除；小占用并行随后才开放“清理旧环境”入口，用户另行执行。保留旧环境的并行模式继续保留 A。
7. 下一次恢复以当前激活槽位为基准交替：A 激活则目标 B，B 激活则目标 A。复用目标非活动槽位是准备下一次恢复的一部分，不要求先去设置手动清理，也不提前删除当前激活环境。首次计划确认需准确显示即将复用的非活动环境及其内容，不隐瞒覆盖后果。

测试和恢复共用与分身准备一致的运行环境构建能力，但恢复的 A/B 属于同一个 Agent，只有一个活动环境；不因此建立 clone_from 或新世代。独立分身仍按其自己的身份和人工启用规则执行。

目录与启动入口的具体实现另行设计，不直接复用旧版软链实现。沿用暂存与交换日志的可靠性要求；不把本稿当成已恢复旧版功能。

目标是减少用户手工救援；正式切换仍有停服、启动和健康检查所需的中断，不承诺所有程序和外部服务均能零停机回退。

## 6. 三种模式及设置边界

| 模式 | 恢复准备期间 | B 正式激活且网关通过后 | 空间与回退含义 |
| --- | --- | --- | --- |
| 并行：保留旧环境（用户称全量并行） | A 继续运行，独立准备 B | 保留非活动 A | 占用两套环境；支持之后切回，不等于新增全量备份 |
| 小占用并行 | 同样保留 A 并独立准备 B | 实际对话成功且用户确认可用后，才开放清理 A 的入口 | 同样需要较高峰值空间；减少清理后的长期占用，清理后不能再本地切回 A |
| 直通 | 沿用现行暂存、校验与目录交换方向，不维持另一套完整运行环境 | 不提供完整旧槽位保障 | 仍需必要的暂存空间；不宣称与双完整环境有相同的快速回退保证 |

- 现阶段按默认开启保留旧环境的并行模式设计。未来使用 Wizard 默认勾选、建议开启；Wizard 是后续界面工作，不画未实现入口。模式在 Agent 设置中选择，恢复页只显示当前模式、空间估算和实际影响，不临时询问要先删除什么、要先上传什么。
- 关闭并行时，在设置里允许用户另行选择彻底清理非活动槽位，变为直通。清理前核实活动槽位与共享依赖，不删除当前环境、其他 Agent 或备份库。
- 恢复流程不得为了腾空间而提前释放当前激活环境。并行模式空间不足就停止准备并说明所需空间，由用户在设置里调整策略；不自动降级或清理活动环境。明确非活动的另一槽位可以按交替恢复规则复用，但必须与未知/仍在运行的环境区分。
- 不再围绕“恢复前释放旧环境”设计云端保护点，也不把强制上传原状态作为恢复新增步骤。已有云备份继续提供其实际保存范围与时间点，不声称包含尚未保存的当前改动。
- 原“先备份当前状态”不能成为并行保护的替代入口；新恢复流程应以设置中的模式说明保护能力。手动备份保持独立，来源不明仍需明确确认，不能用模式替代来源核实。
- 再次恢复直接复用明确非活动的另一槽位，由正常的恢复计划确认覆盖此项影响；模式修改、非活动槽位清理与正在使用该槽位的恢复/测试不得相互破坏。正在执行的恢复沿用冻结的策略，不因设置变化临时改流程。
- 等待用户确认可用时，不能因退出客户端、超时或重新打开页面而清理旧环境。正式切换后的新内容留在 B；若之后切回 A，B 封存保留，不擅自把 B 的记忆或文件合并进 A。

### 已否决：恢复前释放旧环境

上一轮草稿曾提出“停服后先上传云仓，再释放旧环境，腾出空间恢复”。用户已明确否决；本选项不进入恢复计划、界面或执行器。此禁令保护的是当前激活环境，不妨碍下一次恢复复用已明确非活动的另一槽位。与之相关的“是否强制先上传原状态”问题已经撤回，不继续追问。

## 7. 非全量备份在新槽位中的重建

不能把非全量数据直接放入空目录后声称新环境已完整：

1. **官方来源底座**：按所选备份记录的官方来源、程序版本与已核实安装方案构建基础运行环境，再恢复所选档位。不能将“官方安装文件”理解为自动使用最新版本；来源/版本不可得就说明缺口，不悄悄升级。
2. **全量数据底座**：选择同一 Agent 的适用全量备份提供其他数据，再恢复所选非全量范围。全量数据备份不天然包含完整程序或系统依赖，仍按登记来源准备所需运行环境。
3. 所选非全量范围必须以该时间点为准，覆盖该范围时也处理已删除/不再存在的文件，不能只把文件复制上去而残留底座中的旧内容。范围外内容明确来自哪个底座，不混用 A 的活动状态。
4. 底座与目标的身份、profile、来源版本、目录布局须可核对；不凭同名拼接，也不把不兼容的全量静默当作有效底座。组合材料只记录在恢复计划与操作中，不生成虚构的全量快照或旅程分支。
5. 已确认默认底座只选择同一 Agent 且不晚于目标时间点的最近全量；没有适用全量时按目标记录的版本重建，不自动使用更新的全量。计划必须展示两个时间点及各自内容范围，不能把混合内容统称为“全部恢复到目标时刻”。

## 7a. 产品决定与技术设计边界

三轮产品问卷已回答：默认开启保留旧环境的并行；Wizard 后续接入且默认勾选、建议开启；隔离测试保留原运行；设置提供三种模式；切换后实际对话成功、人工确认可用，之后小占用才开放清理；A/B 按当前激活槽位交替复用；非全量底座不得晚于目标时间点；禁止为恢复腾空间而提前释放当前激活环境。

目前没有待回答的产品问卷。下一步技术设计须补齐：环境布局与稳定入口、profile 的私有运行时/隔离/网关探针声明、初次启用的接入路径、任务和交换日志的激活/待验收/回退/复用状态、部分备份的组合清单与空间预算、设置并发与清理授权。网关探针根据已核实 profile 定义，不把仅有端口监听当成网关可用。涉及未核实能力时不能宣布支持，也不以用户确认可用改写官方 profile 的 tested 状态。

正式规范记录已确认语义；技术实现另行评审与靶机验证。本稿不代表并行模式或隔离启动已经交付。

## 8. 验收重点

- 同一 Agent 可选择不同时间点测试；所选快照与来源不发生串换。
- 完整测试核实独立程序版本、文件、启动及网关，并证明原 Agent/其他实例没有被测试写入、连接或登录行为影响。
- 候选失败、断网、客户端退出、服务器重启、启动失败及网关不响应时，恢复原环境或明确报告未完成；不重发恢复操作。
- 本地保护开启时不靠联网重装才能找回被保护的私有程序；共享依赖明确限定保障范围。
- 三种模式准确计算峰值和成功后的占用；并行空间不足时不自动删除 A 或降级。小占用只在 B 正式激活、用户实际对话并确认可用后开放清理 A；确认可用与清理相互独立。关闭并行的清理发生在设置中，下一次恢复可按计划交替复用明确非活动槽位。
- 非全量目标与全量底座的范围明确，已删除文件不被底座复活，程序按记录来源和版本构建，不能把组合材料伪装成一个历史时间点。
- 所有保护物关联恢复操作，旅程身份/世代不意外分叉；备份库继续只追加、普通时间点不被改写或删除。

- A→B→A 的连续恢复覆盖非活动槽位复用、旧候选失败、等待对话确认时退出/重启和清理拒绝；始终保留当前激活环境，不把历史备用槽当成当前活动槽提前释放。
