## 已实现行为

1. Profile 新增可选 `service.repair_action`，引用同一 profile 的固定管理动作。lint 要求有服务候选，动作存在，风险为 `manage`，且不能是交互或机密输出动作。关联代表维护者已核实；Go 不依赖任何具体 harness 或 `restart` 动作名。
2. 健康服务项异常且存在有效关联时，展示实际动作名称。命名实例的有效 profile 没有声明共享服务时，不提供此入口。服务正常时不提供修复入口。
3. TUI 按 `f` 先重读动作清单，再进入既有管理动作确认页，沿用原有授权、执行和审计。取消确认不执行。资料版本不一致时引导到设置中的重新接入入口，完成后由用户重新发起；服务层也阻止版本不同的动作执行。
4. 动作完成后重新检查该服务项，分别显示命令退出码和问题复核结论：通过、仍在、无法复核。命令退出成功不等于服务恢复，忽略状态也不等于问题解决。
5. 结果页完成时刷新服务器状态及导航栈中匹配服务器、实例的 Health/Checkup。实例检查和服务器列表均用请求代号排除旧响应，返回概览或健康页可看到新结果。
6. CLI 健康输出提供可复制的既有 `valise action` 命令，动作结果独立打印复核结论。版本不一致时的动作清单提示与执行限制一致。
7. OpenClaw profile 从版本 19 更新至 20，关联此前已有且已核实的网关重启动作。本轮未对实际 agent 执行重启；使用更新后的资料需按版本检查重新接入。
