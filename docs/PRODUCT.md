# Valise 产品定义

> 本文件是功能取舍的最高依据。新功能提案必须先说明它在第 4 节的对照表中补上了哪个缺口。
> 2026-11-01 用户决定改版（`docs/REDESIGN_PROPOSAL.md`）：Valise 从"逃生舱"扩展为"自托管 Agent 的安装与管理入口，附带可靠的备份、恢复与迁移"。本文已按改版更新，冲突以本文为准。

## 1. 一句话

**Valise 是自托管 Agent 的安装与管理入口。**用户从一台能用 SSH 登录的服务器开始：Valise 部署自己的服务端，安装或接入 Harness，打开它的管理页，完成日常管理；同时由代码在后台提供可靠的备份（逃生舱）、恢复、迁移与克隆。

首次使用的目标结果：**用户连上服务器，安装一个 Harness 或把已有的 agent 接入 Valise，并在浏览器里看到它的管理页。**模型凭据不是这一步的必经环节。

## 2. 背景

2026 年下半年，OpenClaw、Hermes、DeepSeek Harness 等常驻型 agent 被大量部署在 VPS 和家用服务器上，其中很多用户并不具备专业运维能力。

**"大肥鱼事件"**："大肥鱼"是社区对 DeepSeek 的昵称。DeepSeek V4.1-Flash-1017 发布后，效能大幅提升，开销明显降低，大量新用户随之把 agent 接入社交平台。社交平台的信息噪声极大，而这些用户普遍不了解 agent 的会话和记忆管理，于是出现了几种典型结局：

- 一个会话无限延长，agent 越来越笨；
- 开销呈指数级增长；
- 想切换会话时，只能依靠手写的"转生 Prompt"，旧的上下文随之丢失。

新手卡在更早的地方：不会配 SSH、不会用终端、不知道管理页怎么在服务器外打开。进阶用户则面临另一类痛点：harness 升级失败；agent 自我修改把自己改坏；换服务器时漏带文件；凭据随着明文备份四处散落；在无头服务器上完成 OAuth 登录时，不得不临时搭建有头浏览器和 VNC。

## 3. 目标用户

- **主要用户**：有服务器地址和登录凭据、想在上面跑常驻 agent 的个人，包括不会配置 SSH、不熟悉终端的新手。默认体验面向他们：Valise 接手重复的服务器操作，不要求用户先学运维。
- **次要用户**：同时维护多种 harness、多台服务器的进阶用户。CLI、SSH 配置导入与高级功能为他们保留。

**支持范围如实分级**：第一阶段只把 OpenClaw 从空服务器到日常管理的体验打磨透彻；方法成熟后再引入其他主流 harness；最后才是陌生 harness 的通用接入。一份 profile 不等于"全面支持"，支持程度按能力逐项展示（PROFILES.md 第 1 节）。

## 4. 与替代方案的对照（每个功能都要通过这张表的检验）

| 替代方案 | 它做不到的 | Valise 的回答 |
| :--- | :--- | :--- |
| 照着官方文档在终端里装 | 新手要先学 SSH、终端、端口转发；装完不知道管理页怎么打开 | 手动填地址即可连接；官方方案逐步引导或交给原生安装界面；装完自动发现实例、打开管理页 |
| 面板类工具（通用服务器面板） | 不懂 agent 的灵魂、凭据与会话；备份是整目录明文 | 按 profile 理解 harness；凭据分层加密；体检懂会话与记忆 |
| 服务器整机快照 | 绑定云厂商和机器；粒度是整台机器；不懂 agent；不能跨架构 | 只封存 agent 本身，可以在任何服务器、任何架构上复活；单独回滚 agent 不影响同机的其他服务 |
| Harness 自带的备份 | 各家的格式和覆盖范围不同；多为明文，凭据混在其中；不负责重建身体；没有去重和版本历史 | 统一的分层封存；凭据独立加密；按来源记录重建身体；内容寻址去重 |
| restic / rsync + cron | 不懂哪些是灵魂、哪些可以重建、哪些是凭据；不处理 SQLite 一致性；恢复全靠人工 | Profile 驱动的分类与一致性处理；由代码完成复活、健康检查和自动回退 |
| 手写转生 Prompt | 旧会话丢失；新会话不一定会加载这段 Prompt | 先封存旧会话，再把交接内容写进 harness 原生会加载的记忆文件 |
| VNC + 有头浏览器登录 | 对新手过于复杂 | 同端口回环转发，在本机浏览器里打开服务器上的页面、完成授权 |

## 5. 核心承诺

1. **新手可用**：不要求用户懂 SSH 配置与终端；每个会改变服务器的操作都说清后果，并允许展开查看实际命令。
2. **普适且诚实**：新增一种 harness 只需要一份 profile，不改代码；支持到什么程度按能力逐项如实展示。
3. **可靠**：封存与复活全程由代码执行；复活失败时自动回退，活动状态永远不会被写坏一半。
4. **私密**：服务器只持有加密公钥；凭据单独分层；金库可以放在任何不可信的存储上；日常通道拿不到服务器的完整权限（ARCHITECTURE.md 第 2.1 节）。
5. **可脱离**：金库格式公开，使用标准 age 加密。即使 Valise 消失，用户仍能恢复数据。
6. **克制**：只在用户明确发起并确认后才安装东西；不擅自修改 agent 的记忆；不代管模型凭据；不为任何第三方软件背书。

## 6. 功能分区

- **接入与安装**：连接服务器（手动填写或导入 SSH 配置）、一键部署与更新 Valise 服务端、发现已有的 agent 并接入 Valise、按官方方案安装 harness 或进入原生安装界面（INSTALL.md）。
- **日常管理**：运行状态、打开管理页（含令牌处理）、打开服务器上的本地页面、登录授权、原生界面入口、体检、profile 登记的管理动作。
- **保障**（平时安静运行，出问题才醒目提示）：登记、建立逃生舱、金库、空间站（异地备份）、逃生舱着陆（回滚、迁移、克隆）、取回本地。
- **健康区**（可选，由逃生舱技能提供）：会话与记忆体检；交接；风险操作前自动封存。
- **伴生区**（可选，放在独立仓库，后期再做）：长期记忆、短期记忆、冷存档 + 索引、程序性记忆等小插件。Valise 只在体检结果中给出选择标准，不强制安装，也不点名背书第三方方案。体检的"处理建议"中可以引用 Valise 自己的记忆整理技能（`valise-memory`，规划中，尚未开发）。
- **后续规划**（不渲染为可用功能）：管理方技能（AGENT_KIT.md 第 9 节）、用户自建 profile 的表单与技能、第三方工具的登记与安装（INSTALL.md 第 6、7 节）、沙盒插件、服务器健康。

## 7. 非目标

- 不做 harness 的记忆引擎，也不规定 agent 必须使用某种记忆格式。
- 不做插件市场，不托管 agent，不做云服务。
- 不做整机备份，不备份 harness 之外的系统数据；安装第三方工具前的"备份 agent"不等于能撤销工具对系统的修改。
- 不提供 API Key 输入辅助，不代用户提交、保存或管理模型凭据。
- 不做第三方软件的安全审计或认证；安装前的疑点提示不等于"安全"。
- 恢复路径上不使用 LLM。

## 8. 术语表

| 术语 | 含义 |
| :--- | :--- |
| 实例 | 一个被 Valise 登记的 agent，由服务器、harness 类型和状态目录共同确定 |
| Harness | agent 的运行框架，例如 OpenClaw、Hermes、DSH |
| Profile | 描述某种 harness 的发现、目录结构、来源、安装、服务、管理页、登录、体检与管理动作的数据文件；官方 profile 经过审核并按能力逐项核实 |
| 身体 | harness 的代码与运行时，可以重建，不进入封存 |
| 灵魂 | 人格、记忆、技能、配置、会话、状态库 |
| 凭据 | API Key、令牌、授权文件，由 profile 显式声明 |
| 工作区 | agent 产出的文件与资产 |
| 封存 | 对实例做一次加密快照 |
| 封存档位 | `soul`（灵魂）、`soul-secrets`（灵魂 + 凭据 + 未分类文件）、`full`（再加工作区）、`raw`（全量：实例目录下的全部文件，含身体与缓存，按凭据层对待） |
| 金库 | 内容寻址、只追加的加密存储。服务器与异地都按"实例 / 周期"分档，每个周期是一个独立的金库（VAULT_FORMAT.md 第 10 节） |
| 周期 | 金库分档的时间段，默认自然月，可按实例设为每周或每季度 |
| 复活 | 由封存恢复实例，分为回滚、迁移、克隆三种模式 |
| 来源记录 | 登记时由代码读出的身体安装来源与版本，复活时据此重建身体 |
| 搬运工 | 服务器端的 `valise-porter`，由 SSH 按需唤起 |
| 日常钥匙 | Valise 为每台服务器生成的 SSH 密钥，在服务器端被限制为只能调用 porter 的日常操作（ARCHITECTURE.md 第 2.1 节） |
| 管理登录 / 管理钥匙 / 管理口令 | 执行管理操作时出示的凭据：可选的管理钥匙（默认不创建，由管理口令加密，解锁后有时间窗口），或每次用服务器密码临时登录 |
| Valise 口令 | 只保护加密钥匙；与管理口令是两个不同的口令。Valise 不另设登录密码 |
| 官方方案 | profile 中声明的、锁定来源与哈希的安装步骤（INSTALL.md） |
| 原生界面 | harness 自带的交互式 CLI，经管理登录的独立 SSH 连接交给用户直接操作 |
| 登录中继 | 让无头服务器上的登录授权在本机浏览器中完成的功能 |
| 入口 | 实例对外提供的 Web 管理页面 |
| 交接 | 在切换会话之前，先封存旧会话，再由 agent 把交接内容写进原生记忆 |
| 会话与记忆检查 | `checkup` 的只读检查；由代码计算指标，由 agent 用自然语言解读。界面统一入口为“健康”，还汇总备份、恢复测试、服务等状态 |

### 8.1 界面用语（用户于 2026-10-31 决定，2026-11-01 补充）

TUI、GUI 以及 CLI 的人类可读输出一律使用左列的说法；右列的内部术语只出现在代码、协议、金库格式和开发文档中。CLI 的命令名与参数不变。品牌用语（逃生舱、着陆、空间站）出现在关键操作上时，同时用一句话说明实际含义（备份、回滚、迁移、克隆、异地备份）。

| 界面用语 | 内部术语 | 说明 |
| :--- | :--- | :--- |
| 逃生舱 | 快照（snapshot） | 每一份就是一个逃生舱（备份）。列表中按"时间 · 谁建立的 · 原因 · 装了什么 · 大小 · 副本在哪里"展示，不直接展示 id；id 只在详情的技术信息中出现 |
| 建立逃生舱 | 封存（seal） | |
| 教学逃生舱 | 带教学标记的快照 | 首次备份教程中建立的逃生舱，只证明当时的流程与内容（ARCHITECTURE.md 第 6 节） |
| 逃生舱着陆 | 复活（revive） | |
| 原地着陆 | 回滚（rollback） | 让这个 agent 回到逃生舱建立的时刻 |
| 着陆到另一台服务器 | 迁移（migrate） | |
| 着陆成一个新的 agent | 克隆（clone） | |
| 轻装 / 标准 / 完整 / 原样 | `soul` / `soul-secrets` / `full` / `raw` | 逃生舱里装了什么。轻装：记忆、人格、技能、配置、会话；标准：再加登录凭据与未分类文件；完整：再加工作区；原样：实例目录下的全部文件 |
| 管理页 | 入口（entry） | "打开管理页"；端口与隧道只在技术信息中出现 |
| 打开服务器上的本地页面 | 通用回环转发 | 粘贴服务器上的回环地址或填写端口（LOGIN_RELAY.md 第 6 节） |

| 登录授权 | 登录中继 | 界面先用一两句话说明它解决的问题："服务器没有浏览器，Valise 把登录页面转到你这台电脑上完成" |
| 空间站（异地备份） | 异地同步（sync）与同步目标（target） | 原称"云备份"。包括网盘、NAS 等任何异地存储 |

| 着陆前的旧状态 | prev 目录 | 出现在"空间清理"中 |
| 已被取代的旧实例 | superseded 实例 | 出现在"空间清理"中 |
| 接入 Valise / 已接入的 agent / 重新接入 | 登记（enroll）、实例记录 / 重新登记 | 2026-11-01 用户决定。把服务器上已装好的 agent 交给 Valise 管理：读出版本与来源、按 profile 给文件分类、写下实例记录。接入只读取和记录，不改动 agent 的任何文件，也不往 harness 里安装任何东西；确认框写明这一点。不说"纳入""接管""模块" |
| 安装 harness | 官方方案安装 | 从零安装一个新的 agent（INSTALL.md） |
| 归档建议 | 归类提议（proposal） | agent 认为某些文件也应该装进逃生舱（或换一类），放在体检页中 |
| 加密钥匙 | age 身份与收件人 | 界面只讲"口令保护的钥匙、放在哪里、备份一份、在新电脑上导入"；收件人管理放在"高级" |
| 解锁管理权限 | 把管理钥匙载入 ssh-agent，或临时登录 | 有管理钥匙："输入管理口令以继续（15 分钟内不再询问）"；没有："这一步需要服务器密码" |
| 逃生舱技能 | agent-kit（受管方技能） | |
| harness 资料包 | profile 包 | 单独下载的签名包，包含官方 profile（PROFILES.md 1.1） |
