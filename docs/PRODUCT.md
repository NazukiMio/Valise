# Valise 产品定义

> 本文件是功能取舍的最高依据。新功能提案必须先说明它在第 4 节的对照表中补上了哪个缺口。
> 2026-11-05 用户确认产品重整方向、GUI / TUI 草图及后端实施计划，并授权同步正式规范和开发排期。本文规定目标行为；当前实现与未完成项以 [DEV_PLAN.md](DEV_PLAN.md) 为准。原讨论稿 [history/NEW_INSTRUCTURE.md](history/NEW_INSTRUCTURE.md) 保留决策背景，正式规范优先。

## 1. 一句话

**Valise 帮助缺少计算机系统管理经验的用户，在自己的服务器上搭好并照看 harness / agent，需要换环境时，带着熟悉的记忆、习惯与资料继续。**

品牌表达：**带着你的 Agent 去旅行。**关键操作使用连接、安装、备份、恢复和迁移等直接名称。保护数据与运行连续性不等于保证模型升级后行为完全相同，也不承诺跨任意 harness 无损转换记忆。

首次入口保留 **从零开始** 和 **接入已有**：前者按已核实方案安装，后者发现并确认已有安装事实，不重装、不修改记忆、不隐式安装技能。共同结果是找到 Agent、打开已支持的原生入口，并知道尚待完成的设置。模型与渠道设置由用户在 harness 原生流程完成；安装退出、管理页可达、能否运行与备份是否可靠分别判断。

## 2. 背景

2026 年下半年，OpenClaw、Hermes、DeepSeek Harness 等常驻型 agent 被大量部署在 VPS 和家用服务器上，其中很多用户并不具备专业运维能力。

**"大肥鱼事件"**："大肥鱼"是社区对 DeepSeek 的昵称。DeepSeek V4.1-Flash-1017 发布后，效能大幅提升，开销明显降低，大量新用户随之把 agent 接入社交平台。社交平台的信息噪声极大，而这些用户普遍不了解 agent 的会话和记忆管理，于是出现了几种典型结局：

- 一个会话无限延长，agent 越来越笨；
- 开销呈指数级增长；
- 想切换会话时，只能依靠手写的"转生 Prompt"，旧的上下文随之丢失。

新手卡在更早的地方：不会配 SSH、不会用终端、不知道管理页怎么在服务器外打开。进阶用户则面临另一类痛点：harness 升级失败；agent 自我修改把自己改坏；换服务器时漏带文件；凭据随着明文备份四处散落；在无头服务器上完成 OAuth 登录时，不得不临时搭建有头浏览器和 VNC。

## 3. 目标用户

- **主要用户**：有服务器地址和登录凭据、想在上面跑常驻 agent 的个人，包括不会配置 SSH、不熟悉终端的新手。默认体验面向他们：Valise 接手重复的服务器操作，不要求用户先学运维。
- **次要用户**：同时维护多种 harness、多台服务器的进阶用户；以及希望委托另一个 AI 协助管理的用户。SSH 配置导入、高级功能和结构化自动化入口为他们保留。

### 3.1 交付形态

| 入口 | 职责 |
| :--- | :--- |
| GUI | 最终用户交付形态；基础连接、安装或接入、日常使用、备份和恢复流程不要求另开 CLI |
| TUI | 服务资源紧凑或桌面不可用的环境，以菜单、卡片、表单和按需展开降低操作负担 |
| 管理方 MCP | 用户委托的 AI 通过客户端查询、准备计划、发起允许且已授权的任务，读取真实进度与结果；待实现 |
| CLI | 自动化、诊断及高级用户入口，提供结构化输入输出并保留兼容性；不以人工命令数量衡量产品完成度 |

四种入口共用 Go 服务层。GUI / TUI 不通过解析 CLI 人类输出执行业务，管理方 MCP 不模拟终端；原生交互程序采用独立的终端适配。管理方与受管方 AI 权限隔离，详见 AGENT_KIT.md 第 9 节。

**支持范围如实分级**：第一阶段只把 OpenClaw 从空服务器到日常管理的体验打磨透彻；方法成熟后再引入其他主流 harness；最后才是陌生 harness 的通用接入。一份 profile 不等于"全面支持"，支持程度按能力逐项展示（PROFILES.md 第 1 节）。

## 4. 与替代方案的对照（每个功能都要通过这张表的检验）

| 替代方案 | 它做不到的 | Valise 的回答 |
| :--- | :--- | :--- |
| 照着官方文档在终端里装 | 新手要先学 SSH、终端、端口转发；装完不知道管理页怎么打开 | 手动填地址即可连接；官方方案逐步引导或交给原生安装界面；装完自动发现实例、打开管理页 |
| 面板类工具（通用服务器面板） | 不理解 agent 数据、凭据与会话；普通用户难以判断保护范围 | 按 profile 与本机档案识别安装；充分默认备份；分别显示运行、覆盖、副本与恢复验证 |
| 服务器整机快照 | 绑定云厂商和机器；粒度是整台机器；不理解 agent | 在已核实的版本、架构与来源条件下恢复或迁移 Agent；共享服务影响列入计划，不承诺任意环境可运行 |
| Harness 自带的备份 | 各家的格式和覆盖范围不同；多为明文，凭据混在其中；不负责重建身体；没有去重和版本历史 | 统一的分层封存；凭据独立加密；按来源记录重建身体；内容寻址去重 |
| restic / rsync + cron | 不懂哪些是灵魂、哪些可以重建、哪些是凭据；不处理 SQLite 一致性；恢复全靠人工 | Profile 驱动的分类与一致性处理；由代码完成复活、健康检查和自动回退 |
| 手写转生 Prompt | 旧会话丢失；新会话不一定会加载这段 Prompt | 先封存旧会话，再把交接内容写进 harness 原生会加载的记忆文件 |
| VNC + 有头浏览器登录 | 对新手过于复杂 | 同端口回环转发，在本机浏览器里打开服务器上的页面、完成授权 |

## 5. 核心承诺

1. **新手可用**：不要求用户懂 SSH 配置与终端；每个会改变服务器的操作都说清后果，并允许展开查看实际命令。
2. **普适且诚实**：新增一种 harness 只需要一份 profile，不改代码；支持到什么程度按能力逐项如实展示。
3. **可靠**：备份、校验、恢复与回退由确定性代码执行，写入暂存后才进行带日志的目录交换；支持的失败场景按日志退回。多目录交换、程序重建与服务恢复分别报告，不承诺所有外部步骤原子完成。
4. **私密**：服务器只持有加密公钥；凭据单独分层；备份库可以放在任何不可信的存储上；日常通道拿不到服务器的完整权限（ARCHITECTURE.md 第 2.1 节）。
5. **可脱离**：备份库格式公开，使用标准 age 加密。即使 Valise 消失，用户仍能恢复数据。
6. **克制**：只在用户明确发起并确认后才安装东西；不擅自修改 agent 的记忆；不代管模型凭据；不为任何第三方软件背书。

### 5.1 诊断与修复（2026-11-04 用户修订）

Valise 面向普通用户。发现已知问题后，有经过核实且范围明确的处理方法时，提供一键修复或引导修复，帮助用户完成处理，而不止给出告警与命令。用户明确发起后，按操作风险复用已有授权、确认、备份和撤销流程，执行后复核实际结果；不擅自修改、不把忽略当修复、不把退出码当健康保证。无法可靠自动处理时，解释原因并给出可执行的下一步。具体规范见 UI.md 9.5、PROFILES.md 的审批状态检查与 INSTALL.md 第 5 节。

## 6. 功能分区

- **接入与安装**：连接服务器（手动填写或导入 SSH 配置）、一键部署与更新 Valise 服务端、发现已有的 agent 并接入 Valise、按官方方案安装 harness 或进入原生安装界面（INSTALL.md）。
- **日常管理**：运行状态、打开管理页（含令牌处理）、打开服务器上的本地页面、登录授权、原生界面入口、体检、profile 登记的管理动作。
- **保护与旅程**：一份用户确认的保护计划、默认备份、定时保存、备份位置、按时间点浏览、恢复当前实例、迁移、创建副本和导出。已有旧档位仍可显式使用。
- **健康（含 Security Hub）**：综合运行、覆盖、副本、恢复验证、已知安全设置与会话记忆指标；已完成检查、未知和失败分别表达。会话解读与交接可由可选受管方技能辅助，综合健康不依赖安装技能。
- **伴生区**（可选，放在独立仓库，后期再做）：长期记忆、短期记忆、冷存档 + 索引、程序性记忆等小插件。Valise 只在体检结果中给出选择标准，不强制安装，也不点名背书第三方方案。体检的"处理建议"中可以引用 Valise 自己的记忆整理技能（`valise-memory`，规划中，尚未开发）。
- **工具箱与后续扩展**：按用途呈现现有技能与工具；管理方接口、用户自建 profile、第三方工具登记和安装、记忆管理等按 DEV_PLAN.md 逐项交付。规划不渲染为可用按钮，不引入插件市场或自定义解释器。

### 6.1 信息架构

日常起点是 **我的 Agent**，其余一级入口为服务器、备份位置、工具箱、设置。每个 Agent 提供概览、旅程、健康、管理与设置。服务器 / 安装 / Agent 的关系仍保留；共享安装的动作列出所有受影响实例。显示名不能用作跨服务器身份或合并历史的依据。

### 6.2 一份保护计划，一条旅程

- 新保护计划默认使用 `full`：登记 roots 内的人格、记忆、技能、配置、会话、状态、凭据、工作区及未分类文件；程序实体、已声明缓存和忽略项按原分类处理。不等于整机或目录外程序的备份。
- 日常一次保存产生一个时间点，不要求为轻装、含凭据、完整分别设置多套定时任务。修改动作前所需的额外备份继续保留，不合并或删除同日时间点。
- 推荐每天自动备份，由用户确认时间、时区、覆盖、可能停服和复制位置后启用。去重降低新增存储，不代表读取与一致性处理没有成本。原设置不静默扩大；旧快照、旧 CLI 参数按原含义解释。
- profile 提供通用规则，服务器档案确认实际布局。未知项已包含时汇总告知，不要求逐文件归类；不可读内容、外部引用和真正遗漏的目录才提升提醒。自定义是特殊需求的兜底，范围与分类分开，具体语义先定稿再实现。
- 旅程的恢复点必须对应成功保存的快照，显示当时实际范围。失败任务可见但不成为恢复点；缺失时段不画成连续保护，不分析对话来生成成长故事。
- 安装事实与保护设置不保存全部历史。时间轴索引可重建，丢失原服务器或客户端索引后，仍能从完整备份库副本浏览保存时间点并取回数据；原因或迁移关联缺失如实展示。
- 周期继续作为归档与整组显式删除边界；不自动清理、不删除单个快照。

### 6.3 找回过去与更换服务器

先选择时间点，再选择当前实例、另一台服务器或导出。恢复来源与原服务器分开：可从服务器、本机仓库或已支持的其他完整副本准备材料；恢复一个时间点所需的部分缓存不冒充完整周期副本。

分别说明数据是否齐全、目标环境是否满足条件、执行会影响谁。不能重建运行环境时仍可导出数据，不把文件取回称为已恢复运行。原服务器不可达不等于原实例已停止；独占身份无法核实隔离时，首版只提供排除已声明独占凭据后的恢复，或导出/暂存等待处理，不凭用户声明已关机就带独占身份完整启动。

身份与历史采用 2026-11-05 已确认的 N1 契约：新实例有独立世代，成功迁移通过明确关系接续旅程，创建副本拥有独立旅程。身份与迁移关系保存在备份库外；关系丢失后仍可找回保存点，但未知关联不能按同名补全。不向现有公开快照加入必须携带的永久 AgentID，不改写旧字段。

### 6.4 结果与自动化

所有入口共用计划、权限、任务状态与结果。备份保存、复制、完整性校验、解密校验、暂存测试与实际启动验证分别表达；读取失败保留最后成功时间并标明过期，不凭副本数量或元数据存在保证可恢复。

管理方 AI 不能取得口令或钥匙、替用户确认或开启高级模式。跨进程请求采用已确认 N1 契约：MCP 只提交允许的类型化请求并读取脱敏结果，用户打开 GUI/TUI 后重新核对计划、确认，由该人类进程执行；没有人类会话就等待，不跨进程传递解锁身份或通用确认票据。具体工具清单与适配按 N5a.2 交付，当前不开放恢复/删除执行接口。

## 7. 非目标

- 不做 harness 的记忆引擎，也不规定 agent 必须使用某种记忆格式。
- 不做插件市场，不托管 agent，不做云服务。
- 不做整机备份，不备份 harness 之外的系统数据；安装第三方工具前的"备份 agent"不等于能撤销工具对系统的修改。
- 不提供 API Key 输入辅助，不代用户提交、保存或管理模型凭据。
- 不做第三方软件的安全审计或认证；安装前的疑点提示不等于"安全"。
- 恢复路径上不使用 LLM。

## 8. 术语表

| 术语 | 含义 |
| :--- | :--- |
| 实例 | 一个被 Valise 登记的 agent，由服务器、harness 类型和状态目录共同确定 |
| Harness | agent 的运行框架，例如 OpenClaw、Hermes、DSH |
| Profile | 描述某种 harness 的发现、目录结构、来源、安装、服务、管理页、登录、体检与管理动作的数据文件；官方 profile 经过审核并按能力逐项核实 |
| 身体 | harness 的代码与运行时，可以重建，不进入封存 |
| 灵魂 | 人格、记忆、技能、配置、会话、状态库 |
| 凭据 | API Key、令牌、授权文件，由 profile 显式声明 |
| 工作区 | agent 产出的文件与资产 |
| 封存 | 对实例做一次加密快照 |
| 封存档位 | 兼容的范围预设：`soul`（灵魂）、`soul-secrets`（灵魂 + 凭据 + 未分类文件）、`full`（再加工作区）、`raw`（roots 下全部文件，含身体与缓存，按凭据层对待）。新保护计划默认 `full`，旧快照不重新解释 |
| 保护计划 | 用户确认的默认范围、自动备份安排与复制位置等设置；服务器与客户端各保存其执行所需的权威部分，版本和存储契约见已定稿 SERVICE_CONTRACTS.md 第 4 节，待 N2 实现 |
| 旅程 | 备份与恢复记录的用户视图；以成功保存的时间点为主体，不依赖 LLM |
| 备份位置 | 服务器备份库、本机文件夹、外部磁盘或已支持的远端存储；更新条件与验证状态分别展示 |
| 备份库 | （2026-11-09 起取代旧称“金库”；格式文档名 VAULT_FORMAT.md、代码标识与磁盘目录 `valise-vault` 不变）内容寻址、只追加的加密存储。服务器与异地都按"实例 / 周期"分档，每个周期是一个独立的备份库（VAULT_FORMAT.md 第 10 节） |
| 周期 | 备份库分档的时间段，默认自然月，可按实例设为每周或每季度 |
| 复活 | 由封存恢复实例，分为回滚、迁移、克隆三种模式 |
| 来源记录 | 登记时由代码读出的身体安装来源与版本，复活时据此重建身体 |
| 搬运工 | 服务器端的 `valise-porter`，由 SSH 按需唤起 |
| 日常钥匙 | Valise 为每台服务器生成的 SSH 密钥，在服务器端被限制为只能调用 porter 的日常操作（ARCHITECTURE.md 第 2.1 节） |
| 管理登录 / 管理钥匙 / 管理口令 | 执行管理操作时出示的凭据：可选的管理钥匙（默认不创建，由管理口令加密，解锁后有时间窗口），或每次用服务器密码临时登录 |
| Valise 口令 | 只保护加密钥匙；与管理口令是两个不同的口令。Valise 不另设登录密码 |
| 找回 Valise 口令 | 忘了口令时，凭“这台电脑 + 服务器上 sudo 运行一条命令得到的验证码”设新口令，以前的备份照常能打开；靠事先留的备用锁，默认开启、可关闭（ARCHITECTURE.md 3.2）。不叫“重置” |
| 删除服务器 | 两层：只从这台电脑移除；移除并清理服务器上的 Valise 东西（逐项勾选）。备份库保留并标为“已删除的服务器”（ARCHITECTURE.md 2.3） |
| 官方方案 | profile 中声明的、锁定来源与哈希的安装步骤（INSTALL.md） |
| 原生界面 | harness 自带的交互式 CLI，经管理登录的独立 SSH 连接交给用户直接操作 |
| 登录中继 | 让无头服务器上的登录授权在本机浏览器中完成的功能 |
| 入口 | 实例对外提供的 Web 管理页面 |
| 交接 | 在切换会话之前，先封存旧会话，再由 agent 把交接内容写进原生记忆 |
| 会话与记忆检查 | `checkup` 的只读检查；由代码计算指标，由 agent 用自然语言解读。界面统一入口为“健康”，还汇总备份、恢复测试、服务等状态 |

### 8.1 界面用语（2026-11-05 重整）

TUI、GUI 以及 CLI 的人类可读输出使用左列说法。旅行意象用于品牌与旅程，不替代关键操作名称；不再把逃生舱、着陆、空间站作为主界面导航或按钮用语。CLI 命令名、参数、RPC、技能 ID 与磁盘格式保持兼容；`docs/history/` 中的历史文档保留原文。正式规范的叙述也改用左列说法（2026-11-07 用户决定），逐处改写、不做机械替换；代码标识（命令、参数、RPC、字段、文件名）保持原样并用代码格式书写。统一完成之前，规范中残留的旧词按本表理解。
