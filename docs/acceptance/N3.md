# N3 实现与验收记录

依据 DEV_PLAN.md N3 与 ARCHITECTURE.md 7.1.1、7.3。按用户定的顺序：严格副本 → 云盘 → 本机仓库自动同步收入共享服务 → 源服务器失联恢复。

## 1. 严格副本（2026-11-07）

### 1.1 实现映射

| 位置 | 内容 |
| --- | --- |
| `core/vault/materials.go` | `Material`（路径、大小、SHA-256、修改时间文本）；`ListMaterials`（可不读数据包内容）；`CompareMaterials`（缺少、多出、不同、未给哈希的小文件；数据包的哈希对照它的名字）；`IntegrityCheck`（第 7 节免钥匙校验作用于清单，适用于不在本地磁盘上的副本） |

| porter `leaf_materials`、`target_verify`（能力 `copy-verify/1`，日常钥匙） | 服务器叶子的材料清单（基准）与可选的免钥匙校验；服务器配置的位置：rsync 用校验和对比，其他方式下载核对；Valise 管理的远程备份位置交给客户端 |

| `client/ui/service/verification_state.go` | `verification-state.json`（0600）：已核对的数据包与每处每周期两项检查的最近结果（契约 5.2 字段），只有路径与问题类型 |

### 1.2 自动化证据

- `core/vault`：快照数相同但缺数据包、缺去重参数、元数据内容不同、多出文件；数据包未核对时 index 范围仍检查。
- `core/stationsync`：数据包只在要求时下载；已核对的按大小与修改时间复用。
- porter `seal`：sftp 下载核对（含复用与缺包、改元数据）；rsync 校验和对比（同大小被改坏的数据包被找出）。rsync 用例需要 GNU rsync，在 `ubuntu-vm-x86` 上以交叉编译的测试程序运行通过。原有 sftp 测试替身在 `/bin` 即 `/usr/bin` 的系统上会找到 rsync，已改为 PATH 只含替身目录。
- 客户端 service（fake-ssh + 真实 porter 构建）：服务器与本机仓库都完整；删掉一个数据包后仓库为不完整、指出缺的文件、不再算其他完整副本；证据记录；跳过的位置为未核对；单快照取回标记一律不算完整周期；复制后核对结果为“清单一致”。
- 全仓 `testbed/selfcheck.sh` 通过（SELFCHECK_PASS）。

### 1.3 实机（`ubuntu-vm`，porter 以 `porter deploy --local` 部署当前构建）

- `dsh/2026-10-01_2026-10-31`（12 个备份）：不带 `--packs` 时三处（服务器、`nas`、本机仓库 `local`）为“清单一致，内容未核对”，`nas` 提示核对要下载 3.8 KiB；带 `--packs` 后三处都“完整”。`ubuntu-vm` 没有 rsync，`nas` 经 sftp 下载核对。
- `openclaw/2026-10-01_2026-10-31`（29 个备份，264 MiB）：首次带 `--packs` 用时约 77 秒（`nas` 下载 264.2 MiB）；再次核对只下载 1.5 MiB 小文件，用时约 24 秒，三处完整。
- 把本机仓库里的一个数据包临时移走：仓库显示“不完整：缺 1 个文件（列出路径）”及 index 引用问题；放回后恢复为清单一致。
- `vault delete … --skip local`：当场核对后服务器与 `nas` 完整、`local` 为“未核对（已跳过），不算完整副本”，`nas` 复用已核对的数据包未再下载；回答 N，周期未删除。

### 1.3a 服务器复制后由 porter 核对（2026-11-08，用户决定）

- porter 的 `syncLocked`（客户端请求的同步、自动同步、保护计划的复制共用）复制后对清单有变化的周期做清单核对，结果写进 `sync/<位置>.json` 的 `checks`，随 `vault_status` 返回；客户端 `sync` 结果与 `vault status` 显示。
- 测试：sftp 替身上复制后通过；无新内容时不重新读取；位置上的元数据被改后，下一次周期有新内容时核对不通过并指出路径。
- 实机 `ubuntu-vm` → `nas`（sftp）：第一次 `sync` 补传后核对 9 个周期，全部一致（同步加核对共 2 分 13 秒）；随即再同步一次，31 秒、没有重新核对；`vault status` 显示“服务器复制后核对：9 个周期的文件清单一致”。保护计划与自动同步走同一路径，未单独实机触发。
- 限制：清单没变的周期不会重新读取，复制之后位置上被改坏的内容要到下次“核对副本”或删除前才发现。

## 2. 云盘（2026-11-08，实现完成，真实网盘验收待用户授权）

### 2.1 实现映射

| 位置 | 内容 |
| --- | --- |
| `kit/tools.yaml` | rclone 条目加 `client_archives`（macOS 与 Linux，SHA-256 取自 1.75.2 的 SHA256SUMS）与 `clouds`（gdrive、onedrive、dropbox，均 `verify: pending`）；gdrive 固定 `scope: drive.file`、`ask_app: true` |

| porter | `targets.json` 接受 `kind: rclone`（`valise-<名>:<相对目录>`）；使用 `~/.local/bin/rclone` 与 `~/.config/valise/rclone/rclone.conf`；`cloud_login_prepare`（主人）只按签名清单的条目生成固定命令并准备登录中继会话；`cloud_forget`（主人）删除登录，可连同云盘位置一起移除（受保护计划引用的位置照旧拦截）；能力 `cloud/1` |
| 客户端 | `CloudLoginServer`：经登录中继完成服务器登录（53682 不可用或条目声明不支持时，退回无浏览器授权，并在确认后用这台电脑的 rclone 运行 `rclone authorize`，结果只显示给用户、由用户粘贴）；登录后先测试再保存，失败不留残余。`CloudLoginHere`：在用户终端里运行 rclone 自己的配置。`SyncCloud`：服务器登录时直传，连不上且这台电脑登录时经仓库或临时目录中转。副本核对把这台电脑登录的云盘从这台电脑读 |

### 2.3a 第一次实机尝试暴露的问题（2026-11-08，已修复）

用户首次运行服务器登录时无法登录：

1. **提问错位、回车无效**：Valise 经 ControlMaster 复用连接运行 `ssh -tt`，本机 stdin 是管道，OpenSSH 分配的远端 PTY 全部模式为空（`-opost -onlcr`、无回显、回车不转换成换行）。修复：porter `login-run` 在执行登录命令前把 PTY 恢复为行模式（`porter/internal/login/tty_linux.go`）。用 `ssh -tt -o ControlMaster=auto` 复现并确认。
2. **打开的是教程页**：链接扫描接受任意链接，rclone 在 client_id 提问里打印的 `rclone.org` 帮助链接被当成登录页，Valise 的“是否打开”提问还吞掉了用户给 rclone 的回车。修复：云盘登录只认 `http://127.0.0.1:53682/auth?state=…`（`TestCloudLinkPattern`）。
3. **中断的登录留下残余**：客户端仍在等待时服务器上的 `rclone config create` 一直运行，已写入的同名登录使下次登录报“已经有登录”。修复：同名位置不存在时，再次登录先删除旧登录并记入审计（`TestCloudPrepareAndForget`）。

第二次尝试（2026-11-08，用户在浏览器授权成功，rclone 退出码 0）又暴露两处：

4. **令牌显示在终端**：rclone `config create` 结束时把整段配置（含 access/refresh token）打印到终端（只显示给用户，不进日志，用户转述时已自行隐去）。修复：`CreateArgs` 加 `--no-output`；实机确认提问照常显示。
5. **连通测试超时却报“无法运行 rclone”**：服务器审计显示登录结束（23:56:59.8）到撤销登录（23:57:20.2）相隔约 20 秒，即测试用尽时限；rclone 默认静默重试，没有留下原因。同一时刻服务器到 Google 接口的网络正常（0.3 秒）。推测是 rclone 共享应用被限流，尚未证实。修复：测试给 rclone 加限时参数让它自己报错，超时单独说明，rclone 的错误行作为细节返回（`-v` 可见）；用无效令牌的 Google Drive 登录确认错误分类与细节（`TestRcloneProbeTimeout`）。

修复后在 `ubuntu-vm` 上用伪终端走完整个对话（client_id、client_secret、service_account_file 回车，高级设置 n，共享应用 y）：输出逐行对齐，rclone 打印回环授权链接后 Valise 才建立转发并询问是否打开浏览器（测试时答 n，没有打开浏览器）；随后清理服务器上的测试登录。
