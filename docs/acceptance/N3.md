## 1. 严格副本（2026-11-07）

### 1.1 实现映射

| 位置 | 内容 |

| `core/vault/materials.go` | `Material`（路径、大小、SHA-256、修改时间文本）；`ListMaterials`（可不读数据包内容）；`CompareMaterials`（缺少、多出、不同、未给哈希的小文件；数据包的哈希对照它的名字）；`IntegrityCheck`（第 7 节免钥匙校验作用于清单，适用于不在本地磁盘上的副本） |

### 1.2 自动化证据

- `core/vault`：快照数相同但缺数据包、缺去重参数、元数据内容不同、多出文件；数据包未核对时 index 范围仍检查。
- `core/stationsync`：数据包只在要求时下载；已核对的按大小与修改时间复用。
- porter `seal`：sftp 下载核对（含复用与缺包、改元数据）；rsync 校验和对比（同大小被改坏的数据包被找出）。rsync 用例需要 GNU rsync，在 `ubuntu-vm-x86` 上以交叉编译的测试程序运行通过。原有 sftp 测试替身在 `/bin` 即 `/usr/bin` 的系统上会找到 rsync，已改为 PATH 只含替身目录。
- 客户端 service（fake-ssh + 真实 porter 构建）：服务器与本机仓库都完整；删掉一个数据包后仓库为不完整、指出缺的文件、不再算其他完整副本；证据记录；跳过的位置为未核对；单快照取回标记一律不算完整周期；复制后核对结果为“清单一致”。
- 全仓 `testbed/selfcheck.sh` 通过（SELFCHECK_PASS）。

### 1.3 实机（`ubuntu-vm`，porter 以 `porter deploy --local` 部署当前构建）

- `dsh/2026-10-01_2026-10-31`（12 个备份）：不带 `--packs` 时三处（服务器、`nas`、本机仓库 `local`）为“清单一致，内容未核对”，`nas` 提示核对要下载 3.8 KiB；带 `--packs` 后三处都“完整”。`ubuntu-vm` 没有 rsync，`nas` 经 sftp 下载核对。
- `openclaw/2026-10-01_2026-10-31`（29 个备份，264 MiB）：首次带 `--packs` 用时约 77 秒（`nas` 下载 264.2 MiB）；再次核对只下载 1.5 MiB 小文件，用时约 24 秒，三处完整。
- 把本机仓库里的一个数据包临时移走：仓库显示“不完整：缺 1 个文件（列出路径）”及 index 引用问题；放回后恢复为清单一致。
- `vault delete … --skip local`：当场核对后服务器与 `nas` 完整、`local` 为“未核对（已跳过），不算完整副本”，`nas` 复用已核对的数据包未再下载；回答 N，周期未删除。
