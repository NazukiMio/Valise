先说结论

  1. 规范写得比界面好。UI.md 7.2 的“正常就安静、异常才出声、每页一个主按钮”方向是对的，但代码只在首页落实了。全应用有 83 个主按钮、171 个普通按钮 实测，健康页、命令行页、安装页一屏里同时出现两三个主按钮。
  2. 没有“危险”这一档。调色板只有 ok / warn / stop 三种语气，stop 与次要文字对比度 1.03（等于同色），健康检查的“严重”和“留意”画成同一种橙色，删除、注销、关闭备用锁用的是普通主按钮 实测。这是诚实状态的硬伤，比好不好看更要紧。
  3. 整个桌面端没有一处过渡动画。Animate*、Transition、AnimatePose、Timeline、.Cache()、List/Table、ui/shader 的使用次数都是 0；唯一会动的是旅程发丝线，它用每 33ms 重绘一次的 CPU 路径实现 实测。
  4. 主题只解耦了一半。颜色是令牌，但间距、字号、阴影、动效全是散落的数字（13 种字号、22 种内边距写法、11 种圆角值 实测），调色板的名字直接叫 gold、strand、spine，等于把“金线发丝”写进了主题格式。
  5. 文案的问题集中在三处：恢复流程把内部词搬上了台面（暂存、交换、活动目录、现场、相交操作）；“副本”同时指“备份的拷贝”和“克隆出来的 Agent”；与现行规范矛盾的“管理口令”文案还在。

A2 令牌与主题框架

轻量与重量级怎么共存。着色器是编译进客户端的“材质库”，主题文件只是点菜单："materials": {"backdrop": "aurora", "surface": "glass", "intensity": 0.6}。这样外部主题仍然是纯数据（AGENTS.md 第 3 节：主题不得含条件、循环、表达式或脚本），内置的重量级主题和用户自己做的主题走同一条路，只是选的材质不同。

护栏（哪种主题都不能破）

  • 提醒、错误、确认框、口令框永远画在不透明表面上，不吃毛玻璃和背景着色器。UI.md 7.4 的“始终显示”清单保持不变。
  • 导入主题时检查对比度：text.primary 对各表面 ≥ 4.5，状态色对其底色 ≥ 3，不达标就拒绝导入并说明是哪一对。重量级主题不能把警告洗淡。
  • 自动降级为 flat：p.Accelerated() 为假、系统开了减少动态效果或高对比度、或用户在个性化里把“氛围动效”设为关。降级只换材质，不改布局和文字。
  • 格式兼容：新名字需要 valise-theme/2；/1 的旧颜色名继续按别名读取，已导入的主题不失效。这一条要先改 UI.md 7.4，见需要你决定。

两套重量级主题提案

夜航（深色，沉浸）

深靛蓝夜空，机舱窗外的极光缓慢流动；卡片是磨砂舷窗；旅程是一条发光的航迹，每个时间点是一盏航标灯。

  • 背景：Kage 片元着色器做两色低频噪声流动，颜色在 Oklab 里混。画进 1/4 分辨率的 ui.Canvas 再放大，p.After(66ms) 约 15 帧。
  • 卡片：shader.Options{BackdropBlur: 18} 加一层 tint；1px 渐变镂空边用 Masks（MaskContentBox + MaskExclude）。
  • 旅程：航迹与光晕画进一个着色器矩形；节点微光用 DrawInstances，上限 300 个粒子；选中节点用 Oklab RadialGradient。
  • 首页结论句：shader.Text 给大字一层很淡的金属渐变，只在“一切正常”时用。

手账（浅色，质感）

一本旅行手账：厚纸、压印、烫金边，每次备份是一枚邮戳。表现力来自材质，几乎不动，待机零开销。

  • 纸面：静态噪点颗粒着色器加四角暗角（RadialGradient），整层 .Cache()。
  • 卡片：InsetShadow 做压印边，外阴影两层叠出纸的厚度；待处理卡片用撕边纸条的 ClipPath。
  • 烫金：主按钮和选中的时间点用 BorderConicGradient，角度随指针位置在 Draw 里变，离开即静止。
  • 旅程：一笔墨线（shader.StrokePath），时间点画成圆形邮戳，日期沿圆弧排字。

D · 《Valise 审美、交互与文案工程指南》

下面是可以直接落进 docs/ 的草稿（建议作为 UI.md 的一节或独立的 docs/DESIGN.md）。写法是规则加检查办法，后来的 Agent 不需要看到未来页面的草图也能照做。

D1 一页怎么搭

  1. 每页回答一个问题，把这个问题写在视图函数的注释第一行。页头是：返回（或面包屑）、标题、一句现在怎样、至多一个主按钮。
  2. 从上到下的顺序固定：页头 → 需要处理的事 → 正在进行的事 → 正常的内容 → 折叠的技术信息。
  3. 只用语义函数：card、subPanel、reportPanel、codeBox、fact、stepList、pressable、backLink、statusRow、emptyState。视图文件里不出现 FontSize(数字)、Padding(数字)、Radius(数字)、Gap(数字)，一律取令牌。用一个测试扫描 gui/ 守住，白名单只含 theme.go 和自绘组件。
  4. 间距三档：组内 8，组间 16，区块间 24 或 32。同一个容器里不混用相邻两档以外的值。
  5. 卡片是例外，不是默认。一页里并排的同类内容用一张卡片加分隔线；只有需要单独拿起来看的东西才各自成卡。卡片里不再套卡片，里面的小块用 subPanel。
  6. 字号只有 7 级，最小 12。次要信息靠颜色退后，不靠缩小。

D2 按钮与状态

种类用在规则
主按钮这一屏最该做的那一件事每屏至多一个；弹窗里的确认按钮算弹窗这一屏的
普通按钮其余会做事的操作文字是动词加对象，会再问一次的以“…”结尾

危险按钮删除、注销、关闭备用锁、移除并清理只出现在确认框里；文字写出后果（“删除并清理”），不写“确定”
  • 状态五种语气：ok、warn、danger、neutral（明确不在运行）、unknown（没读到）。每种都是“图标或点 + 词”，不只靠颜色。
  • 各说各的：隧道 / 端口 / 页面；退出码 / 服务是否健康；已存到服务器 / 已同步到别处；已核实 / 未核实。每一组里的每一项各占一行或一格，用 statusRow 或状态牌。不做把它们合起来的徽标、总分或总进度环。

  • 没做的不画：未实现的能力不放按钮，也不放灰色按钮。因前置条件未满足而暂时不能点的按钮可以禁用，但旁边必须写出还差什么。

D3 可点区域、悬停与折叠

  • 整行整卡规则：有边框或底色、内容指向另一个页面的行或卡片，整块可点，行尾有箭头图标。块内另有按钮时，按钮自己处理点击、不触发整块（参照 locCard）。不指向别处的信息行不做成卡片外观。
  • 可点的东西必须同时有：CursorPointer、Role、Label、键盘焦点环、悬停与按下外观。全部由 pressable 提供，不手写。
  • 点击区不小于 28×28；图标按钮带 Tooltip。
  • 悬停只在 Draw 回调里读 Hovered()。构建期读取会让指针每次进出都重建整个视图。只有悬停要改变布局或显示新内容时才允许在构建期读，并写注释说明。
  • 静态而复杂的块加 .Cache()：渐变、多层阴影、噪点、模糊。里面有会动的东西就不要整块缓存。
  • 移动与缩放用 AnimatePose；颜色与阴影用 ElementTransition{Colors, Shadows}；出现与消失用 Enter/Exit 并给元素 Key。动效时长只取 120 / 200 / 320 三个令牌。
  • 自己用 p.After 或 AnimationFrame 驱动的绘制必须：看 ReduceMotion；看 p.Accelerated()；所在页签不可见时停止。
  • 可能超过 50 行的集合用 List 或 Table。
  • 折叠详情是必配的：凡是出现 id、路径、端口、命令、哈希、错误代码、原理说明，都放进“技术信息”或“查看详情…”。例外是确认框：将要执行的每条命令和会改变的内容直接展示，不折叠（UI.md 9.5）。
  • 错误一律用 errorBox：原因一句、建议一句、技术信息折叠。不把原始错误文本放在主位置。

规矩

  • 一处一句。写完数一下句号：正文超过一个就把后面的移进“查看详情…”。

  • 口语但不随便：用“没有”“还没”“先…再…”，不用“尚未”“须”“以…为准”“进行…操作”“该”“此”“上述”“下列”。也不用“搞定”“没办”这类过头的口语。
  • 否定要具体：不写“失败”，写“没有完成”并说卡在哪一步。
  • 数字和名字放前面：“3 个 Agent 有新备份还没同步”，不写“存在未同步备份的 Agent 共 3 个”。
  • 标点：中文全角；“…”只用于“还会再问一次”的按钮和进行中的状态；并列用“·”仅限标签，句子里用逗号顿号；箭头和对勾是图标，不写进词表。
