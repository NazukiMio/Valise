## 1. 真实窗口试用（2026-11-08）

环境：本机开发构建（临时打成 `.app`，只为让操控工具识别；不是发布包），`--config-dir` 指向演练配置，连接 `ubuntu-vm`、`ubuntu-vm-x86`、`debian-vm`。操作由 Claude 通过 macOS 无障碍接口在后台完成。

### 1.1 通过

| 项 | 结果 |
| --- | --- |
| 首页读取 | 14 个 Agent，卡片视图；提醒卡片带「知道了」「带我去处理」 |
| 搜索 | 输入 `x86` 只剩该服务器上的 5 个；清除后恢复 |

### 1.2 发现并已修复

1. **本机备份按连接名匹配**：仓库里服务器目录用的是金库自己的名字（`debian-vm` 存在 `debian/` 下），界面按连接名找，`debian-vm` 上的 Agent 都显示“本机没有备份”并被算进“超过 7 天”的提醒。改为读 Agent 时顺带用日常钥匙读各服务器的金库名（`VaultStatus`），按它匹配；提醒从 6 个降到 4 个。
2. **自绘卡片没有按钮角色**：Agent 卡片、列表行、视图切换、导航窄栏、旅程节点在无障碍树里只有文字，读屏无法按下。加上按钮角色；名字带上 harness 与服务器，同名 Agent 可以区分。
3. **桌面版没接 Valise 口令框**：管理页令牌一步要确认是本人，服务层报“这里没法询问 Valise 口令”。已接上 `OwnerAuth`，与管理口令共用一个弹框，文案分开。
4. **健康页“定时备份：每 一次”**：保护计划按日历时间运行，没有固定间隔，文案拼空。改为“按保护计划的时间运行”。服务层文字，TUI 同样受益。
5. **未来时间说成“1 分钟前”**：模拟夏令时期间（时钟调到 2027 年）留下的备份，健康页说成“1 分钟前”。改为写出记录的日期并说明“晚于现在（备份时服务器时钟可能不准）”。
6. **搜索时计数不变**：改为“找到 N 个 · 共 M 个在用”。
7. **“超过 7 天”提醒不分原因**：补齐后仍有 4 个 Agent 报“没有新备份到这台电脑”，其实服务器上也没有新备份，“现在补到本机”解决不了。按用户决定（UI.md 7.2、7.3）分成两张卡片：服务器有更新的备份 →“有新备份还没复制到这台电脑”，去备份位置；服务器也没有 →“超过 7 天没有新备份”，去第一个 Agent 的“健康”看定时备份。服务器每个 Agent 的最新备份时间随读 Agent 时的金库状态一起读。实机复核：4 个都归到后者，进入 `debian-vm` 的 drill-synthetic 健康页签，显示“定时备份：没有开启”“备份：还没有备份”。

## 3. 服务器设置与删除（2026-11-09，ARCHITECTURE.md 2.3，草图 `docs/sketches/valise-server-settings-gui-2026-11-09.html`）

### 3.1 实现映射

- porter：管理方法 `server_leave`（`core/vaultrpc`，分级表列为管理级），三步 `timers`（`timer.RemoveAll`：停掉并删除全部 `valise-seal@*.timer/.service`，保护计划记录留着）、`mark`（`seal.MarkServerRemoved` 写 `server.json` 的 `removed_at`；同名再起名时清除）、`porter`（删 `~/.local/bin/valise-porter`）。测试：`porter/internal/timer/leave_test.go`、`porter/internal/seal/leave_test.go`。
- 服务层：`ServerLeftovers`（用户通行证读取：porter、本机有的通行证、定时备份、Valise 装的增强工具、云盘授权、各 Agent 的保护技能；记进 `server-leftovers.json` 供连不上时列出）、`RemoveServerHere`（只从这台电脑移除：列表、本机通行证文件、Valise known_hosts 中无人再用的地址）、`LeaveServer`（一次管理登录，按 定时备份 → 工具 → 云盘授权 → 保护技能 → 标记 → porter → 通行证 的顺序，每项回报，失败就停、服务器留在列表）、`RemovedServers`（`removed-servers.json`；重新添加时清除）、部署记录 `LastDeploy`（`porter-deploys.json`，SHA-256）。测试：`service/leave_test.go`（fake-ssh：清理后 porter、`authorized_keys` 里的通行证、列表、known_hosts 都没了，`server.json` 带 `removed_at`，备份库与名字留着）。
- 桌面：`gui/serversettings.go`（设置页签各行）、`gui/serveractions.go`（改名、改用 Valise 通行证、更新 porter 三页）、`gui/serverleave.go`（删除对话框、进度、连不上时）、`gui/serverremoved.go`（已删除的服务器、备份位置标签、重装与重新添加借用添加向导）、`gui/job.go`（子步骤、已等时间、停止）。测试：`gui/serversettings_test.go`；`VALISE_SHOTS` 渲染核对与草图一致。

## 4. 钥匙与备份（2026-11-09，UI.md 7.7、7.8，ARCHITECTURE.md 3、3.2、3.3）

### 4.1 实现映射

- 共享：`core/recovery`（请求与结果的 RPC 类型、验证码、最多 3 次）；分级表把 `recovery_request`、`recovery_result`、`recovery_clear` 列为日常级。
- porter：`internal/recovery`（放请求、读结果、清除；`Answer` 用主机密钥打开备用锁、用一次性公钥重新加密、只新建结果文件；`Run` 要求 euid 0 且 `--for` 等于 `SUDO_USER`，读完 `/etc/ssh/ssh_host_ed25519_key` 立即 `setgroups/setgid/setuid` 到该用户）；`main.go` 的 `recovery-code --for <用户>`；`internal/server/recovery_methods.go`。新依赖 `filippo.io/age/agessh`（age 的标准 SSH 收件人）。测试：`internal/recovery/recovery_test.go`（真实 ed25519 主机密钥，含错锁、符号链接、不覆盖）。
- 服务层：`keyextra.go`（钥匙是否备份过、“稍后”、修改口令）、`recovery_lock.go`（备用锁的做、补做、换口令、关闭与每台服务器的状态）、`recovery_run.go`（扫描 porter、放请求、核对验证码、设新口令并重做备用锁、取消；找回模式暂停自动复制）、`adminrebuild.go`（逐台重办管理员通行证，连不上的留“待重办”）。测试：`service/recovery_test.go`（fake-ssh 端到端：口令修改、找回全流程含错码与作废、主机密钥变了、关闭；重办后 `authorized_keys` 只剩新的那行）。
- 桌面：`gui/settingspage.go`、`gui/keyflow.go`、`gui/protect.go`、`gui/backupnow.go`、`gui/recoverpage.go`、`gui/rebuildpage.go`；服务器设置的“加密钥匙”可登记、显示备用锁；首页“超过 7 天没有新备份”带到“管理与设置”。保护计划修改与备份都由窗口里的点击确认（服务层的 review 钩子只放行这里确认过的计划）。测试：`gui/keys_test.go`；`VALISE_SHOTS` 渲染核对。
