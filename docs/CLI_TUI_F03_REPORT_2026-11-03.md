# F03 按快照取回：实现与验证报告

- 日期：2026-11-03
- 起点：`docs/CLI_TUI_RETEST_2026-11-03.md` 中的 F03 第二部分（冷缓存 + 小目标快照 + 同周期大历史备份时，取回整个周期）
- 用户决定：同意"只取回这个逃生舱需要的部分"的方案（2026-11-03）
- 范围：只涉及客户端的取回方式；金库公开格式（VAULT_FORMAT.md）没有改动。

## 1. 做了什么

恢复计划（原地恢复、迁移、克隆）与恢复测试都改为按快照取回：

1. **小文件**：先取回周期里不含数据包的文件：VAULT、epochs、keys、index、快照头与 meta。
2. **解开快照头**：用加密钥匙解开快照头。口令因此从"取回之后"提前到"取回中间"，因为用到哪些数据块写在加密的文件清单里。
3. **文件清单所在的数据包**：按快照头里文件清单的 blob 查 index，只取回清单所在的数据包，然后解开文件清单。
4. **文件内容所在的数据包**：按清单里每个文件引用的 blob 查 index，只取回本机缺的数据包。这一步自然包含引用了历史 blob 的情况。
5. **完整性没有放松**：
   - 下载的数据包核对 SHA-256，必须等于 pack id，沿用原有检查。
   - 本机已有的数据包重新核对后才复用，损坏的重新下载。
   - 快照头由 age 认证。
   - 每个文件写出时仍按 SHA-256 核对。
6. **部分副本有标记**：这样的本机缓存旁边写 `<金库目录>.partial.json`，说明它尚未通过完整周期校验；清单仅记录已成功取回恢复材料的逃生舱。2026-11-04 补充：在任何下载写入前原子写入标记，标记失败就停止，失败与中断后保留标记；清单为空表示还没有成功取回的快照。
   - 对它运行整体校验（`valise verify --vault`）会被拒绝，并说明原因。
   - 之后若取回整个周期且校验通过，标记自动删除。
7. **其他复制方式不变**：本机仓库、空间站、"保存加密备份"（`valise pull`）仍复制整个周期，脱离 Valise 恢复（`tools/standalone-restore/`）的承诺不变。
8. **结果可见**：恢复计划与恢复测试的输出写明周期总大小、逃生舱大小、用到的数据包数量与大小、本次下载量和复用量。

阶段名称同步更新：CLI 显示"取回周期的索引与清单（很小）"与"只取回这个逃生舱用到的数据包（已有的核对 SHA-256 后复用）"；终端界面的着陆步骤也加了这一步。

代码位置：`client/ui/service/pullsnap.go`（新）、`core/vault/reader.go`（`SnapshotHeader`、`PacksOf`）、`client/ui/service/revive_plan.go`、`client/ui/service/restoretest.go`、`client/ui/service/vault.go`、`client/ui/cmd/valise/progress.go`、`client/ui/tui/landing.go`；规范：ARCHITECTURE.md"快照来源"一节。

## 2. 验证

### 2.1 自动测试（fake-ssh）

`TestPullSnapshotOnlyItsPacks` 复现报告里的触发条件：先封存一个 40 MiB、不可压缩的完整快照，再封存一个只有几字节的轻装快照，两者在同一周期。

| 检查 | 结果 |
| --- | --- |
| 冷缓存 | 周期 41,974,984 字节，共 4 个数据包；只取回 2 个（17,061,420 字节） |
| 部分标记 | 存在；整体校验被拒绝 |
| 逐文件写出与 SHA-256 | 全部通过 |
| 热缓存 | 下载 0，复用量等于用到的数据包总量 |
| 本机数据包被改坏 | 重新下载 |
| 之后取回整个周期 | 部分标记被删除 |

注意：这个用例里，小快照的 blob 与大快照写在同一个数据包里，所以要取回 2 个数据包（约 17 MiB），而不是只有几字节。这就是复测记录提醒的"传输粒度可能是整个 pack"，测试里按数据包数量验收，不按快照逻辑大小。

### 2.2 靶机（debian-vm，Debian 13 arm64）

条件与复测一致：
- 周期 `openclaw/2026-11-01_2026-11-30` 共 235.3 MiB，其中有一个 722.9 MiB 的原样（raw）逃生舱。
- 目标是同周期里 3.7 MiB 的轻装逃生舱 `s_01M6G5GTQH7NAAPKZ71JC79HYP`。

使用测试配置的副本，去掉本机金库缓存，构成冷缓存，执行 `valise restore-test debian openclaw --snapshot …` 两次：

| | 冷缓存 | 热缓存 |
| --- | --- | --- |
| 周期总大小 | 235.3 MiB | 235.3 MiB |
| 逃生舱大小 | 3.7 MiB | 3.7 MiB |
| 用到的数据包 | 2 个，463.5 KiB | 2 个，463.5 KiB |
| 本次下载 | **8.3 MiB** | **0 B** |
| 复用本机已有 | 0 B | 463.5 KiB |
| 本机缓存占用 | 8.4 MiB | 不变 |
| 结果 | 通过：两边都解开并核对 10 个文件，没有切换 | 通过 |
| 用时 | 19 秒（含服务器暂存与核对） | 17 秒 |

8.3 MiB 中约 7.9 MiB 是周期的索引与快照元数据，其中大部分是原样逃生舱 48,601 个文件的 index；真正用到的数据包只有 463.5 KiB。改动前，同样的操作要先下载约 235 MiB。

恢复测试按设计在服务器上写入暂存并丢弃，没有切换，也没有改动 agent；测试用的配置副本（含钥匙）已经删除。

### 2.3 没有覆盖的

- **取回中途断线**：没有在靶机上故意制造断线。2026-11-04 已补 fake-ssh 故障注入：分别在元数据与 pack 传输 32 字节后断开，检查部分标记保留、未完成快照未列入清单、整体校验拒绝、pack 临时文件清理，然后重新进入并完成取回。已完成 pack 的哈希复用仍由热缓存测试覆盖；这不等于真实网络断线验收。
- **oracle 上的复测快照**（`s_01M6GMVKSS3HDH5MFRRHGS09PY`）：这台电脑上没有你那份配置的口令，所以没有在 oracle 上跑。改用条件相同的 debian 周期。
- **终端界面里的着陆流程**：只经过自动测试，靶机上用的是 CLI。

## 3. 后续可以考虑

- **索引的体积**：冷缓存时周期索引就占了约 7.9 MiB，原样逃生舱文件很多时会更大。能否按快照减少索引读取，以及是否需要调整格式，仍需研究；当前实现取回整个周期的索引。
- **数据包共享**：当前实现以整个 pack 为传输与 SHA-256 校验单位。小快照的数据块若和大快照共享 pack，仍要取回整个包。未来可以研究调整新 pack 的分组策略，或利用现有 offset/length 做范围读取，未必需要改公开格式；范围读取需要另行设计完整性校验方式，本轮没有实现。

## 4. 2026-11-04 复核补修

按代码复核意见补了以下三处：

- **F07 错误分支**：健康读取失败时，概览写“健康状态读取失败，暂无法判断”；其他运行与备份问题仍照常显示，不再退回“需要处理：无”。测试覆盖没有其他问题时的读取失败。
- **部分缓存状态**：下载前先用临时文件、同步、原子改名写入标记；失败立即返回错误，不开始写取回文件。中断后标记保留，尚未完成的快照不加入清单；成功后更新清单也检查写入错误。仅完整周期取回且通过整体校验后删除标记，删除错误向调用者报告。即使所有 pack 文件恰好都存在，也不再只凭文件存在就取消标记。
- **报告判断**：索引优化是否涉及格式变更仍待研究；pack 分组策略和基于 offset/length 的范围读取可能不需要改公开格式，但范围读取的完整性校验需要另行设计。

验证结果：

| 检查 | 结果与范围 |
| --- | --- |
| 健康错误分支 | `TestOverviewNeeds` 通过 |
| 元数据断线后重新进入 | fake-ssh 传输 32 字节后强制断开；部分标记保留，清单为空，整体校验拒绝；重新进入后继续 |
| pack 断线后重新进入 | 同样断开，未完成 pack 的临时文件清除；重新进入后成功取回并逐文件核对 |

| 真实 TUI 着陆计划 | 最终客户端在 110×34 伪终端连接 Debian，进入逃生舱详情、着陆选项、口令、取回与计划页；显示周期 235.5 MiB、目标 3.7 MiB、2 个必要 pack，以及缓存尚未通过完整周期校验的说明；在开始暂存前退出，驱动最终退出码 0 |

真实 TUI 检查使用已有配置和缓存，不是冷缓存指标复测；运行期间首页按已有配置进行了后台仓库补齐。没有请求暂存、目录交换或修改 agent 活动目录，也没有覆盖完整 TUI 着陆流程。

**仍未验收：真实 SSH 中途断线重试。** 本轮准备使用客户端测试包装器截断真实 pack 流，随后重试恢复测试；自动审批在写入验收脚本时拒绝，理由为 `Remote Shell Writes`（恢复测试会写入服务器暂存目录）。脚本没有获准写入，该项没有执行；不能用 fake-ssh 结果代替靶机验收。Oracle 原样本和完整 TUI 着陆也仍未覆盖。
