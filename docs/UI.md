# UI 规范（TUI 与 mygo 桌面）

> UI 分两步：终端 UI（第 8 节，M7a 起），桌面 UI（第 2–7 节，mygo，M7b 暂停到新信息架构在 TUI 上稳定之后）。第 1 节的分层原则全程有效：服务层不依赖 UI。第 9 节的信息架构由两者共用。

## 1. 分层原则

- 所有业务逻辑都写在 `client/ui` 的服务层（纯 Go）中，CLI、TUI 和桌面 UI 共用同一套服务层。**TUI 和桌面 UI 都只是很薄的适配层，没有它们，CLI 也必须完整可用。**
- 这样做也是对框架风险的控制：mygo 是一个由个人维护的年轻项目。即使将来需要更换 UI 框架，也只需要重写适配层和前端，服务层不受影响。

## 2. 资料来源

- 官方文档：https://github.com/egoist/mygo/tree/main/docs ，阅读时以锁定 tag 下的版本为准。
- Go API：`go doc -all github.com/egoist/mygo`
- 开发机检查：`go tool mygo doctor`
- 不确定的 API 一律查阅文档或源码，**不要凭印象编写**。

## 3. 版本锁定与 CLI

- 锁定版本：v0.7.3（用户于 2026-10-31 指定，提交 `6f28d7b`；M7b 开工时写入依赖并复核本文约定）。锁定后，升级必须经过用户同意。
- 把 mygo CLI 作为 Go tool 依赖加入，保证 CLI 和库的版本一致：`go get -tool github.com/egoist/mygo/cmd/mygo@<锁定版本>`。之后统一使用 `go tool mygo <命令>` 调用 CLI。
- 前端依赖中的 `mygo-runtime` 也锁定为与锁定版本对应的版本。

## 4. 绑定约定

- **生成客户端**：`go tool mygo generate`，输出路径为 `client/ui/src/mygo.ts`（在 `mygo.config.ts` 的 `bindings` 中配置）。生成的文件不得手工修改，也不计入"单文件 400 行"的限制。
- **生成期间会执行 main**：`mygo generate` 会在设置 `MYGO_GENERATE` 的情况下运行程序，直到 `App.Run` 返回。因此建立 SSH 连接、读取 keystore、启动隧道等任何有副作用的初始化，都必须放进 `App.WhenReady`。main 函数中只允许调用 `mygo.Bind` 和注册事件。
- **服务划分**：按领域绑定，例如 `Servers`、`Instances`、`Vault`、`Revive`、`Relay`、`Keystore`、`Settings`。每个服务对应 `client/ui` 服务层中的一个 Go 类型，方法只负责参数转换。
- **进度流**：封存、同步、复活、登录中继等长时间操作，通过 `*mygo.Channel[T]` 参数把进度推送给前端。方法的第一个参数接收 `context.Context`，页面关闭时操作随之取消（复活进入交换阶段之后不响应取消，见第 6 节）。
- **全局状态变化**：例如实例的健康状态、隧道的三个状态，使用 `mygo.NewEvent` 声明的事件进行广播。
- **字段命名**：所有结构体字段必须带 `json` 标签。可能超过 2⁵³ 的整数（目前没有）使用 `json:",string"`。

## 5. 错误约定

mygo 会把 Go 方法返回的 error 文本作为前端 `CallError` 的 message。约定如下：

- 服务层的错误统一为 `valise.UserError{Code, Reason, Suggestion, Detail}`，它的 `Error()` 返回该结构的 JSON 文本。
- 前端在 `src/errors.ts` 中统一解析：能解析时，展示"原因 + 建议"，细节默认折叠；不能解析时，展示"发生了未预期的错误"，并附上原文。
- 禁止在前端直接展示未经解析的原始错误文本。

## 6. 安全铁律

- **入口一律用系统浏览器打开**（通过 mygo 的 shell API 打开 URL），**绝不在 mygo 窗口中加载 agent 的 Web 页面**。原因：开发构建会信任 localhost 页面，经隧道转发的 agent 页面也位于 localhost，在应用窗口中加载它，就等于允许它调用 Go 方法，包括解锁密钥和复活。
- 禁止设置 `TrustedOrigins: ["*"]`。应用窗口只加载自己的前端。
- 口令输入框不得把值写进任何前端状态持久化或日志中，提交后立即清空。
- 复活一旦进入交换阶段，关闭窗口或页面不得中断进行中的交换。服务层持有独立的 context，前端重新打开后，通过事件恢复显示进度。

## 7. 前端结构

```text
client/ui/src/
├── mygo.ts            # 生成文件，禁止手改
├── main.ts            # 入口与路由
├── state.ts           # 全局状态（订阅 events）
├── errors.ts          # UserError 解析
├── views/
│   ├── instances.ts   # 实例总览
│   ├── vault.ts       # 金库与快照
│   ├── revive.ts      # 复活向导
│   ├── relay.ts       # 登录中继
│   └── settings.ts    # 设置与信任根
└── components/        # 状态徽标（三态分离）、进度条、确认对话框等
```

单个手写 `.ts` 文件不得超过 400 行。`package.json` 中的 `typecheck` 和 `build:web` 脚本由本项目自己定义：`typecheck` 执行 `tsc --noEmit`，`build:web` 只构建前端。打包应用使用 `go tool mygo build`。

## 8. 终端 UI（M7a）

- **框架与版本**：Bubble Tea 生态，锁定 `charm.land/bubbletea/v2 v2.1.1`、`charm.land/bubbles/v2 v2.2.1`、`charm.land/lipgloss/v2 v2.0.6`（2026-10-31 的最新稳定版）。升级须经用户同意。
- **入口**：`valise tui`，与 CLI 同一个二进制；共用 `--config-dir`。
- **代码位置**：`client/ui/tui/`，按视图拆分（如 `model.go`、`instances.go`、`vault.go`、`revive.go`、`relay.go`、`kit.go`、`settings.go`、`styles.go`）。单个 `.go` 文件不得超过 400 行。TUI 只调用服务层，不直接发 RPC、不读写服务器文件。
- **耗时操作**：一律放进 `tea.Cmd` 在后台执行，界面显示进度；服务层回调（如复活的阶段、登录状态）转成消息送回界面。复活进入交换阶段后，界面上的"取消"不得中断交换。
  - 进度（2026-11-01 用户反馈）：取回逃生舱、着陆等长操作逐步列出阶段（已完成打勾、当前一步转动、之后的变暗），能计量的阶段（取回到本机、写入暂存目录）显示进度条、百分比与已传输量，并显示已用时间，让用户知道它没有卡住。服务层经 `service.WithProgress` 上报，界面只在动画帧里读取最新值。
  - 动画与遥测面板（2026-11-01 用户决定，草图已确认）：火箭字符画（素材 `assets/TUI/rocket`，用户创作，TUI 实现 `client/ui/tui/rocket.go` 与 `hud.go`）只用于逃生舱着陆与上云两页；逃生舱列表、详情不铺背景。
    - 画面：场景按等比例放大盖满内容区（超出部分居中裁掉，不拉伸），一直播放到离开页面。文字放在"科幻面板"里：面板盖住的场景压暗显示、继续运动（模拟半透明），四角标记加细边线，左上角小标题。左上主面板：当前提示（加粗，正常字距）、下面一行白话说明实际在做什么、步骤勾选；右上遥测：已用时、预计剩余（能估算时）、速度、目标；底部进度面板：第几步、大进度条、百分比与数据量，无法计量时显示来回扫动的光条，等用户决定时光条停住。宽度不足 100 列时遥测并入主面板；不足 60×16 时去掉背景，退回纯文字布局。
    - 提示（步骤名用航天说法，小字用白话）：着陆为"逃生舱正在进入预备轨道…（将备份取回本机）""逃生舱正在进入轨道…（解密备份，检查里面的文件）""轨道就绪 · 请确认着陆计划""正在联络母星…（把备份写入服务器的暂存目录）""正在呼叫地面指挥…（核对暂存的文件，等你下令）""逃生舱即将登陆…（把 agent 换成备份里的版本，并做健康检查）""逃生舱登陆成功！"，失败为"着陆中止"。上云为"逃生舱等候发射…（把还没上云的备份传到云端位置）"，完成后随火箭依次显示"正在进入轨道…""正在呼叫空间站…""空间站对接中…"，最后"逃生舱已接入空间站！"，失败为"发射中止"。
    - 时机：能预估剩余时间时，在接近结束时开始播放火箭，按原版速度；不能预估时等结束后再播放。着陆在用户下令交换后火箭开始下降（交换与健康检查只需几秒）；降到底部面板上方仍未完成时悬停等待，真正完成后才着地。上云目前无法预估，传输时火箭停在发射台，完成后点火。成功的提示和结果在动画结束（落地、烟尘散尽 / 火箭飞离）后才出现；后台任务已经完成而动画仍在播放时提供 enter 跳过动画，任务还在进行时不提供；esc 在任务完成后随时可用。失败不播放火箭动画（正在下降的火箭掉头飞离），立即显示原因；已自动退回时同样处理。
- **需要终端的操作**：登录中继、口令输入等需要原始终端的步骤，用 Bubble Tea 的暂停机制把终端交还给对应的 CLI 流程，结束后恢复 TUI。口令不得保存在 TUI 的状态里，用完即弃。
- **确认**：所有会改动服务器的操作（封存、同步、复活、删除 prev、清理旧实例、接受降级提议、安装技能）都要有明确的确认步骤，文案与 CLI 一致；降级提议逐个确认。
- **错误**：服务层的 `UserError` 显示为"原因 + 建议"，技术细节默认折叠。
- **入口**：Web 入口一律用系统浏览器打开（与第 6 节相同）。
- **测试**：模型的状态迁移与渲染用单元测试覆盖（直接调用 `Update`/`View`，不依赖真实终端）；涉及服务器的部分用 fake-ssh 替身。
- **滚动**：任何列表和卡片网格都放在可滚动的视口里，光标始终可见；窗口尺寸变化时重新排版。不得出现光标移出屏幕后停止渲染的情况。滚动跟随光标移动，不要求用户按 PgUp/PgDn；没有光标的长内容用 ↑↓ 逐行滚动，PgUp/PgDn 只是翻页的快捷方式。
- **80 列**：80×24 终端必须能完整使用。恢复计划、停机与空间说明、结果路径、命令全文等决策所需信息换行或可滚动展示，不得截断；快捷键菜单放不下时换行或收进"?"帮助。长操作显示阶段与等待状态。
- **确认主人**（2026-11-02 用户决定）：主人操作（ARCHITECTURE.md 第 2.2 节，如着陆、装技能、改周期、不敏感的删除）只问 Valise 口令，不要求管理钥匙；口令框写明"输入 Valise 口令以确认是你本人，15 分钟内不再询问"。着陆时为解密逃生舱输入的口令同时完成确认，不再多问。
- **解锁开发者模式**（原"管理权限"；管理钥匙即开发者模式钥匙）：开发者模式的操作前，需要管理登录：有管理钥匙且未解锁时弹出口令框（"输入管理口令以继续，15 分钟内不再询问"），顶栏显示"管理权限已解锁 · 剩余 12 分钟"，可以立即锁定；没有管理钥匙时说明"这一步需要服务器密码"，CLI 把终端交给 ssh 的密码提示（GUI 用 askpass），并提示"经常做管理操作，可以在服务器设置里创建管理钥匙"。
  - 主动解锁（2026-11-01 用户反馈）：顶栏在锁定时显示"管理权限：已锁定 · U 解锁"，按 `U` 直接输入管理口令解锁当前服务器；没有管理钥匙时询问是否创建。不需要先执行某个管理操作才能进入解锁状态。
  - 终端界面里的 OpenSSH 一律不得向终端询问任何东西（`BatchMode=yes`）：全屏界面占着终端，ssh 的密码或钥匙口令提示会和界面抢输入，导致输入无效甚至卡死。管理钥匙只从 Valise 的 ssh-agent 取；长操作（如着陆等待用户确认）继续前若管理窗口已过期，由界面重新询问管理口令。需要服务器密码的操作交给 CLI 流程（暂停界面）。口令用完即弃，不进入任何状态。高级模式开启时，顶栏换成红色的"高级模式 · <服务器> · 剩余 N 分钟"，并提供"立即关闭"（INSTALL.md 4.1）。

### 8.1 卡片与图标（2026-11-01 用户决定）

- **统一尺寸**：同一视图内所有卡片宽高一致，图标区固定，不因图标的行数或宽度改变卡片尺寸；名称、状态与操作信息对齐。
- **标准卡片**（服务器页的实例卡片）：外框 52 列 × 14 行；左侧图标区 24 列 × 12 行，右侧信息区约 22 列。图标在图标区内居中，不足的部分补空白。
- **横向翻页**：卡片只排一行，每页放得下几张就放几张（80 列 1 张，110 列 2 张，160 列 3 张）；←→ 移动光标，越过边缘自动翻页；`[` `]` 直接翻页；卡片行下方显示页码圆点（`‹ ● ○ ○ 1/3 ›`）。
- **紧凑卡片**：终端窄于 80 列或矮于 24 行时，同一视图内统一换成紧凑卡片（图标区 12 列 × 6 行），仍横向翻页；重要状态不得被截断。
- **图标来源与降级**：profile 的 `display.icon`（标准）与 `display.icon_compact`（紧凑）原样显示，颜色取 `display.color`。只有标准图标时，紧凑场景按点缩放兜底（盲文按点比例判断，不用"任一点即填满"，以免填平图案内部的细节）；两个都没有时用内置机器人图标。没有图标的 harness 也占同样大小的图标区。
- **内置机器人图标**：`docs/robot-icon-24x12.txt`（标准）与 `docs/robot-icon-12x6.txt`（紧凑），用户 2026-11-01 绘制；随 UI 代码内置，不属于 harness 知识。
- 在不同终端宽度、长名称、无图标与多种图标尺寸下用单元测试验证。

## 9. 信息架构（TUI 与 GUI 共用；2026-10-31 用户决定，2026-11-01 按改版重写）

原则：

- **日常管理优先，备份安静运行**。首页和实例页先回答"它在不在跑、怎么打开、有没有要处理的事"；正常的备份只用一行简短状态（上次成功时间、空间站副本），备份失败、长期未备份、空间不足、钥匙或空间站有问题时才提升为提醒。不把"建立逃生舱"放在每一页的中心。
- **先给结论，再给细节**。每一页只回答一个问题，技术信息（id、端口、路径、epoch、实际命令）折叠在"技术信息"或"查看实际命令"里。用语以 PRODUCT.md 8.1 为准。
- **层层进入**：首页只有服务器，服务器页只有实例，实例页才有操作。不在上层页面直接操作下层对象。
- **每个可能破坏东西的操作都说清后果**：确认框写明"会发生什么、不会发生什么、能否撤销"；涉及备份的品牌用语附一句实际含义。
- 底部菜单只放当前页能做的事，最多一行（80 列下可两行）；更多操作进入子页。
- 未实现的能力（管理方技能、工具、沙盒插件等）不出现空页面或灰色按钮。
- **点缀语**（2026-11-01 用户决定）：Valise 是旅行箱，可以在页面上放一句带旅行与行李意象的短句，增加一点诗意，但不能破坏重心。
  - 位置二选一：标题下方的副标题（以"——"开头），或伪窗口右下角、贴近边框处。
  - 每页最多一句；暗色、次要的字重；不放在按钮、确认框、错误与警告里，不替代任何说明。
  - 内容必须真实：说的是这一页确实发生的事（如"——把 openclaw 塞进 Valise 了。之后它的运行状态、管理页和逃生舱都在这里。"），不制造假象，不暗示 Valise 搬走或复制了 agent。
  - 空间不够时（窄终端、内容放不下）先省略点缀语，任何信息都不为它让位。
  - 文案集中放在一个文件里（TUI：`client/ui/tui/flourish.go`），方便统一修改；首批文案见 `docs/sketches/M12-tui.md`。

### 9.1 第一次启动

1. 欢迎：一句话说明 Valise 做什么（"在你的服务器上安装和管理 agent，并替它做好备份"）。
2. 建议设置 Valise 口令与加密钥匙（输入两次，至少 12 个字符；说明口令保护加密钥匙，Valise 不保存它，丢了就无法打开逃生舱）。可以"稍后设置"。管理口令不在这里出现。
3. 设好后展示钥匙保存位置，强烈建议立即"备份钥匙"（导出恢复套件），可以稍后。
4. 安装 harness 资料包（在线拉取或选择本地文件，见 PROFILES.md 1.1）；可以跳过，用到时再提示。
5. 添加第一台服务器（9.3）。

已有钥匙的用户可以选"我在别的电脑上已经有钥匙"→ 导入恢复套件。跳过口令的用户在添加第一台手动服务器、或第一次建立逃生舱时补上（ARCHITECTURE.md 第 3 节）。

### 9.2 首页

- 每台已记录服务器一张卡片：服务器名、在线 / 离线、agent 数量与各自的运行状态、需要处理的事（服务停止、管理页不可达、porter 有更新、未完成的着陆、体检问题、备份失败或长期未备份、空间站问题）。备份正常时只写一行"备份正常 · 3 小时前 · 空间站 ✓"。
- 卡片上不能直接选实例。
- 卡片样式（2026-11-01 用户确认）：首页用整宽的服务器卡片纵向排列，每台服务器 4～5 行（名称与在线状态、各 agent 一行状态、需要处理的事、一行备份状态），不带图标；横向翻页的标准卡片只用于服务器页的实例卡片（8.1）。草图见 `docs/sketches/M12-tui.md`。
- 底部菜单：进入服务器、添加服务器、设置、退出。没有服务器时显示空状态与"添加你的第一台服务器"。

### 9.3 添加服务器

- 第一屏两个同样醒目的入口："手动填写"（地址、端口、用户名、登录方式：密码或私钥文件、别名）与"从 SSH 配置导入"。
- 依次展示 ARCHITECTURE.md 第 3 节的步骤与进度：确认服务器身份（首次连接与指纹变化都用白话解释）→ 安装日常钥匙（说明"之后日常使用不再需要密码；日常钥匙只能做安全的操作，敏感操作会再要服务器密码"；高级选项"同时创建管理钥匙"，需设一个与 Valise 口令不同的管理口令，之后敏感操作改为输入管理口令）→ 体检 → 一键部署 Valise 服务端（可展开查看来源、签名与哈希）→ 服务器名 → 发现 harness。
- 最后一步分两条路：已有 agent → "接入 Valise"（接入报告用白话展示）；没有 → "安装第一个 harness"（9.6）。

### 9.6 安装 harness

- 选择 harness：列表按 PROFILES.md 1.2 显示"可安装 / 只能管理"与适用版本。第一阶段只有 OpenClaw 可安装。
- 两种方式并列："简易引导"（官方方案，INSTALL.md 第 3 节）与"原生安装界面"（INSTALL.md 第 2 节）。
- 简易引导：依赖检测结果 → 方案说明（默认白话，可展开实际命令、来源、权限、依赖、脚本全文与哈希、运行时下载说明）→ 解锁管理权限 → 在交互终端中执行 → 重新检测 → 引导打开管理页。模型凭据提示"在管理页或原生界面里自己填写，可以稍后再做"。
- 缺少需要管理员权限的依赖时：展示需要执行的命令，三个选择——自己在原生界面里执行、交给服务器管理员、开启高级模式（口令挑战与免责确认见 INSTALL.md 4.1）。
- 失败或版本不符：说明原因，提供"用原生方式继续"。
