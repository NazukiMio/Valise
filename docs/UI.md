# UI 规范（TUI 与 mygo 桌面）

> UI 分两步：M7a 终端 UI（第 8 节），M7b 桌面 UI（第 2–7 节，mygo）。第 1 节的分层原则全程有效：服务层不依赖 UI。第 9 节的信息架构由两者共用。

## 1. 分层原则

- 所有业务逻辑都写在 `client/ui` 的服务层（纯 Go）中，CLI、TUI 和桌面 UI 共用同一套服务层。**TUI 和桌面 UI 都只是很薄的适配层，没有它们，CLI 也必须完整可用。**
- 这样做也是对框架风险的控制：mygo 是一个由个人维护的年轻项目。即使将来需要更换 UI 框架，也只需要重写适配层和前端，服务层不受影响。

## 2. 资料来源

- 官方文档：https://github.com/egoist/mygo/tree/main/docs ，阅读时以锁定 tag 下的版本为准。
- Go API：`go doc -all github.com/egoist/mygo`
- 开发机检查：`go tool mygo doctor`
- 不确定的 API 一律查阅文档或源码，**不要凭印象编写**。

## 3. 版本锁定与 CLI

- 锁定版本：v0.7.3（用户于 2026-10-31 指定，提交 `6f28d7b`；M7b 开工时写入依赖并复核本文约定）。锁定后，升级必须经过用户同意。
- 把 mygo CLI 作为 Go tool 依赖加入，保证 CLI 和库的版本一致：`go get -tool github.com/egoist/mygo/cmd/mygo@<锁定版本>`。之后统一使用 `go tool mygo <命令>` 调用 CLI。
- 前端依赖中的 `mygo-runtime` 也锁定为与锁定版本对应的版本。

## 4. 绑定约定

- **生成客户端**：`go tool mygo generate`，输出路径为 `client/ui/src/mygo.ts`（在 `mygo.config.ts` 的 `bindings` 中配置）。生成的文件不得手工修改，也不计入"单文件 400 行"的限制。
- **生成期间会执行 main**：`mygo generate` 会在设置 `MYGO_GENERATE` 的情况下运行程序，直到 `App.Run` 返回。因此建立 SSH 连接、读取 keystore、启动隧道等任何有副作用的初始化，都必须放进 `App.WhenReady`。main 函数中只允许调用 `mygo.Bind` 和注册事件。
- **服务划分**：按领域绑定，例如 `Servers`、`Instances`、`Vault`、`Revive`、`Relay`、`Keystore`、`Settings`。每个服务对应 `client/ui` 服务层中的一个 Go 类型，方法只负责参数转换。
- **进度流**：封存、同步、复活、登录中继等长时间操作，通过 `*mygo.Channel[T]` 参数把进度推送给前端。方法的第一个参数接收 `context.Context`，页面关闭时操作随之取消（复活进入交换阶段之后不响应取消，见第 6 节）。
- **全局状态变化**：例如实例的健康状态、隧道的三个状态，使用 `mygo.NewEvent` 声明的事件进行广播。
- **字段命名**：所有结构体字段必须带 `json` 标签。可能超过 2⁵³ 的整数（目前没有）使用 `json:",string"`。

## 5. 错误约定

mygo 会把 Go 方法返回的 error 文本作为前端 `CallError` 的 message。约定如下：

- 服务层的错误统一为 `valise.UserError{Code, Reason, Suggestion, Detail}`，它的 `Error()` 返回该结构的 JSON 文本。
- 前端在 `src/errors.ts` 中统一解析：能解析时，展示"原因 + 建议"，细节默认折叠；不能解析时，展示"发生了未预期的错误"，并附上原文。
- 禁止在前端直接展示未经解析的原始错误文本。

## 6. 安全铁律

- **入口一律用系统浏览器打开**（通过 mygo 的 shell API 打开 URL），**绝不在 mygo 窗口中加载 agent 的 Web 页面**。原因：开发构建会信任 localhost 页面，经隧道转发的 agent 页面也位于 localhost，在应用窗口中加载它，就等于允许它调用 Go 方法，包括解锁密钥和复活。
- 禁止设置 `TrustedOrigins: ["*"]`。应用窗口只加载自己的前端。
- 口令输入框不得把值写进任何前端状态持久化或日志中，提交后立即清空。
- 复活一旦进入交换阶段，关闭窗口或页面不得中断进行中的交换。服务层持有独立的 context，前端重新打开后，通过事件恢复显示进度。

## 7. 前端结构

```text
client/ui/src/
├── mygo.ts            # 生成文件，禁止手改
├── main.ts            # 入口与路由
├── state.ts           # 全局状态（订阅 events）
├── errors.ts          # UserError 解析
├── views/
│   ├── instances.ts   # 实例总览
│   ├── vault.ts       # 金库与快照
│   ├── revive.ts      # 复活向导
│   ├── relay.ts       # 登录中继
│   └── settings.ts    # 设置与信任根
└── components/        # 状态徽标（三态分离）、进度条、确认对话框等
```

单个手写 `.ts` 文件不得超过 400 行。`package.json` 中的 `typecheck` 和 `build:web` 脚本由本项目自己定义：`typecheck` 执行 `tsc --noEmit`，`build:web` 只构建前端。打包应用使用 `go tool mygo build`。

## 8. 终端 UI（M7a）

- **框架与版本**：Bubble Tea 生态，锁定 `charm.land/bubbletea/v2 v2.1.1`、`charm.land/bubbles/v2 v2.2.1`、`charm.land/lipgloss/v2 v2.0.6`（2026-10-31 的最新稳定版）。升级须经用户同意。
- **入口**：`valise tui`，与 CLI 同一个二进制；共用 `--config-dir`。
- **代码位置**：`client/ui/tui/`，按视图拆分（如 `model.go`、`instances.go`、`vault.go`、`revive.go`、`relay.go`、`kit.go`、`settings.go`、`styles.go`）。单个 `.go` 文件不得超过 400 行。TUI 只调用服务层，不直接发 RPC、不读写服务器文件。
- **耗时操作**：一律放进 `tea.Cmd` 在后台执行，界面显示进度；服务层回调（如复活的阶段、登录状态）转成消息送回界面。复活进入交换阶段后，界面上的"取消"不得中断交换。
- **需要终端的操作**：登录中继、口令输入等需要原始终端的步骤，用 Bubble Tea 的暂停机制把终端交还给对应的 CLI 流程，结束后恢复 TUI。口令不得保存在 TUI 的状态里，用完即弃。
- **确认**：所有会改动服务器的操作（封存、同步、复活、删除 prev、清理旧实例、接受降级提议、安装技能）都要有明确的确认步骤，文案与 CLI 一致；降级提议逐个确认。
- **错误**：服务层的 `UserError` 显示为"原因 + 建议"，技术细节默认折叠。
- **入口**：Web 入口一律用系统浏览器打开（与第 6 节相同）。
- **测试**：模型的状态迁移与渲染用单元测试覆盖（直接调用 `Update`/`View`，不依赖真实终端）；涉及服务器的部分用 fake-ssh 替身。
- **滚动**：任何列表和卡片网格都放在可滚动的视口里，光标始终可见；窗口尺寸变化时重新排版。不得出现光标移出屏幕后停止渲染的情况。
- **卡片**：用 lipgloss 边框绘制，网格列数随终端宽度变化（每张卡片约 28 列宽），窄终端退化为单列。

## 9. 信息架构（TUI 与 GUI 共用，2026-10-31 用户决定）

原则：

- **先给结论，再给细节**。每一页只回答一个问题，技术信息（id、端口、路径、epoch）折叠在"技术信息"里。用语以 PRODUCT.md 8.1 为准。
- **层层进入**：首页只有服务器，服务器页只有实例，实例页才有操作。不在上层页面直接操作下层对象。
- **每个可能破坏东西的操作都说清后果**：确认框写明"会发生什么、不会发生什么、能否撤销"。
- 底部菜单只放当前页能做的事，最多一行；更多操作进入子页。

### 9.1 第一次启动（没有钥匙时）

1. 欢迎：一句话说明 Valise 做什么。
2. 设一个口令（输入两次，至少 12 个字符），说明"口令用来保护你的加密钥匙，Valise 不保存它，丢了就无法打开逃生舱"。
3. 钥匙已生成：展示保存位置；强烈建议立即"备份钥匙"（导出恢复套件到 U 盘或密码管理器），可以选择稍后。
4. 安装 harness 资料包（在线拉取或选择本地文件，见 PROFILES.md 1.1）；可以跳过，登记时再提示。
5. 添加第一台服务器（流程见 ARCHITECTURE.md 第 3 节"添加服务器"）。

已有钥匙的用户可以在第 2 步选择"我在别的电脑上已经有钥匙"→ 导入恢复套件。

### 9.2 首页

- 每台已记录服务器一张卡片：服务器名、在线 / 离线、agent 数量（附各实例的小图标与名字）、最久没有建立逃生舱的实例距今多久、云备份状态（最近一次成功同步；没有云备份时写"未设置云备份"）、需要注意的事项数量（体检问题、未完成的着陆、porter 需要更新）。
- 卡片上不能直接选实例。
- 底部菜单：进入服务器、添加服务器、设置、退出。没有服务器时显示空状态与"添加服务器"。

### 9.3 服务器页

- 实例卡片网格：图标（profile 的 `display.icon` 与主色；没有时用内置的机器人字符画）、实例名、harness 与版本、运行状态（运行中 / 已停止 / 没有服务）、最近一个逃生舱距今多久、是否已上云、体检徽标。已被取代的旧实例显示为暗色卡片，标注"已被取代"。
- 不显示逃生舱列表。
- 底部菜单：进入实例、登记新 agent、云备份、空间清理、服务器设置、刷新、返回。
- **云备份**（子页）：每个目标一张卡片（名称、位置、自动同步开关与频率、最近一次同步）；进入目标后按"实例 → 周期"浏览，每个周期显示逃生舱数量、大小、"服务器有 / 云端有 / 两处都有"；可以立即同步、删除整个周期（VAULT_FORMAT.md 10.4）、添加目标（只渲染已实现的种类）。
- **空间清理**（子页）：着陆前的旧状态、已被取代的旧实例、服务器上已结束的周期，各自显示占用空间与"删除后会怎样"，逐项确认。
- **服务器设置**（子页）：服务器名（只读）、porter 版本与更新、服务器上的可用工具、加密钥匙是否已登记到这台服务器、从已记录服务器中移除。

### 9.4 实例页

顶部是实例卡片（图标、名字、状态），下面是分栏，左右切换：

- **概览**：运行状态、harness 版本与安装来源、profile 是否已核实、最近的逃生舱与云备份、agent 最近一次通过逃生舱技能联系 Valise 的时间。快捷操作：建立逃生舱、打开管理页。
- **逃生舱**：按日期分组的列表，每行是"时间 · 谁建立的（你 / agent / 安全网 / 定时 / 着陆前自动）· 原因 · 装了什么（轻装 / 标准 / 完整 / 原样）· 大小 · 是否已上云"。支持搜索（原因、日期如 `10-30`、建立者、档位）与按周期筛选。进入一个逃生舱看详情（各类内容的大小、技术信息折叠），从详情发起"逃生舱着陆"（原地着陆 / 着陆到另一台服务器 / 着陆成一个新的 agent），向导步骤不变。建立逃生舱时先选装什么，每个档位附一句话说明。
- **体检**：顶部一行总评；每个发现一张卡片：严重程度、白话解释、相关数字的条形图（与阈值对比）、**处理建议**：harness 自己就能做的操作（来自 profile，例如开新会话、交接）、"交给 agent 处理"（给出一段可以复制给 agent 的话）、以及"记忆整理技能（规划中）"的说明文字（不渲染按钮）。下方是**归档建议**：agent 认为应该装进逃生舱或换一类的文件，逐条接受 / 拒绝，降级逐个确认。
- **管理页与登录**：打开管理页（三个状态分开展示；令牌按 LOGIN_RELAY.md 4.1 处理；需要时"打开服务器终端"）；登录授权（先说明它解决什么问题，再列出 profile 声明的登录方式）。
- **设置**：逃生舱技能（状态、安装 / 更新 / 卸载、接入 MCP 的命令）、金库周期（每周 / 每月 / 每季度，只影响下一个周期）、定时建立逃生舱（开关与频率，写明会在服务器上留下什么）、profile 信息与补充归类规则、重新登记。

### 9.5 设置页（全局）

左侧分栏：

- **加密钥匙**：一张状态卡（"你的钥匙已创建，存放在 <路径>，由口令保护"）；操作只有两个：备份钥匙（导出恢复套件）、在这台电脑上导入钥匙。三行白话说明：逃生舱用这把钥匙加密；服务器只拿到"只能上锁、不能开锁"的那一半；换电脑时导入同一把钥匙并输入口令即可打开以前的逃生舱。
- **服务器**：已记录服务器列表、添加（手动输入或从 SSH 配置导入，流程见 ARCHITECTURE.md 第 3 节"添加服务器"）、移除。
- **云备份**：按服务器列出云备份目标与自动同步设置，默认的金库周期。
- **更新**：客户端自身（GitHub Release 下载并验签）、各服务器的 porter、harness 资料包（单独下载的签名包，在线拉取或选择本地文件，列出各 profile 的版本变化；PROFILES.md 1.1）、各实例的逃生舱技能。
- **高级**：多把钥匙与收件人管理（从服务器移除公钥等，每项写明后果）、生成一把新钥匙、配置目录位置。
- **关于**：版本、项目地址、脱离 Valise 恢复的说明。
