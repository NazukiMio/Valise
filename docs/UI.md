# UI 规范（TUI 与 mygo 桌面）

> 2026-11-05 用户批准 GUI / TUI 草图及 N1–N5 实施顺序。2026-11-08 用户决定桌面界面用 mygo 原生 UI（Go 写），第 2–7 节据此重写，原 TS 前端约定作废。GUI 是最终用户交付，TUI 服务资源紧凑环境，CLI 面向自动化与诊断。第 1 节的分层原则全程有效；第 9、10 节由各入口共用。M7b 保留里程碑 ID，按 DEV_PLAN.md 的 N4 进入条件恢复，不再等待所有 TUI 边缘功能。
> 本文规定目标行为，不代表实现状态。N1 [共享服务契约](SERVICE_CONTRACTS.md) 已于 2026-11-05 经用户确认定稿；N2、N3 已完成，N4 自 2026-11-08 进行中，N5 未实现。草图已经批准，不重复设置同一草图的审批闸门。

## 1. 分层原则

- 所有业务逻辑都写在 `client/ui` 的服务层（纯 Go）中，CLI、TUI、桌面 UI 与后续管理方 MCP 都是薄适配。共享能力不能只藏在某个前端或命令处理函数中；CLI 保留兼容性并提供结构化自动化入口，不要求普通用户先学命令，也不要求为每项能力复制同等复杂的人工 CLI 向导。
- GUI 必须完成基础任务的全部引导、授权、确认与结果查看；TUI 用菜单、表单和可滚动列表提供同等核心能力，不照搬 GUI 布局。GUI/TUI 直接调用 Go service，原生交互按需交给独立终端或系统浏览器。
- 复用系统 OpenSSH、按需 porter、age/zstd、分块与周期备份库、暂存交换及恢复/配置事务各自的专用 journal。统一的是任务状态、计划与结果的呈现契约，不编写万能任务执行引擎，不用统一状态替代持久日志或原有安全检查。
- 这样做也是对框架风险的控制：mygo 是一个由个人维护的年轻项目。即使将来需要更换 UI 框架，也只需要重写适配层和前端，服务层不受影响。

## 2. 资料来源

- 桌面界面用 **mygo 原生 UI**（2026-11-08 用户决定）：界面用 mygo 的 `ui` 包在 Go 里写，由 mygo 在 GPU 上绘制（macOS Metal、Windows Direct3D 11、Linux OpenGL）。没有 HTML、JavaScript、TypeScript、webview 和前端构建，也不需要 Bun。
- 官方文档：https://github.com/egoist/mygo/tree/main/docs （原生 UI 在 `docs/ui/`），阅读时以锁定 tag 下的版本为准；本地副本在 Go 模块缓存 `github.com/egoist/mygo@v0.7.3/docs/`。
- Go API：`go doc -all github.com/egoist/mygo/ui`、`go doc -all github.com/egoist/mygo`
- 开发机检查：`go tool mygo doctor`
- 不确定的 API 一律查阅文档或源码，**不要凭印象编写**。

## 3. 版本锁定与 CLI

- 锁定版本：v0.7.3（用户于 2026-10-31 指定，tag 提交 `6f28d7b`，要求 Go 1.27.3）。锁定后，升级必须经过用户同意。

- 应用的名称、标识与版本写在 `client/ui/mygo.json`，图标在 `client/ui/resources/`（`mygo init -template native` 的布局）。

## 4. 代码结构与调用约定

- 桌面界面的代码在 `client/ui/gui/`（Go 包，与 `client/ui/tui/` 并列），入口为 `client/ui/cmd/valise-desktop/`。界面直接调用 `client/ui/service`，**不经过绑定、不生成客户端代码**；业务逻辑不得写在 `gui/` 里。
- **视图模型**：每个窗口有一个应用状态（Go 结构体），视图函数 `func (app *X) view(c *ui.Context)` 每帧从状态构建界面。构建期的值（`ui.Element`）不得存进状态或后台 goroutine；持久身份用 `ui.Handle`，列表等控件状态放在应用状态里。每次改动后跑 `go tool mygo vet` 检查构建期值的生命周期。
- **启动无副作用**：`main` 只构造状态与窗口；建立 SSH 连接、读取钥匙、启动隧道等有副作用的初始化放进 `mygo.App.WhenReady` 之后按需发起，绝不在视图函数里同步执行。
- **耗时操作**：SSH、封存、同步、恢复、登录中继等一律在 goroutine 中执行，进度经 service 的进度回调送回，用 `Window.Update` 在主线程改状态并重绘。视图函数里不得阻塞。页面离开与任务生命周期分开：切页不取消任务，取消只来自显式操作；恢复进入交换后不得中断（第 6 节）。
- **路由**：一个窗口一个 `ui.Router`，一级入口用 `ui.Sidebar`，路径与第 9 节的信息架构一一对应。
- **主题**：颜色、字体、圆角等令牌、样式变体与布局都来自当前主题（7.4），视图里不写散落的颜色常量；默认跟随系统深浅色。
- **文案**：界面文字集中放在少数文件中（与 TUI 的 `flourish.go` 一样便于统一修改），用语以 PRODUCT.md 8.1 为准。

## 5. 错误约定

- 服务层的错误统一为 `valise.UserError{Code, Reason, Suggestion, Detail}`。界面用 `errors.As` 取出后展示“原因 + 建议”，细节默认折叠在“技术信息”里。
- 不是 `UserError` 的错误展示为“发生了未预期的错误”，原文折叠在技术信息里；禁止直接把未经整理的原始错误文本放在主要位置。

## 6. 安全铁律

- **入口一律用系统浏览器打开**（`mygo.Shell` 打开 URL），**绝不在 Valise 窗口里加载 agent 的 Web 页面**，包括 mygo 原生 UI 里的 web view 控件。经隧道转发的 agent 页面位于 localhost，与 Valise 进程同处一台机器，不让它进入 Valise 的窗口。
- 原生界面（harness 的终端）在 Valise 自己绘制的终端里显示时，同样不解析、不保存、不记录输入与回显（INSTALL.md 第 2 节）。
- 口令输入框用 `Password` 模式（不显示、不进剪贴板），值只在提交瞬间交给 service，提交后立即清空，不写入任何持久状态或日志。
- 复活一旦进入交换阶段，关闭窗口或页面不得中断进行中的交换。服务层持有独立的 context；界面重新打开后，查询实际任务或持久日志并重新跟踪进度；退出进程或断连后的恢复按专用 journal 规则处理。

## 7. 测试与自检

- 视图测试用 `ui.NewTester`（不开窗口，按文字查找、点击、输入、推进时钟），与 service 的 fake-ssh 测试一起跑在 `go test` 里；动画用 `tt.Advance` 推进时钟，不 sleep。界面测试只证明界面状态，不代替靶机验收。
- `client/ui/gui/` 下单个手写 `.go` 文件不得超过 400 行。
- 自检（AGENTS.md 第 6 节第 5 步）：`go tool mygo vet`，以及 `client/ui` 的 `go test`、`go vet`、`gofmt`。打包应用用 `go tool mygo build`。

### 7.2 轻重缓急（2026-11-08 用户讨论决定）

用户反馈：元素过分统一，看不出重点，也不知道该做什么。据此：

- **首页先回答“有没有要我处理的事”**：顶部一句结论（如“15 个 Agent，2 件事需要你处理”或“一切正常”），其下是待处理卡片，每张写明原因与下一步；一切正常的 Agent 收成安静的紧凑行；已迁出、已被替换的放进默认折叠的“不再使用”。
- **算作待处理的只有三种**：Valise 控制的服务停止、失败或状态未知（没有服务的 harness 不算）；服务器这次读不到（附原因与建议）；登记过本机仓库，而本机副本里最近一次备份超过 7 天或一次都没有。这一种按原因分成两张卡片（2026-11-08 用户决定）：服务器上有比本机更新的备份 →“N 个 Agent 有新备份还没复制到这台电脑”；服务器上最近一次备份也超过 7 天或一次都没有 →“N 个 Agent 超过 7 天没有新备份”（新内容没有被保存，要看定时备份）。服务器这次读不到时不判断原因，只由“服务器读不到”那张卡片说明。已迁出的旧实例仍在运行这轮不算（用户未选）。
- **正常就安静**：正常时只留一行淡色小字（“运行中 · 今天 09:00 已备份”）；异常的那一项单独出来、着色、写原因。各项状态仍分开表达，只是不再等量。完整的状态牌只在 Agent 页作为详情。
- **辨识度**：Agent 头像按 harness 区分（7.3 修订为官方图标或用户图片）；同一 harness 的多个 Agent 靠名字与服务器区分。这是展示资料自带的信息，不构成背书。
- **每页最多一个主按钮**：Agent 页顶部是名字、一句结论与主按钮“打开管理页”（建立隧道并在系统浏览器打开；隧道、远端监听、健康检查、令牌分步显示），状态牌降为下方详情。需要口令或会改动东西的操作（备份、恢复）留给对应分段。
- **旅程页金线为主角**：金线放大；完整列表按月折叠，只展开最近一个月，每行更紧凑。

### 7.3 第二轮反馈（2026-11-08 用户决定）

- **提醒能停、能去处理**：每张待处理卡片都有「知道了」与「带我去处理」。
  - 「知道了」记住“这一次的情况”（哪个 Agent 或服务器、什么问题、当时的状态，例如服务状态值、错误代码、本机最近备份的日期），保存在本机；情况变化后重新出现。结论句改写为“另有 N 件已知道”，可以展开查看并取消。
  - 「带我去处理」进入只做这件事的最小处理页：服务停止 → Agent 页的“健康”，列出健康检查结果，资料登记了修复动作时提供“启动服务”（先说明会执行什么、需要管理登录，确认后执行）；服务器读不到 → 服务器详情，显示原因与建议并可“重新连接”；有新备份还没复制到这台电脑 → 备份位置，列出本机仓库与是否可用，可“现在补到本机”（逐个仓库，从服务器复制缺少的备份，不需要钥匙）；超过 7 天没有新备份 → 卡片里第一个 Agent 的“管理与设置”，在保护计划里开启或修改定时备份（2026-11-09“钥匙与备份”段实现后改为此处）。
  - 管理登录：有管理钥匙时由界面弹出管理口令框；只能用服务器密码的管理登录，由 askpass 转交 OpenSSH 的密码提示（7.5、ARCHITECTURE.md 2.1）；转交不可用时界面写明原因并给出终端里的同一条命令。
- **首页卡片风**：默认卡片视图，可切换为列表视图，选择记在本机；顶部搜索按名字、harness、服务器实时过滤，⌘F 聚焦。卡片写名字、harness · 服务器、一句状态；有问题的卡片单独标出。
- **图标**：界面的品牌与导航图标用 2026-11-05 草图那套线条图标（小行李箱、机器人等）。Agent 头像优先级：用户为这个 Agent 选的本机图片 > harness 资料的官方图标（`display.logo`，PROFILES.md）> 草图的线条机器人（以 harness 颜色着色）。用户图片只复制到本机数据目录，不上传。GUI 不再画字符画；字符画只用于 TUI。
- **发丝时间线**：旅程的线改为 `references/TimelineExample.html` 的画法：一根主脊线缓缓呼吸起伏，约 32 根极细的发丝贴着它错落流动、两端淡出，节点挂在主脊线上；减少动效时全部静止。点击节点的柔光与 300ms 后展开保留。
- **功能设计先查 2026-11-05 草图**，好用优先；草图没有覆盖时再提问。

### 7.4 主题（2026-11-08 用户决定）

桌面界面的外观由主题决定；功能先在“经典”主题上接好，以后换外观只需切换主题，用户也可以自己设计。只覆盖桌面 GUI；TUI 到它的阶段再按同一份令牌映射。

- **主题能改什么**：
  - **令牌**：颜色（含提醒、错误、状态色）、字体（正文、标题、等宽）、字号阶梯、圆角、阴影、间距。视图里不写散落的颜色与字体，一律取当前主题的令牌。
  - **样式变体**：从 Valise 内置的具名变体里选，例如时间线“发丝 / 金线 / 简洁”、导航“侧栏 / 窄栏 / 顶栏”、Agent 卡片“标准 / 大 / 紧凑”。
  - **布局**：声明式布局树。每页由 Valise 暴露一组固定插槽（例如结论句、提醒、搜索、Agent 列表、导航），主题只用行、列、网格与尺寸、间距、对齐、背景把插槽摆到位置上。没有条件、循环、表达式或脚本，是模板而不是解释器（AGENTS.md 第 3 节）。所有按钮与动作仍是同一套，只是设计与位置不同；例如“沉浸模式”：导航缩成窄栏，Agent 卡片放大占满一页。
  - **本机图片**：页面背景、品牌图等，随主题文件夹一起复制到本机。
- **始终显示（主题不能隐藏）**：待处理提醒；错误与失败原因；确认框与口令框；各项独立状态（隧道 / 端口 / 健康、退出码 / 服务状态等，AGENTS.md 7.5）；“未核实”提示；切回经典主题的入口。主题的布局缺了其中的插槽，Valise 按经典主题的位置补上，并在主题菜单里说明补了哪些。确认框、口令框不在布局树里，任何主题下都由 Valise 以经典方式画出。其他插槽主题可以不放。
- **内置主题**：“经典浅色”（7.1 的配色）与“经典深色”（同一色相推出）；默认“跟随系统”，在两者间随系统深浅色切换。
- **切换入口**：侧栏底部的主题菜单（以后挪进设置页）：跟随系统、经典浅色、经典深色、本机已导入的主题、“导入主题…”。选择记在本机（`desktop/prefs.json`）。
- **主题文件**：一个文件夹，内含 `theme.json` 与它引用的图片；导入时用系统对话框选这个文件夹，检查通过后整个复制到数据目录的 `desktop/themes/<id>/`，不从网络加载。
  - `theme.json` 的 `format` 为 `valise-theme/1`；`base` 指定继承的内置主题，没写的令牌、变体与布局都取自它；未知字段、未知插槽、同一插槽出现两次、布局树超过 12 层都算错误。
  - 颜色写 `#rrggbb` 或 `#rrggbbaa`；图片只能引用文件夹内的相对路径（不得含 `..` 或绝对路径），只认能解码的图片格式（PNG、JPEG、WebP、SVG），单张不超过 4 MiB，整个文件夹不超过 16 MiB，`theme.json` 不超过 256 KiB。
  - 检查不过就不导入，或（已导入的）退回经典主题，并写明哪一项不对、怎么改。
  - 不点名推荐第三方主题（AGENTS.md 7.6）。
- **分步落地**：第一轮把令牌、深色、主题文件与导入、外壳（导航与页面区）和首页的插槽做好；其余页面先只用令牌与变体，之后逐页开放插槽。每页开放了哪些插槽，记在本节下方的插槽表里。

#### 7.4.1 插槽表

| 页面 | 插槽 | 始终显示 |
| --- | --- | --- |
| 外壳 | `brand` 品牌（`icon`：只显示图标）、`nav` 导航（`sidebar` 侧栏 / `rail` 窄栏 / `top` 顶栏）、`tagline` 标语、`theme` 主题菜单（`icon`：只写“主题”）、`page` 页面区 | `theme`（补在 `nav` 下方）、`page` |
| 首页 | `header` 标题与重新读取、`verdict` 结论句（含“另有 N 件已知道”与读取错误）、`reminders` 待处理提醒、`known` 已知道、`toolbar` 搜索与视图切换、`agents` Agent（`normal` 标准 / `large` 大 / `compact` 紧凑，`columns` 设列数）、`retired` 不再使用、`note` 数据来源说明 | `verdict`、`reminders`（补在 `verdict` 后面） |

#### 7.4.2 主题文件参考

布局节点恰好是 `row`、`column`、`grid`（子节点数组）或 `slot`（插槽名）之一，可带：`columns`、`gap`、`padding`（1、2 或 4 个数）、`width`、`height`、`max_width`、`grow`、`align` 与 `justify`（`start`、`center`、`end`、`stretch`、`between`）、`background`（颜色名）、`image`（主题的图片名，铺满）、`radius`；`style` 只能写在插槽上。`page` 插槽的 `padding` 与 `max_width` 作用于页面内容。

### 7.5 服务器与接入（N4 第一段，2026-11-08 用户确认草图）

草图：`docs/sketches/valise-servers-gui-2026-11-08.html`。

- **服务器状态**四种，各自一个标签，不合并：在线、离线、需要处理、未知（PRODUCT.md 8.1）。“离线”“需要处理”的行直接写一句原因；显示旧结果时写“下面是 X 前的情况”。首页提醒卡片同样用这套词。
- **入口**：首页“添加 Agent”与服务器页“添加服务器”进同一个向导；从首页进入时，连上后直接到“这台服务器上的 Agent”。
- **向导**：连接服务器 → 确认身份 → 登录 → 准备服务器 → 这台服务器上的 Agent。
  - 连接：左边填写（可粘贴 `用户@地址:端口` 自动拆开；登录方式用两张卡片选：服务器密码 / 我的私钥；名字），右边实时名片与“接下来会发生什么”。也可改为“从已有 SSH 配置导入”，选中后直接到“准备服务器”。
  - 确认身份：显示指纹与核对方法；“不一致，停止”不写任何东西。
  - 登录：服务器密码经 askpass 转交（ARCHITECTURE.md 2.1）。弹框显示 OpenSSH 的原始提问，下方可选“同时办一张管理员通行证”（默认不勾，勾上才出现管理口令两栏）。
  - 准备服务器：每一步一行，进行中、完成、失败分开写；没有 porter 时默认从 GitHub Release 下载与客户端同版本并核对，本地构建放“更多选项”。
- **这台服务器上的 Agent**：不预设已有 Agent，三种情况可同时出现：找到认识的 → 接入（报告确认后写入，未识别文件默认按敏感保留，可逐项改归类）；有 harness 但资料包不认识 → 链到“为 harness 写一份资料”入门教程（PROFILES.md 附录 A）；一个都没有 → 列出有官方安装方案的 harness，可“安装第一个 Agent”，也可“重新扫描”。手动指定目录接入、从备份导入这一段不做，不画按钮。
- **安装第一个 Agent**：先列计划（来源锁定版本、脚本核对 SHA-256 并可展开全文、可选步骤、缺的前提），确认后在窗口里的终端执行（mygo 终端插件）；“装好了”以重新检测为准，与退出码分开写；之后直接接入。服务器上已有同一 harness 的默认 Agent 时先停下来让用户决定。
- **服务器详情**：状态、porter 版本、来源各自一个标签；通行证一块（用户通行证能不能用；管理员通行证已锁上 / 已解锁 / 没办，可办一张或注销）；这台服务器上的 Agent 与“查找、接入或安装”；离线或需要处理时的原因、建议与时间。来自 SSH 配置的服务器写“用你自己的 SSH 设置登录”。
- **实现时的细化**（2026-11-08，按草图实现时发现）：
  - 名字栏同时是连接名与服务器名（备份位置里的文件夹名，只能用小写字母、数字和连字符，之后不改），默认由地址生成；草图里“家里的服务器”这类中文显示名暂不支持，界面写明规则。
  - 管理钥匙要在引导登录之前生成，所以“同时办一张管理员通行证”与两栏管理口令放在“登录”这一屏上，点“登录”后再由 askpass 弹框问服务器密码。
  - porter 来源在“登录”屏说明；开发版客户端没有对应的 Release，界面说明要在“更多选项”里选本地构建。
  - 安装用的终端加载不了时（libghostty-vt 下载失败等），退回为文字输出加一行输入框，安装照常。
  - 首页的“添加 Agent”是普通按钮，主按钮仍留给提醒（7.2“每页最多一个主按钮”）。
- **等待时说清在做什么**（2026-11-09 用户反馈：服务器连不上时向导卡很久，看不出在干什么、也停不下来）：准备服务器时，进行中的那一步写出当前子步骤与已等时间，例如“用 SSH 连接 192.0.2.24，登录后写入通行证…（已等 12 秒）”“从 GitHub Release 下载 porter，核对签名与 SHA-256 后上传”；私钥登录写“SSH Agent 要你确认时，请在它的窗口里放行”；OpenSSH 的提问开着时写“等你在弹框里回答 OpenSSH 的提问”。旁边始终有“停止”：结束正在运行的 ssh 与它的提问，已做完的步骤保留，可重试或取消。读取指纹时写“正在连接 地址:端口 读取指纹（最多约 10 秒）”。连接本身最多 15 秒（ARCHITECTURE.md 2.1 连接与保活超时）。

### 7.6 界面文字：标准键与词表（2026-11-09 用户决定）

界面上的每一句话都用一个英文的**标准键**表示，表现层按键从**词表**取当前语言的文字。主题管样子，词表管文字，两者都只对接键名，互不相干。

- **范围**：先做桌面 GUI（`client/ui/gui/` 的非测试代码不再写界面文字字面量，一律 `T("key", 参数…)`，测试守住这一条）。服务层错误随后改为“错误代码 + 参数”，由界面按代码取词；在那之前错误仍显示服务层给的原因与建议。TUI 在“TUI 对齐”段接同一套词表。CLI 与 porter 暂不改。
- **键**：小写英文、点分层级，按页面与用途命名，例如 `server.state.online`、`wizard.connect.title`、`remove.keep_backups`。键一经发布不改名；废弃的键在词表里保留到下一个格式版本。
- **词表**：JSON，`{"format": "valise-locale/1", "lang": "zh-CN", "name": "简体中文", "messages": {"键": "文字"}}`。占位符写 `{name}`，参数按名字传入，不靠位置；数量写 `{n}`，需要单复数的语言可写 `{"one": "…", "other": "…"}`。内置词表随客户端打包（`client/ui/gui/i18n/zh-CN.json`），是唯一的基准：键的全集与每个键的占位符以它为准。
- **语言**：现在只有简体中文；英文词表另行一步，翻译完成后再开放切换。选择记在本机（`desktop/prefs.json` 的 `lang`），默认简体中文。
- **导入词表**（用户决定允许，带检查）：入口在侧栏底部菜单的“语言”一组（以后挪进设置页）：内置语言、本机已导入的词表、“导入语言…”。用系统对话框选一个 JSON 文件，检查通过后复制到数据目录的 `desktop/locales/<id>.json`，不从网络加载。检查：格式与 `format`；`lang` 是合法的语言标签；不认识的键算错误；每条文字的占位符必须与内置词表的同一个键完全一致；单条不超过 2000 字、整个文件不超过 1 MiB；不允许控制字符。缺少的键沿用内置简体中文，菜单写明“N 条还没有翻译”。导入的词表一律标“非官方翻译”，在语言菜单里始终可见：Valise 无法检查其他语言的措辞是否守住 AGENTS.md 7.4–7.6 的文案红线（例如不写“安全”、各项状态分开说）。检查不过就不导入，或（已导入的）退回内置简体中文，并写明哪一条不对、怎么改。
- **主题不改文字**：主题文件不能覆盖词表（7.4）。

### 7.7 文案：一句话，详情折叠（2026-11-09 用户决定）

界面是软件，不是汇报。每块正文只写一句：现在怎样、按下去会怎样。代价、救不了的情况、原理与出处放进折叠的「查看详情…」（或单独的详情页）。确认框里决策必需的后果仍要直接看得到，但也压成一句。

## 8. 终端 UI（M7a）

- **框架与版本**：Bubble Tea 生态，锁定 `charm.land/bubbletea/v2 v2.1.1`、`charm.land/bubbles/v2 v2.2.1`、`charm.land/lipgloss/v2 v2.0.6`（2026-10-31 的最新稳定版）。升级须经用户同意。
- **入口**：`valise tui`，与 CLI 同一个二进制；共用 `--config-dir`。
- **代码位置**：`client/ui/tui/`，按视图拆分（如 `model.go`、`instances.go`、`vault.go`、`revive.go`、`relay.go`、`kit.go`、`settings.go`、`styles.go`）。单个 `.go` 文件不得超过 400 行。TUI 只调用服务层，不直接发 RPC、不读写服务器文件。
- **耗时操作**：一律放进 `tea.Cmd` 在后台执行，界面显示进度；服务层回调（如复活的阶段、登录状态）转成消息送回界面。复活进入交换阶段后，界面上的"取消"不得中断交换。
  - 进度（2026-11-01 用户反馈）：取回备份、恢复等长操作逐步列出阶段（已完成打勾、当前一步转动、之后的变暗），能计量的阶段（取回到本机、写入暂存目录）显示进度条、百分比与已传输量，并显示已用时间，让用户知道它没有卡住。服务层经 `service.WithProgress` 上报，界面只在动画帧里读取最新值。
  - 动画与遥测面板（2026-11-01 用户决定，草图已确认）：火箭字符画（素材 `assets/TUI/rocket`，用户创作，TUI 实现 `client/ui/tui/rocket.go` 与 `hud.go`）只用于恢复与同步两页；备份列表、详情不铺背景。
    - 画面：场景按等比例放大盖满内容区（超出部分居中裁掉，不拉伸），一直播放到离开页面。文字放在"科幻面板"里：面板盖住的场景压暗显示、继续运动（模拟半透明），四角标记加细边线，左上角小标题。左上主面板：当前提示（加粗，正常字距）、下面一行白话说明实际在做什么、步骤勾选；右上遥测：已用时、预计剩余（能估算时）、速度、目标；底部进度面板：第几步、大进度条、百分比与数据量，无法计量时显示来回扫动的光条，等用户决定时光条停住。宽度不足 100 列时遥测并入主面板；不足 60×16 时去掉背景，退回纯文字布局。
    - 提示（步骤名用航天说法，小字用白话）：恢复为"正在进入预备轨道…（将备份取回本机）""正在进入轨道…（解密备份，检查里面的文件）""轨道就绪 · 请确认恢复计划""正在联络母星…（把备份写入服务器的暂存目录）""正在呼叫地面指挥…（核对暂存的文件，等你下令）""即将完成…（把 agent 换成备份里的版本，并做健康检查）""恢复成功！"，失败为"恢复中止"。同步为"等候出发…（把还没同步的备份传到备份位置）"，完成后随火箭依次显示"正在进入轨道…""正在呼叫备份位置…""正在对接备份位置…"，最后"已送达备份位置！"，失败为"发射中止"。
    - 时机：能预估剩余时间时，在接近结束时开始播放火箭，按原版速度；不能预估时等结束后再播放。恢复在用户下令交换后火箭开始下降（交换与健康检查只需几秒）；降到底部面板上方仍未完成时悬停等待，真正完成后才着地。同步目前无法预估，传输时火箭停在发射台，完成后点火。真实任务的成功、失败、部分完成与等待状态立即显示，不能等动画结束；后台任务已经完成时可用 enter 跳过装饰动画，esc 在任务完成后随时可用。2026-11-05 起主流程按第 10 节逐步替换航天场景，此处保留既有素材和历史实现说明。失败不播放火箭动画（正在下降的火箭掉头飞离），立即显示原因；已自动退回时同样处理。
- **需要终端的操作**：登录中继、口令输入等需要原始终端的步骤，用 Bubble Tea 的暂停机制把终端交还给对应的 CLI 流程，结束后恢复 TUI。口令不得保存在 TUI 的状态里，用完即弃。
- **确认**：所有会改动服务器的操作（封存、同步、复活、删除 prev、清理旧实例、接受降级提议、安装技能）都要有明确的确认步骤，文案与 CLI 一致；降级提议逐个确认。
- **错误**：服务层的 `UserError` 显示为"原因 + 建议"，技术细节默认折叠。
- **入口**：Web 入口一律用系统浏览器打开（与第 6 节相同）。
- **测试**：模型的状态迁移与渲染用单元测试覆盖（直接调用 `Update`/`View`，不依赖真实终端）；涉及服务器的部分用 fake-ssh 替身。
- **滚动**：任何列表和卡片网格都放在可滚动的视口里，光标始终可见；窗口尺寸变化时重新排版。不得出现光标移出屏幕后停止渲染的情况。滚动跟随光标移动，不要求用户按 PgUp/PgDn；没有光标的长内容用 ↑↓ 逐行滚动，PgUp/PgDn 只是翻页的快捷方式。
- **窗口尺寸**（2026-11-03 用户决定）：最小 80×24，推荐 100×30。低于最小值时只显示"窗口太小，请放大到至少 80×24"，不进入确认页与操作页（已经开始交换的操作不受影响，继续执行，结果放大后可见）。最小值以上，恢复计划、停机与空间说明、结果路径、命令全文等决策所需信息一律换行或可滚动看完整；看不完整的内容不允许确认。快捷键菜单放不下时换行或收进"?"帮助。长操作显示阶段与等待状态。Valise 不调整用户的终端窗口。
- **确认主人**（2026-11-02 用户决定）：主人操作（ARCHITECTURE.md 第 2.2 节，如恢复、装技能、改周期、不敏感的删除）只问 Valise 口令，不要求管理钥匙；口令框写明"输入 Valise 口令以确认是你本人，15 分钟内不再询问"。恢复时为解密备份输入的口令同时完成确认，不再多问。
- **解锁开发者模式**（原"管理权限"；管理钥匙即开发者模式钥匙）：开发者模式的操作前，需要管理登录：有管理钥匙且未解锁时弹出口令框（"输入管理口令以继续，15 分钟内不再询问"），顶栏显示"管理权限已解锁 · 剩余 12 分钟"，可以立即锁定；没有管理钥匙时说明"这一步需要服务器密码"，CLI 把终端交给 ssh 的密码提示（GUI 用 askpass），并提示"经常做管理操作，可以在服务器设置里创建管理钥匙"。
  - 主动解锁（2026-11-01 用户反馈）：顶栏在锁定时显示"管理权限：已锁定 · U 解锁"，按 `U` 直接输入管理口令解锁当前服务器；没有管理钥匙时询问是否创建。不需要先执行某个管理操作才能进入解锁状态。
  - 终端界面里的 OpenSSH 一律不得向终端询问任何东西（`BatchMode=yes`）：全屏界面占着终端，ssh 的密码或钥匙口令提示会和界面抢输入，导致输入无效甚至卡死。管理钥匙只从 Valise 的 ssh-agent 取；长操作（如恢复等待用户确认）继续前若管理窗口已过期，由界面重新询问管理口令。需要服务器密码的操作交给 CLI 流程（暂停界面）。口令用完即弃，不进入任何状态。高级模式开启时，顶栏换成红色的"高级模式 · <服务器> · 剩余 N 分钟"，并提供"立即关闭"（INSTALL.md 4.1）。

## 9. 信息架构（TUI 与 GUI 共用；2026-11-05 修订）

本节按已批准的新入口组织；已有细项的安全、确认、健康与安装规则继续有效。旧分栏、快捷键及主题文案保留为迁移参照，冲突时以本节的新导航和第 10 节为准，不据此宣称旧实现已完成改版。

原则：

- **日常管理优先，备份安静运行**。首页和实例页先回答"它在不在跑、怎么打开、有没有要处理的事"；正常的备份只用一行简短状态（上次成功时间、其他位置副本），备份失败、长期未备份、空间不足、钥匙或远程备份位置有问题时才提升为提醒。不把“备份现在”放在每一页的中心。
- **先给结论，再给细节**。每一页只回答一个问题，技术信息（id、端口、路径、epoch、实际命令）折叠在"技术信息"或"查看实际命令"里。用语以 PRODUCT.md 8.1 为准。
- **Agent 为首页**：一级入口为“我的 Agent / 服务器 / 备份位置 / 工具箱 / 设置”。首页跨服务器汇总 Agent，可直接进入概览和旅程、打开已支持的原生入口；底层服务器 / 安装 / agent 层次与共享服务影响保留，确认时明确实际目标。未实现的工具箱或 AI 接入能力不渲染占位入口。
- **每个可能破坏东西的操作都说清后果**：确认框写明"会发生什么、不会发生什么、能否撤销"；关键操作直接称备份、恢复、迁移；旅行点缀不替代后果说明。
- **名称**（2026-11-02 用户决定）：Valise 自己的"profile"概念在界面上叫"harness 资料"（资料包叫"harness 资料包"）；命令行参数与代码标识符（`--profile`、`--allow-draft-profile`、`profile_id`）不改。harness 里的 agent 按 harness 自己的叫法显示（资料的 `terms.agent`，如 Hermes 的 "profile"），内部统一叫 agent（PROFILES.md 1.3、ARCHITECTURE.md 4.1）。
- 底部菜单只放当前页能做的事，最多一行（80 列下可两行）；更多操作进入子页。
- 未实现的能力（管理方技能、工具、沙盒插件等）不出现空页面或灰色按钮。
- **点缀语**（2026-11-01 用户决定）：Valise 是旅行箱，可以在页面上放一句带旅行与行李意象的短句，增加一点诗意，但不能破坏重心。
  - 位置二选一：标题下方的副标题（以"——"开头），或伪窗口右下角、贴近边框处。
  - 每页最多一句；暗色、次要的字重；不放在按钮、确认框、错误与警告里，不替代任何说明。
  - 内容必须真实：说的是这一页确实发生的事（如“已接入 Valise，可以在这里查看运行、管理入口和备份。”），不制造假象，不暗示 Valise 搬走或复制了 agent。
  - 空间不够时（窄终端、内容放不下）先省略点缀语，任何信息都不为它让位。
  - 文案集中放在一个文件里（TUI：`client/ui/tui/flourish.go`），方便统一修改；首批文案见 `docs/history/M12-tui-sketch.md`。

### 9.1 第一次启动

顺序（2026-11-03 用户决定：先让 agent 跑起来，加密在第一次需要时再设）：

1. 欢迎：一句话说明 Valise 做什么（"在你的服务器上安装和管理 agent，并替它做好备份"）。
2. 安装 harness 资料包（在线拉取或选择本地文件，见 PROFILES.md 1.1）；可以跳过，用到时再提示。

5. 加密钥匙：第一次需要时（第一次建立备份、添加手动服务器需要登记钥匙时）再设 Valise 口令（输入两次，至少 12 个字符；说明口令保护加密钥匙，Valise 不保存它，丢了就无法打开备份），设好后强烈建议立即"备份钥匙"（导出恢复套件），可以稍后。向导里也可以选"现在就设"。管理口令不在这里出现。

已有钥匙的用户可以选"我在别的电脑上已经有钥匙"→ 导入恢复套件。

- **第一次使用清单**（2026-11-02 用户决定，草图见 Artifact「Valise 引导草图」）：向导只做准备工作（口令、钥匙、资料包、服务器、安装或接入第一个 agent）。之后 Agent 首页出现三行的"第一次使用"卡片（进度与下一步，按 `g` 打开），全部完成或用户选"不再显示"后消失，设置里可以再打开。清单七项：准备工作、第一个 agent、建立第一个备份、存一份到别处（备份位置）、做一次恢复测试、认识管理钥匙（可选）、认识 Kit 与高级模式（可选，只介绍并写明在哪里打开，不默认开启）。打勾依据真实状态（有备份、备份位置同步过、恢复测试通过、读完介绍页），可以跳过。每项是两三屏的小引导：是什么、什么时候用、"这一步会 / 不会"，然后在真实页面上做一次。进度只存在客户端。

- 保护计划以服务器上的设置为权威，GUI/TUI/CLI 读取同一事实；本机仓库路径与客户端运行条件仍由客户端负责。服务器计划与本客户端绑定分别版本化，提交前比较预期版本；采用固定提交事务和分项结果。接管后拒绝旧无版本设置写入；具体契约见 N1 第 4 节，待 N2 实现。
- 时间轴以成功备份为恢复点，分别展示时间、已知原因、实际范围、各位置副本与验证证据。失败/取消任务可查看，但不是恢复点；缺失原因显示未知，不读取对话生成成长叙事，不调用 LLM。索引可丢弃并从备份库副本重建，不依赖原服务器或原客户端历史缓存；附加原因、备注、迁移关系缺失如实展示。周期仍为存储和整组删除边界，不重写旧快照。
- 跨服务器先汇总 Agent，不凭同名或同一 `instance_id` 合并历史。迁移以明确记录关联，创建副本保持独立；使用 AgentRef 的实例世代，身份与迁移关系保存在备份库外；关系丢失时仍能重建保存点，但关联显示未知。具体采用已定稿 N1 第 3 节，待 N2/N3 实现。

### 10.3 副本状态、自动同步与失联恢复

- “服务器已保存”“副本传输完成”“副本校验通过”“恢复测试通过”“服务运行正常”分开展示，并注明位置、范围、检查时间与失效条件。当前 `LeafCopies.Complete` 仅比较快照数，不能作为完整副本证据或放行依据。
- N3 须对选定时间点所需的清单、索引、密钥/epoch 与数据包等依赖执行完整性检查；缺失、损坏、部分下载、检查失败与过期证据不得显示完整。具体证据与缓存失效采用已定稿 N1 第 5 节，不能以数量相等替代数据校验，也不能把免私钥校验称为已试解或已验证可运行。
- 自动同步由共享 service 调度，各前端使用相同触发与结果（本机仓库与这台电脑登录的云盘见 ARCHITECTURE.md 7.4，2026-11-08）。区分客户端关闭后仍可执行的服务器定时/直传，与需要客户端在线、外盘挂载或客户端中转的位置；短期证书失效和同步落后要明确显示，不新增常驻服务。
- 原服务器失联时，N3 提供从完整本机/异地副本选择时间点、核对恢复材料、读取快照内 profile 与来源、导出文件、向可达目标准备恢复计划及完成恢复的流程。不得先连接源服务器或依赖源 dossier；缺少身体来源、兼容环境、凭据授权或数据时给出缺口。当前正常 `PlanRevive` 依赖源服务器，此能力尚未完成。
- 恢复/迁移/创建副本继续使用计划、暂存、校验、确认、专用 journal 交换与结果复核，保留独占凭据和共享服务影响说明。副本完整不等于任意环境均可恢复；删除仍只允许显式删除整个已结束周期，各位置分别确认。

### 10.4 已定稿服务契约与交付边界

相关架构目标见 ARCHITECTURE.md 5.1（保护计划）、7.1（副本证据）、7.2（旅程）、8.2.2（离线来源）和第 11 节（任务、授权与生命周期）。具体服务契约已定稿于 SERVICE_CONTRACTS.md，不等于接口已实现或发布。

N1 已定义身份及迁移关联、服务器保护计划版本与并发、timeline/task API、确认及授权与冻结计划绑定、取消/重连与结果，以及自定义范围的兼容边界。服务层按该契约统一表达目标、计划、授权需求、阶段、进度、取消边界、结果和恢复入口。自定义匹配与回滚的完整语义在 N5b 开工前另行定稿，不提前提供 custom。

源服务器失联且独占身份无法核实隔离时，确认页只提供排除声明的独占凭据后恢复，或导出/暂存等待处理；说明排除整个配置文件的实际影响，不提供“我确认已关机”后带独占身份完整启动的首版分支。

沿用日常 / 主人 / 管理登录，不把口令或钥匙交给管理方 AI，不自动开启高级模式；受管方 MCP 的禁区保持独立。管理方 MCP 目前不存在，N5a 先设计接口再实现；首批只提供查询、准备允许的计划及已允许任务，不开放恢复/删除执行接口，未来若需请求恢复/删除，其工具清单与人工确认机制须另行评审。跨进程 MCP 只留类型化请求，用户主动打开 GUI/TUI 后重建计划并确认，由该人类进程执行；无人类会话就等待。不传递解锁身份或通用确认票据，重开不能凭磁盘 approved 状态自动执行。

GUI 可在 N4 初期先只读接入，完整交付必须依赖 N3 的副本与失联恢复闭环（N3 已于 2026-11-08 完成，mygo v0.7.3 随 N4 骨架引入）。每个阶段按具体交付验收，fake-ssh 不代替实机；最终必须由用户在 GUI 走完从零/接入已有、备份、同步、恢复、迁移及源服务器失联恢复的全链路。

B03 的事务与链接处理已在真实实例上验收（2026-11-07），OpenClaw 的正式入口已开放；其他 harness 须各自核实并登记动作后才显示。该阻塞不作为独立查询或所有 GUI 页面的前提；依赖同一暂存/链接机制的管理动作和恢复路径须完成各自验收才开放。任何新 scope 或链接方案均须先定语义和验收，不能借本轮导航更新绕过。
