### N3：严格副本、跨前端自动同步与源服务器失联恢复

- **交付**：替换只比较快照数的完整性判定，验证所选时间点依赖的清单、索引、密钥/epoch、数据包及相应校验，区分传输、完整性、试解、恢复测试与运行证据。规定证据时间与失效条件；缺失、损坏、部分缓存和检查失败不能放行成完整副本，删除分级沿用既有安全边界。
- **交付**：将本机仓库自动同步的触发与结果从 TUI 收敛到共享 service，GUI/TUI/CLI 使用同一规则，处理并发、重试、断连和刷新。显示客户端在线、外盘挂载、中转、证书有效期等限制，不新增常驻守护进程。
- **交付**：源服务器完全不可达时，从完整本机/异地副本及恢复材料读取时间轴、选择快照、读取内含 profile 和来源、导出数据，并向可达目标完成计划、暂存、校验、确认、交换和复核；不先读取源 dossier 或调用源服务器。缺少来源、兼容环境、凭据授权或数据时明确停止并说明下一步。
- **交付（云盘，2026-11-07 用户决定）**：备份位置新增“云盘”，经 rclone 完成；首批 Google Drive、OneDrive、Dropbox，坚果云（WebDAV）与自定义云下一步。能支持哪些云盘取决于 rclone，Valise 不自己实现各家协议。添加时分两步登录，界面分别说明各自代表的同步级别：
  - **这台电脑登录**：rclone 配置与授权留在用户电脑上，复制由客户端经本机文件夹或临时目录中转完成，只在 Valise 打开时更新。
  - **服务器登录**：rclone（经 Kit 工具清单安装，版本与 SHA-256 核实后）及其配置在服务器上，备份完成后由服务器直接上传，定时与自动复制依赖它，不需要 Valise 打开。授权保存在服务器上，只建议使用限定单个文件夹的授权（如 Dropbox 的 App 文件夹、Google Drive 的 `drive.file`），界面说明服务器被攻破时这个授权会一起暴露（备份内容本身是 age 加密的）。
  - 两步都登录时先由服务器直传，失败再经这台电脑中转，结果写明所用路径；只有服务器登录的云盘能被保护计划的自动复制使用。授权内容只在 rclone 自己的配置里，Valise 不读取、不保存、不记录；服务器登录的具体流程（例如在原生终端里用 rclone 的无浏览器授权）在 N3 开工前定稿。副本校验与其他备份位置适用同一 N3 规则，保存前同样由服务器测试（N2 G 节 `target_check`）。
- **依赖**：N1 副本证据、任务/授权和离线身份契约；N2 保护计划与时间轴对应能力；既有金库和恢复 journal。任何格式/协议调整须先定义兼容，继续可用独立恢复工具。
- **验收**：fake-ssh 覆盖快照数相同但缺包/损坏、部分拉取、过期证据、多入口触发和重试；实机验证 SSH/NAS 同步、直传与客户端中转限制。阻断源服务器连接，仅靠副本和恢复材料向真实目标恢复并核对内容、程序/服务状态及断连恢复，同时验证独立导出；不能仅用 `restore.py` 成功代替正常产品恢复路径。相关 GUI 用户全链路在 N4 再验收。

## 贯穿全程：`testbed/drill.sh`

每个里程碑都往演练脚本中追加对应的步骤。M4 完成时，脚本必须覆盖：部署 → 登记 → 三个档位的封存 → 同步到 NAS → 脱离 Valise 恢复 → 回滚 → 跨架构迁移 → 故障与崩溃注入 → 克隆。最终输出 `ALL_PASS (failures=0)`。
