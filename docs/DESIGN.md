# 审美、交互与文案工程指南

> 2026-11-17 用户授权定稿。写或改任何桌面界面前先读本文件；安全、确认流与诚实状态以 AGENTS.md、UI.md 为准，本文件只规定“怎么搭、怎么说”。不需要先画出未来功能的草图，照这里的规则做出来就应当与现有界面一致。

## 1. 一页怎么搭

1. **每页回答一个问题**，写在视图函数注释的第一行。页头是：返回（`backLink`）、标题、一句现在怎样、至多一个主按钮。
2. **从上到下的顺序固定**：页头 → 需要处理的事 → 正在进行的事 → 正常的内容 → 折叠的技术信息。
3. **只用语义函数与尺度令牌**（`gui/theme.go`、`gui/scale.go`、`gui/widgets.go`）：`card`、`subPanel`、`reportPanel`、`codeBox`、`fact`、`pressable`、`backLink`、`statusRow`、`notice`、`dangerButton`、`quietButton`。新代码不写 `FontSize(数字)`、`Padding(数字)`、`Radius(数字)`、`Gap(数字)`，取 `fs.*`、`sp.*`、`rad.*`。存量代码改到哪迁到哪。
4. **间距三档**：组内 8，组间 16，区块间 24。
5. **卡片是例外，不是默认**。并排的同类内容用一张卡片加分隔线；卡片里不再套卡片，里面的小块用 `subPanel`。
6. **字号 7 级**：12 说明 · 13 次要 · 14 正文 · 16 小标题 · 20 标题 · 28 页面标题 · 36 结论句。最小 12；次要信息靠颜色退后，不靠缩小。

## 2. 按钮与状态

| 种类 | 用在 | 规则 |
| --- | --- | --- |
| 主按钮 | 这一屏最该做的那一件事 | 每屏至多一个；弹窗里的确认按钮算弹窗这一屏的 |
| 普通按钮 | 其余会做事的操作 | 文字是动词加对象；会再问一次的以“…”结尾 |
| 安静按钮 `quietButton` | 关闭、知道了、查看详情、删除的入口 | 没有边框和底色 |
| 危险按钮 `dangerButton` | 删除、注销、关闭备用锁、移除并清理 | 只出现在确认框里；文字写出后果，不写“确定” |

- **状态五种语气**：`ok`、`warn`、`danger`、`stop`（明确不在运行）、未知（没读到）。每种都是“点或图标 + 词”，不只靠颜色。`danger` 只用于严重问题与不可撤销的操作。
- **各说各的**（AGENTS.md 7.5）：隧道 / 端口 / 页面；退出码 / 服务是否健康；已存到服务器 / 已同步到别处；已核实 / 未核实。每一项各占一行或一格。不做把它们合起来的徽标、总分或总进度环。
- **正常就安静**：正常的项不着色、不加粗，可以收成一行。`warn`、`danger` 的项排在前面，写原因和下一步。
- **警告不能画成次要色**。来自服务层的警告一律用 `notice(c, "warn", …)`。
- **没读到不等于正常**：读取失败时显示上次结果加时间，或显示未知。
- **没做的不画**：未实现的能力不放按钮，也不放灰色按钮。因前置条件未满足暂时不能点的按钮可以禁用，旁边必须写出还差什么。
- **安装检查的结论只写“未发现基础疑点”**，任何位置不写“安全”“已验证”“可信”。
- **窗口顶部的横幅一律用 `banner`**（`gui/banners.go`）：`busy`（正在进行，带转圈）、`warn`、`danger` 三种；一句话加至多两个按钮，按钮靠右不撑满。横幅在主题布局之外，任何主题都不能把它藏掉。
- **一页里有多条检查结果时**，需要处理的排前面，每条的修复进度与结果紧跟在它下面；两条以上的“正常”收成一行（`healthItems`）。
- **多步流程顶上放步骤条**（参照 `restoreStepper`）：走过的打勾，当前的实心，后面的空心。它只表示走到哪，不能点着跳步。
- **几种并列的入口用选择卡**（参照 `nativeTile`）：图标、名字、一句话、箭头，整张可点。选择卡不算主按钮，这一屏的主按钮留给真正要先做的事。
- **口令框顶上写明是哪种密码、交给谁核对**（`askKind`），免得把服务器密码填进 Valise 口令框。

## 3. 可点区域、悬停、动效与性能

- **整行整卡规则**：有边框或底色、内容指向另一页的行或卡片，整块可点，行尾有箭头图标（`chevron`）。块内另有按钮时，按钮自己处理点击（参照 `locCard`）。不指向别处的信息行不做成卡片外观。
- **可点的东西一律走 `pressable`**：它给手型、角色、标签，并在 `Draw` 回调里画悬停。
- **悬停只在 `Draw` 回调里读**，并且经 `over(e)` 读，不直接调 `e.Hovered()`：带 `Exit` 过渡或正在关闭的弹窗会用旧一帧的回调重画离场副本，直接读会 panic。构建期读取会让指针每次进出都重建整个视图（mygo performance.md）。只有悬停要改变布局或显示新内容时才在构建期读，并写注释说明。
- **静态而复杂的块加 `.Cache()`**（渐变、多层阴影、噪点、模糊）；里面有会动的东西就不要整块缓存。
- **动效只解释“从哪来、到哪去、状态变了”**。移动与缩放用 `AnimatePose`；颜色与阴影用 `ElementTransition{Colors, Shadows}`；出现与消失用 `Enter`/`Exit` 并给元素 `Key`；数字变化用 `ContentTransition{Numeric: true}`。时长只取 `motion.fast`（120ms）、`motion.base`（200ms）、`motion.slow`（320ms）。
- **真实任务的结果、错误和确认不等动画**（UI.md 10.1）。
- **自己用 `p.After` 或 `AnimationFrame` 驱动的绘制**必须看 `ReduceMotion`，所在页签不可见时停止。
- **可能超过 50 行的集合用 `List` 或 `Table`**。
- **材质只经由语义函数生效**：`card` 的阴影来自 `materialCard`，页面标题的记号来自 `titleMark`，窗口背景来自 `backdrop`（`gui/material.go`，UI.md 7.4.4）。视图不判断当前材质，也不自己画背景纹理；改材质时把浅色、深色、手账、夜航都渲染一遍看（`VALISE_SHOTS=<目录> go test ./gui -run TestDesignShots`）。
- **折叠详情是必配的**：id、路径、端口、命令、哈希、错误代码、原理说明都放进“技术信息”或“查看详情…”。例外是确认框：将要执行的每条命令和会改变的内容直接展示（UI.md 9.5）。
- **错误一律用 `errorBox`**：原因一句、建议一句、技术信息折叠。

## 4. 中文界面文案

### 4.1 公式

| 场合 | 公式 | 例 |
| --- | --- | --- |
| 状态 | 谁 + 现在怎样 | 服务没在运行，Agent 现在不会回应。 |
| 按钮 | 动词 + 对象，2–6 个字 | 打开管理页 · 现在同步 · 移除… |
| 说明 | 按下去会怎样，一句 | 只从这台电脑移除，服务器上什么都不动。 |
| 确认框 | 标题是问句；正文说会发生什么、不会发生什么、能否撤销 | 移除 nas？删掉这里的记录和钥匙；上面已有的备份不动。 |
| 错误 | 原因 + 下一步 | 服务器没有及时回应。检查连接后再看这次操作的状态。 |
| 等待 | 正在做什么 + 已等多久 | 正在连接 192.0.2.24…（已等 12 秒） |
| 空状态 | 现在没有什么 + 第一步怎么做 | 还没有备份位置。再放一份到别处，服务器坏了也不怕。 |

### 4.2 规矩

- **一处一句**（UI.md 7.7）。正文超过一句，就把后面的移进“查看详情…”。
- **一词一义**，以 PRODUCT.md 8.1 为准；新增叫法先改 8.1。
- **从用户这边说**：写“现在用的文件还没动”，不写“活动目录尚未替换”。写“你”，不写“用户”“我们”。
- **口语但不随便**：用“没有”“还没”“先…再…”；不用“尚未”“须”“进行…操作”“该”“此”“上述”“下列”，也不用“没办”“搞定”。
- **否定要具体**：不写“失败”，写“没有完成”并说卡在哪一步。
- **数字和名字放前面**：“3 个 Agent 有新备份还没同步”。
- **标点**：中文全角；“…”只用于还会再问一次的按钮和进行中的状态；箭头和对勾是图标，不写进词表。
- **旅行意象只在两处**：每页标题下那一句点缀语，和旅程页。按钮、确认框、错误、警告里不出现。

### 4.3 禁用词（出现在主文案里即为缺陷；技术信息里可以出现）

| 类别 | 不写 | 写 |
| --- | --- | --- |
| 内部概念 | 暂存、交换、活动目录、现场、执行器、任务编号、回调、世代、实例（指 Agent 时）、快照、封存、复活、回滚、克隆、仓库、porter | 备好的文件、替换、现在用的文件、服务器现状、（不提）、（不提）、浏览器里已完成、（不提）、Agent、备份或时间点、备份、恢复、原地恢复、分身、本机文件夹、搬运工 |
| 过度承诺 | 安全、已验证、可信、保证、完全、无损 | 未发现基础疑点；核对通过（并说核对了什么） |
| 合并状态 | 一切就绪、已恢复（只恢复了文件时） | 逐项说；“文件已恢复，未启动程序” |
| 公文腔 | 尚未、须、予以、进行、上述、下列、此、该 | 还没、要、（直接用动词）、这些、下面、这个 |
| 推诿 | 发生未知错误、请稍后重试（不说原因） | 原因和一个能做的下一步 |
| 旧主题词 | 逃生舱、着陆、空间站、上云、演练、金库 | 见 PRODUCT.md 8.1 |

## 5. 提交前自查

1. 这一屏有几个主按钮？超过一个就改。
2. 所有新文字都在 `zh-CN.json` 里、对应测试已更新吗？
3. 每个看起来能点的块都能点吗？
4. 把服务器断开再打开这一页，它显示的是“没读到”还是“正常”？
5. 系统开启“减少动态效果”后，有没有信息只靠动画传达？
6. 文件超过 400 行了吗？
